既然读了不可信内容的模型可能被说服，那就干脆不给它任何权限——让它只负责读，另一个只负责做。

## 一句话

把「处理不可信内容」和「执行有权限的操作」拆到两个模型上，中间只传结构化摘要——**不可信内容永远无法直接决定工具调用**。

## 原理

### 结构

```text
不可信内容（文档、网页、工具返回）
        ↓
【隔离模型】没有任何工具权限
        ↓  只输出结构化数据，不输出指令
    { "extracted": {...}, "summary": "..." }
        ↓  经过 schema 校验
【执行模型】持有工具，但只看得到结构化摘要
        ↓
    工具调用
```

关键在两处：

**一、隔离模型没有工具。** 它被说服了也没用——它能做的只有输出文本。

**二、中间是结构化数据，不是自由文本。** 摘要必须过 schema 校验，见 [[01-结构化输出三档]]。自由文本会把注入指令原样带过去，等于没隔离。

### 为什么这样有效

回到那个数字：即便防护最好的模型，注入的攻击成功率也在 1% 左右，见 [[01-间接提示注入与 20 条攻击载荷]]。

dual-LLM 改变的不是这个概率，而是**成功之后能做什么**：

| | 单模型 | dual-LLM |
| --- | --- | --- |
| 注入成功率 | ~1% | 隔离模型仍是 ~1% |
| 成功后的后果 | **可以调用任何工具** | 只能污染那份结构化摘要 |

**它把「任意代码执行」级别的风险降成了「数据污染」级别。** 后者仍然有害（错误的摘要会导致错误的决策），但爆炸半径小了几个量级，见 [[02-纵深防御]]。

这也是「会思考的不许行动，会行动的不许思考」这个原则的具体实现。

### 传什么、不传什么

中间那层的设计是成败关键：

**该传**：结构化字段、枚举值、数字、经过白名单校验的标识符。

**不该传**：自由文本、原始内容片段、任何可能包含指令的字符串。

现实中往往需要传一些文本（比如摘要正文）。这时候要：

- **限长**——短文本能藏的指令有限
- **过滤**——扫描典型的注入模式
- **标注来源**——执行模型要知道这段来自不可信通道
- **不让它单独触发操作**——摘要只能作为参考，工具调用的参数必须来自可信来源或用户确认

**最后一条最重要**：即便摘要被污染了，只要工具参数不直接从它取，危害就有限。

### 代价

不是免费的：

| 代价 | 说明 |
| --- | --- |
| **两次调用** | 成本和延迟都翻倍 |
| **信息损失** | 结构化摘要必然丢掉细节 |
| **schema 要预先设计** | 处理开放式内容时很难穷举字段 |
| **实现复杂度** | 两条链路、两套提示词、中间层校验 |

所以它不是默认架构，是**高风险场景的选择**。

### 什么时候值得

| 场景 | 值得吗 |
| --- | --- |
| agent 有写操作工具 + 会读外部内容 | **非常值得** |
| 处理用户上传的任意文件 | 值得 |
| 多租户，且会读别人上传的内容 | 值得 |
| 纯只读的问答系统 | 通常不必——最小权限已经够了 |
| 内部可信语料的 RAG | 不必 |

**判据：注入成功之后，攻击者能做什么？** 只能让回答变差 → 不需要隔离；能调用写操作 → 需要。

### 简化版：能力隔离

完整的 dual-LLM 成本高。一个轻量替代是**同一个模型、按阶段收权限**：

```text
阶段 1：读文档、抽取信息 → 工具集为空
阶段 2：基于抽取结果决策 → 工具集只含只读工具
阶段 3：执行 → 工具集含写操作，但参数必须来自阶段 1 的结构化输出且经过校验
```

**核心是「读不可信内容的那一步不能持有写权限」**，至于是不是换个模型实例，是次要的。这个简化版能覆盖大部分收益，成本低得多。

### 别忘了它也不是万能的

隔离模型输出的摘要如果被污染，执行模型会基于错误信息做决策。所以：

- 摘要要过 schema 校验和值域校验，见 [[06-四层参数校验]]
- 关键操作仍然要人确认，见 [[02-纵深防御]]
- 要有指称校验——摘要里提到的 ID 必须真实存在

**隔离是限制爆炸半径，不是消除风险。**

## 动手做

- [ ] 判断你的系统是否需要隔离：注入成功后攻击者能做什么
- [ ] 先实现简化版：读不可信内容的那一步把工具集清空
- [ ] 设计中间层 schema，尽量只传结构化字段
- [ ] 必须传文本时加上限长、过滤、来源标注
- [ ] 验证工具参数不直接从不可信摘要取
- [ ] 拿 20 条注入载荷跑一遍，对比隔离前后的穿透后果
- [ ] 测隔离带来的成本和延迟增加

## 算学会了

- [ ] 理解隔离改变的是爆炸半径而非成功率
- [ ] 中间层传结构化数据而非自由文本
- [ ] 工具参数不从不可信摘要直接取
- [ ] 会用「成功后能做什么」判断需不需要隔离
- [ ] 知道简化版（按阶段收权限）能覆盖大部分收益

## 坑

**中间传自由文本。** 注入指令原样带过去，隔离形同虚设。

**工具参数直接从摘要取。** 摘要被污染就等于参数被控制。

**以为隔离之后就安全了。** 它限制爆炸半径，不消除风险，人确认仍然需要。

**在只读系统上上完整 dual-LLM。** 成本翻倍换来的收益很小，最小权限就够。

**schema 设计得太宽松。** 留了一个自由文本字段，前面的努力全废。

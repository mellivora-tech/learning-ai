「我们在返回给用户之前会过滤掉他无权看的内容」——这句话听起来没问题，但越权在那之前就已经发生了。

## 一句话

权限必须在**检索时**作为查询条件强制生效，而不是生成后再过滤；因为模型一旦读到，就可能把它总结进回答里，而过滤器认不出来。

## 原理

### 早一步和晚一步的区别

![[权限过滤的时机.excalidraw.md|700]]

**生成后过滤**的三个问题：

**一、越权已经发生。** 模型读到了不该读的内容。在很多合规框架下，「系统把数据取出来了」本身就构成一次访问。

**二、过滤器认不出改写。** 模型不会原样复述，它会总结、会改写、会推理。原文里的「张三工资 3 万」变成回答里的「该员工薪资处于部门中上水平」——关键词过滤完全拦不住。

**三、上下文被污染。** 不该看的内容进了上下文，会影响这一轮的所有输出，甚至影响后续几轮，见 [[04-记忆冲突消解]]。

### 检索时过滤怎么做

核心是把权限变成**查询条件**，让数据库层面就查不出来：

```python
results = vector_db.search(
    query_vector=qv,
    namespace=f"tenant_{claims.tenant_id}",     # 一租户一命名空间
    filter={
        "$and": [
            {"tenant_id": {"$eq": claims.tenant_id}},
            {"acl_groups": {"$in": claims.groups}},
        ]
    },
    top_k=50,
)
```

三个要点：

**一、租户 ID 来自签名令牌，不来自请求参数。** 从 JWT 之类的签名凭证里取，客户端改不了。这是整套隔离的地基。

**二、一个租户一个命名空间。** 命名空间是硬隔离，比过滤条件更可靠——过滤条件写漏了还能查到别的租户，命名空间写错了直接查不到东西（失败是显性的）。

**三、过滤在数据库层执行**，不是取回来再在应用层筛。取回来再筛意味着数据已经离开了存储边界。

### 索引时也要打好标签

检索时能过滤的前提是索引时打了标签：

```json
{
  "chunk_id": "doc-77:3",
  "tenant_id": "acme",
  "acl_groups": ["finance", "managers"],
  "sensitivity": "internal",
  "source_doc": "doc-77"
}
```

要注意：

- **权限变更要同步**——用户被移出某个组之后，检索结果要立刻变，见 [[05-Freshness 与 tombstone 删除传播]]
- **权限继承要展开**——「财务部所有人」要在索引时展开成具体的组标签，别在查询时做复杂的图遍历
- **文档权限变更要重新打标**——不只是新文档

**第一条最容易漏**：人事变动后权限系统更新了，但向量索引里的标签还是旧的。

### 一个容易被忽略的泄漏面

**元数据本身可能泄漏信息。** 即便过滤了内容，如果返回结果里带了「共找到 137 条相关文档，其中 92 条你无权查看」，攻击者就能通过构造查询来探测存在性。

处理：

- 不返回被过滤掉的数量
- 不返回「你无权访问」这类区分性的错误——统一返回「未找到」
- 注意时间差异：有权限和无权限的查询耗时不该有明显区别

最后一条和缓存的时序侧信道是同一类问题，见 [[05-缓存安全与跨租户命中]]。

### 工具调用也一样

RAG 之外，工具调用的权限同样要在**执行时**按当前用户判，而不是执行后过滤结果，见 [[06-四层参数校验]]。

同一个原则：**不该拿到的，从来不该被取出来。**

### 怎么测

权限问题不会自己暴露，要主动测：

- **跨租户测试**：用租户 A 的身份，构造能命中租户 B 内容的查询
- **跨角色测试**：普通用户构造能命中管理员内容的查询
- **权限变更测试**：移除某个组之后，立刻查之前能查到的内容
- **存在性探测**：通过结果数量、错误信息、耗时差异能否推断出无权内容的存在

这几条要进对抗测试集并接 CI，critical 级零容忍，见 [[03-对抗测试集]]。

## 坑

**生成后过滤。** 越权已经发生，而且模型改写后过滤器认不出来。

**租户 ID 从请求参数取。** 客户端能改，等于没有隔离。

**只过滤不分命名空间。** 过滤条件写漏了就泄漏，而命名空间写错是显性失败。

**权限变更不同步索引。** 人走了还能查到，这是最常见的合规问题。

**泄漏「你无权查看 N 条」。** 存在性本身就是信息。

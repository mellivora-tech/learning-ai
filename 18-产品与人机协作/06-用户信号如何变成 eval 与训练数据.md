用户每天都在免费告诉你哪里做错了——点了踩、重问了一遍、把答案改了、直接转人工。问题是这些信号绝大多数被扔掉了。

## 一句话

用户信号是**线索不是标签**——必须经过一道人工判定才能进 eval 集，否则会把误报当成错误训进去。

## 原理

![[用户信号的两种来源.excalidraw.md|700]]

### 信号有哪几种

![[用户信号流入 eval 集.excalidraw.md|700]]

按「信息量」和「噪声」两个维度排：

| 信号 | 信息量 | 噪声 | 说明 |
| --- | --- | --- | --- |
| **用户改了答案** | **最高** | 低 | 改前改后就是一对样本 |
| 转人工 | 高 | 中 | 但不知道具体哪里不行 |
| 立刻重问同一个问题 | 中 | 中 | 强烈暗示上一次没答好 |
| 👎 | 中 | **高** | 相当一部分是误报 |
| 👍 | 低 | 高 | 用户很少点，且点了也不代表正确 |
| 会话中途放弃 | 低 | 高 | 原因太多 |

**第一行是金矿**。用户的修改动作同时给了「原答案错在哪」和「正确答案是什么」，这是标注员做的活儿而用户免费做了，见 [[03-HITL 交互设计]]。

**倒数第二行经常被高估**：👍 的数据几乎没用，别在它上面花力气。

### 关键的一道闸门

**👎 里有相当一部分是误报。** 常见的误报来源：

- 答案是对的，但用户不喜欢（态度、长度、语气）
- 用户自己的问题问错了
- 用户误解了答案
- 手滑

**所以信号不能直接当标签。** 直接把 👎 的样本当负例进 eval 集或训练集，等于把噪声固化下来——之后每次改动都要迎合一批本来就是对的样本。

正确流程是：**信号 → 优先级排序 → 人工判定 → 才进 eval 集**。

### 采集时必须一起记下的东西

信号本身没用，得能还原当时发生了什么。所以采集时要关联：

| 记什么 | 为什么 |
| --- | --- |
| **trace id** | 能拉回完整调用链，见 [[01-Trace 与 Span]] |
| 完整的输入与输出 | 复现的前提 |
| **检索到的片段** | 判断是检索问题还是生成问题 |
| 模型版本与提示词版本 | 判断是不是某次改动引入的，见 [[07-数据版本化]] |
| 用户改成了什么 | 直接的期望输出 |
| 拒绝原因（选项化） | 自由文本没法统计 |

**「检索到的片段」这一条最容易漏**，而漏了之后你根本分不清「模型编的」和「检索就没找到」——这两个的修法完全不同，见 [[06-检索评估两段式]]。

### 怎么排优先级

信号很多，人工判定的力气有限。排序依据：

1. **重复出现的模式**——同一类问题多个用户都反馈，优先
2. **高价值用户或高价值场景**
3. **和已有 golden set 不重合的**——重复的没有信息量
4. **代价大的错误**——安全、合规类的一律优先

**第三条常被忽略**：如果新收的样本 golden set 里已经有类似的，加进去只是稀释，不产生新信息，见 [[01-Golden set]]。

### 进 eval 集还是进训练集

判定完是真错之后，两个去处：

| 去处 | 什么时候 | 数量级 |
| --- | --- | --- |
| **golden set** | **默认走这里** | 几百条就有用 |
| 训练集 | 确认是行为问题、且量够，见 [[01-四条路线选型：prompt、RAG、LoRA、蒸馏]] | 几千条起 |

**默认走 golden set。** 大部分失败用改提示词、改检索就能解决，而 golden set 能验证改没改好。直接拿去微调是最贵也最容易搞坏的路径，见 [[06-灾难性遗忘]]。

### 别让闭环变成过拟合

一个隐蔽的风险：**只按用户反馈优化，会越来越擅长「用户会抱怨的那类问题」，而在没人抱怨的地方悄悄退步。**

因为反馈是有偏的——沉默的成功和沉默的失败都不产生信号。

对策：

- **保留一批不受反馈影响的基准样本**，定期跑，见 [[02-回归测试与 CI 门禁]]
- 主动抽样复核（不只看有反馈的）
- 监控整体分布，见 [[03-漂移监控三条线]]

## 坑

**把 👎 直接当负例。** 相当一部分是误报，固化下来之后每次改动都要迎合本来就对的样本。

**只记信号不记上下文。** 事后无法复现，也分不清检索问题还是生成问题。

**在 👍 上花力气。** 数据量小且几乎不含信息。

**收到反馈就拿去微调。** 默认应该进 golden set，微调是最贵最容易搞坏的路径。

**只按反馈优化。** 反馈有偏，会在没人抱怨的地方悄悄退步。

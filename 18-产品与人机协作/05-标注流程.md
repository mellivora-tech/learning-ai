标注质量的上限不是标注员的水平，是标注规范的清晰度——规范说不清楚的地方，请再多人也标不一致。

## 一句话

**先用一致率检验规范，再扩大标注量**——规范不清楚时增加人力只会增加噪声。

## 原理

### 从规范开始，不从人力开始

标准流程：

1. **写规范**——把判定规则写清楚，见 [[01-怎么定义「好」]]
2. **小批试标**——两三个人独立标同一批 30–50 条
3. **算一致率**——不一致的地方就是规范的漏洞
4. **改规范**——针对分歧补规则和例子
5. **重复 2–4 直到一致率达标**
6. **然后才扩量**

**第 5 步之前不要扩量。** 规范不清楚时标 1000 条，得到的是 1000 条噪声，而且事后没法修——你不知道哪些是错的。

### 一致率多少算够

看任务类型：

| 任务 | 目标一致率 |
| --- | --- |
| 客观判定（格式对不对、字段值是多少） | 95% 以上 |
| 半客观（回答有没有依据） | 85% 以上 |
| 主观（哪个回答更好） | 70% 以上就不错 |

**主观任务达不到高一致率是正常的**，不要硬追——那说明这个维度本身就有分歧，应该考虑拆成更客观的子维度。

### 规范里必须有的东西

| 部分 | 说明 |
| --- | --- |
| **判定规则** | 每个标签的定义 |
| **正例** | 典型的该标这个的例子 |
| **反例** | **看起来像但不该标的例子** |
| **边界情况** | 分歧最多的那些，逐条给裁决 |
| **不确定怎么办** | 允许标「不确定」并说明，别逼着二选一 |

**反例和边界情况是规范的价值所在**。只有正例的规范等于没写——分歧从来不在典型案例上。

**最后一条也很重要**：逼着标注员在模糊案例上二选一，会得到随机的标签，还不如让他们标出来供后续裁决。

### 谁来标

| 场景 | 谁 |
| --- | --- |
| 定规范、裁决边界 | **领域专家**，见 [[05-人工评估作为校准工具]] |
| 客观判定的批量标注 | 标注员，规范够清晰就行 |
| **需要领域知识的判定** | **必须专家**——外包会得到大量看似合理的错标 |
| 预标注 | 模型先标，人来改，见 [[04-Judge 校准]] |

**模型预标注 + 人工修正**能显著提速，但有个陷阱：**人倾向于接受模型的答案**（和自动化偏见同一回事，见 [[03-HITL 交互设计]]）。对策是混入一批不给预标注的样本作为对照。

### 质量怎么持续保证

扩量之后不能不管：

- **混入已知答案的样本**——算每个标注员的准确率
- **重复标注**——一部分样本标两遍，看一致性
- **定期抽检**——专家复核一小部分
- **监控速度异常**——标得特别快的通常没认真看

**第一条是性价比最高的**，可以自动化，而且不打扰标注员。

### 标注是持续的，不是一次性的

数据在变、模型在变、标准在变，所以：

- **新出现的失败模式**要补进标注，见 [[06-用户信号如何变成 eval 与训练数据]]
- **规范要版本化**，标注数据要记录用的是哪版规范，见 [[07-数据版本化]]
- **老数据在规范变更后可能要重标**

**规范版本化那一条经常被漏掉**，结果是数据集里混着按不同标准标的数据，而且分不出来。

## 动手做

- [ ] 写第一版规范，包含正例、反例、边界情况
- [ ] 找两三个人独立标 30–50 条，算一致率
- [ ] 针对分歧改规范，重复到一致率达标
- [ ] 允许标「不确定」，并定期裁决这些
- [ ] 扩量后混入已知答案样本，监控每个标注员的准确率
- [ ] 试模型预标注 + 人工修正，同时留一批无预标注的对照
- [ ] 给规范加版本号，标注数据记录规范版本

## 算学会了

- [ ] 先验证规范再扩量
- [ ] 知道自己任务的一致率目标，且实测达标
- [ ] 规范里有反例和边界裁决
- [ ] 有持续的质量监控（已知答案样本）
- [ ] 规范和标注数据都版本化了

## 坑

**规范没验证就扩量。** 得到的是没法修的噪声。

**规范只有正例。** 分歧从来不在典型案例上。

**逼着在模糊案例上二选一。** 得到随机标签，不如允许标「不确定」。

**用模型预标注不留对照。** 人会倾向于接受模型答案，一致率虚高。

**规范不版本化。** 数据集里混着不同标准的数据，还分不出来。

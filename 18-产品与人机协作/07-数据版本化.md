「上周那个 eval 跑出来是 87%，今天同样的代码跑出来 82%」——如果说不清中间哪个数据变了，这个系统就没法被优化。

## 一句话

**分数只有在「模型 + 提示词 + 检索库 + 评测集 + 判定规范」五样都可定位时才有意义**，任何一样没版本化，回归对比就是自欺欺人。

## 原理

![[可复现要钉住四样东西.excalidraw.md|700]]

### 五样都得版本化

| 东西 | 变了会怎样 | 怎么定位 |
| --- | --- | --- |
| **模型** | 分数整体漂移 | 模型 id + 版本/快照日期 |
| **提示词** | 行为变化 | 提示词模板的 git commit |
| **检索库** | 召回变化 | 索引快照 id + 文档集版本 |
| **评测集** | **分数不可比** | 数据集版本号 |
| **判定规范** | 判定标准变了 | 规范版本号，见 [[05-标注流程]] |

**第四、五样最容易被漏**。往 golden set 里加了 20 条难题，分数从 87% 掉到 82%——不是系统退步了，是尺子换了。没记版本的话这个误判几乎必然发生。

### 检索库是最难的那个

代码有 git，模型有版本号，检索库没有天然的版本。而它一直在变：文档增删改、重新切块、换 embedding 模型、重建索引。

可行的做法：

- **记录索引构建时的元信息**——文档集快照、chunking 配置、embedding 模型与版本，见 [[02-Embedding 模型选型与评估]]
- **给索引本身一个 id**，评测结果里记下用的是哪个
- **重建索引时不覆盖旧的**，至少保留上一版，方便对比

**换 embedding 模型必须重建全部索引**——新旧向量不在同一个空间里，混着用会静默地检索错，而且不报错。这是最难查的一类问题。

### 评测集的正确改法

golden set 会持续加样本，见 [[06-用户信号如何变成 eval 与训练数据]]。改法要有纪律：

| 做法 | 说明 |
| --- | --- |
| **加样本时打版本号** | v3 → v4 |
| **同时报告两个数** | 「v3 上 87%（和上次可比），v4 上 82%（新基线）」 |
| **保留一个稳定核心集** | 长期不动，专门用来看趋势 |
| 删样本要记录原因 | 删掉难题会让分数虚高 |

**「保留一个稳定核心集」是最实用的一条**——有了它，长期趋势才看得出来，见 [[02-回归测试与 CI 门禁]]。

### 评测结果要带全套指纹

每次评测的结果记录里，至少要有：

```
eval_run_id
model: Qwen3-8B @ <权重 sha>
prompt_version: <git commit>
index_id: <索引快照 id>
dataset_version: v4
rubric_version: v2
score: {...}
```

**这一条实现起来很便宜，不实现的代价却很大**——半年后想回答「什么时候开始变差的」，没有指纹就只能猜。

### 训练数据也一样

如果做微调，训练数据的版本化同样重要，见 [[02-SFT 数据构造]]：

- 训练集的确切内容（不是「大概几千条」）
- 数据来源与过滤规则
- **和 eval 集有没有重叠**——重叠了分数就是假的

**最后一条是最致命的**。用户反馈的样本同时进了训练集和 eval 集，评测分数会很好看，线上却没改善。所以两个集合的划分必须在数据进来时就定好，而不是事后分。

### 别过度工程

不需要一上来就上专门的数据版本管理系统。**最小可用版本**：

- 数据集存成文件，进 git（或加 LFS）
- 索引构建脚本的配置进 git
- 评测结果写成 JSON 存下来，带上全套指纹

**这套东西一天能搭好，能解决九成的可复现问题。** 需要更强的（比如 DVC、LakeFS）时你自然会知道。

## 动手做

- [ ] 检查那五样里，你现在有几样能定位到确切版本
- [ ] 给 golden set 加版本号，改动时同时报告新旧两个数
- [ ] 划出一个长期不动的稳定核心集
- [ ] 给索引加 id，评测结果里记下用的哪个
- [ ] 实现评测结果的全套指纹记录
- [ ] 检查训练集和 eval 集有没有重叠
- [ ] 找一次历史上「分数变了」的记录，看能不能定位到是什么变了

## 算学会了

- [ ] 五样都能定位到确切版本
- [ ] golden set 改动时会同时报告可比的旧分数
- [ ] 有长期不动的稳定核心集
- [ ] 评测结果带全套指纹
- [ ] 确认过训练集和 eval 集无重叠

## 坑

**只版本化代码。** 检索库和评测集变了，分数就不可比。

**改了 golden set 直接对比新旧分数。** 尺子换了，分数变化说明不了任何事。

**换 embedding 模型不重建索引。** 新旧向量不在同一空间，静默检索错，不报错。

**训练集和 eval 集重叠。** 分数很好看，线上没改善。

**一上来就上重型数据版本系统。** 文件进 git + 结果带指纹，一天搭好，解决九成问题。

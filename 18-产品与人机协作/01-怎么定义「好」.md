「让它回答得更好一点」——这是所有 AI 项目里最贵的一句话，因为在把「好」写成可判定的规则之前，没人能证明改动有没有用。

## 一句话

**「好」必须落成一条能对同一个输出给出稳定判定的规则**，否则评估、优化、验收全都无从谈起。

## 原理

### 三层，从模糊到可判定

| 层 | 例子 | 能判定吗 |
| --- | --- | --- |
| 感受 | 「回答得更专业一点」 | 不能 |
| 属性 | 「不能编造数据」「要引用来源」 | 勉强 |
| **规则** | **「每个数字都必须出现在检索到的片段里」** | **能** |

**必须推到第三层。** 判据很简单：**两个人拿同一条输出，按这条规则判，会不会得出同一个结论？** 不会就还没到位。

推的方法是不断追问「怎么才算」：

> 「回答要专业」→ 怎么才算专业？
> →「用词准确、有依据」→ 怎么才算有依据？
> →「引用了文档」→ 引用到什么程度？
> →「**每个事实性断言后面都有一个引用标记，且引用的片段确实支持这个断言**」✓

### 「好」不是一个维度

一个输出可以在某些维度好、某些维度差。所以要拆开：

| 维度 | 典型规则 |
| --- | --- |
| **正确性** | 事实无误、数字对得上 |
| **有据性** | 每个断言都能追溯到来源，见 [[06-幽灵文档测试]] |
| **完整性** | 该覆盖的点都覆盖了 |
| **格式** | schema 合法、字段齐全，见 [[01-结构化输出三档]] |
| **安全** | 不泄露、不越权，见 [[04-权限过滤时机]] |
| **成本与延迟** | 在预算内，见 [[04-成本归因与每次成功任务成本]] |

**拆开之后才能做取舍**：这次改动正确性 +3%、延迟 +40%，值不值？没拆开的时候这个问题问不出来。

### 分级，不是二值

多数任务不是「对/错」，中间有层次：

```
优秀  — 正确、完整、有据、格式对
可用  — 正确但不够完整，用户还得追问
凑合  — 部分正确，需要人工修
错误  — 事实错误或严重遗漏
有害  — 泄露、越权、误导
```

**「有害」要单独拎出来，它不是「更差的错误」而是另一类东西**——它的容忍度是零，而普通错误可以有百分之几的配额，见 [[03-对抗测试集]]。

### 谁说了算

规则定下来之后还有一个问题：**谁的判断是权威？**

| 判定者 | 用在哪 |
| --- | --- |
| **领域专家** | 定标准、定标注规范，见 [[05-人工评估作为校准工具]] |
| 标注员 | 批量打标，见 [[05-标注流程]] |
| **自动判定** | 能程序化的部分（格式、引用是否存在） |
| Judge 模型 | 需要语义判断的部分，见 [[04-Judge 校准]] |
| 用户信号 | 真实反馈，但有噪声，见 [[06-用户信号如何变成 eval 与训练数据]] |

**优先级：能程序化的就别用模型判。** 「JSON 是否合法」「引用的片段是否真的存在」这类判定，写个函数比调 judge 又快又准又免费。

### 落地成 golden set

定义完了要变成资产，见 [[01-Golden set]]：

- 每条样本带上**期望输出**或**判定规则**
- 覆盖各个维度和各个难度档
- 进 CI，见 [[02-回归测试与 CI 门禁]]

**没有 golden set 的「好」的定义等于没定义**——它无法阻止下一次改动把事情弄坏。

### 什么时候该重新定义

「好」不是定一次就完了：

- 用户开始抱怨你没测的维度
- 某个维度已经饱和（都是满分），失去了区分度
- 业务场景变了

**第二条最容易被忽略**：当所有样本都过了，这批样本就不再产生信息了，见 [[03-对抗测试集]]。

## 动手做

- [ ] 拿你现在的「好」的描述，用「怎么才算」追问到可判定为止
- [ ] 让两个人独立按这条规则判 20 条输出，算一致率
- [ ] 把「好」拆成至少四个维度，各写一条规则
- [ ] 定出五档分级，且把「有害」单独拎出来
- [ ] 标出哪些维度能程序化判定，先把这些实现掉
- [ ] 把规则落成 golden set 进 CI

## 算学会了

- [ ] 「好」的定义能让两个人得出同一个结论
- [ ] 拆成了多个维度，能做取舍
- [ ] 「有害」单独一档，容忍度为零
- [ ] 能程序化的判定没用 judge 模型
- [ ] 定义已经落成 golden set 并进了 CI

## 坑

**停在「更专业」这一层。** 无法判定就无法优化。

**只用一个总分。** 掩盖了维度之间的取舍。

**把「有害」当成更差的错误。** 它的容忍度是零，不该和普通错误共用配额。

**能写函数判的用 judge 模型。** 又慢又贵还不准。

**定义完不落成 golden set。** 挡不住下一次改动。

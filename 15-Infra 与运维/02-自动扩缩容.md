Web 服务的扩缩容是解决过的问题。GPU 推理不是——因为它的冷启动以分钟计，而扩容信号往往来得太晚。

## 一句话

按**队列深度或等待时间**扩容，不按算力利用率；而冷启动的分钟级延迟意味着**必须提前扩**，等指标到阈值就来不及了。

## 原理

### 用什么指标触发

| 指标 | 好用吗 |
| --- | --- |
| 算力利用率 | **不好**——它到顶之前显存就 OOM 了，见 [[01-GPU 容量规划]] |
| 显存利用率 | 可以，但它到 95% 时已经在抢占了 |
| **队列深度** | **好**——领先指标 |
| **等待时间** | **最好**——直接对应用户感受 |
| 抢占次数 | 好——说明已经过载，见 [[06-驱逐与内存压力]] |

**推荐用等待时间当主指标**：队列深度 1000 在快系统里没事、在慢系统里是灾难，而「预计等待超过 X 秒」在任何系统里都说得通，见 [[03-超时与背压]]。

### 冷启动是核心矛盾

> [!warning] 一个新副本可能要十几分钟才能服务
> 起一个 LLM 实例的耗时可能在 **10–14 分钟**量级——拉镜像、加载几十 GB 权重、初始化引擎、预热。极大的模型（几百 B）光加载权重就要十几分钟。
>
> 经过优化（镜像预拉取、权重放本地 NVMe、缓存管理）能压到一分钟以内，但这需要专门的工程投入。
>
> **十几分钟意味着「等指标到阈值再扩容」必然来不及**——那时候用户已经等了十几分钟。

所以策略只能是：

- **提前扩**——按预测而不是按当前指标，比如按历史同时段流量
- **保留缓冲**——常驻比实际需要多一点的容量
- **预热池**——起好但不接流量的实例，需要时秒级接入
- **缩容要慢**——扩容快、缩容慢，避免抖动导致反复冷启动

### 缩容到零划不划算

serverless 式的「无流量就缩到零」对 GPU 推理通常不成立：

**经验分界线是持续 5–10 RPS**。超过这个量，养一个常驻副本的成本已经低于用户吃冷启动的代价。

低于这个量的场景（内部工具、低频批处理）可以考虑缩到零，但要接受首个请求的分钟级延迟——**产品上必须明确告知**，见 [[06-降级 UX]]。

### 怎么压缩冷启动

按收益排：

| 做法 | 效果 |
| --- | --- |
| **镜像预拉取 / 本地缓存** | 省掉几 GB 的拉取时间 |
| **权重放本地 NVMe 而非网络存储** | 加载快几倍 |
| **预热池** | 把冷启动移出关键路径 |
| 更小的模型 | 加载时间和大小成正比，见 [[07-蒸馏]] |
| 量化 | 权重小一半，加载快一半，见 [[09-量化]] |

**前两条是最基础也最有效的**，而且不需要改架构。

### 缩容要小心正在跑的请求

GPU 推理的请求可能跑几分钟。缩容时直接杀实例会让这些请求全部失败。

正确做法：

1. **先从负载均衡摘掉**，不再接新请求
2. **等现有请求跑完**（设一个最长等待）
3. **超时未完成的转移或转人工**，见 [[03-升级到人与结构化中间状态]]
4. 然后才销毁

**这个优雅退出的窗口要按 P99 请求耗时设**，不是按平均。

### 多副本的路由也要管

扩出来的副本之间怎么分流量，会影响前缀缓存的命中率：

- **轮询**：简单，但同一个租户的请求分散到各副本，前缀缓存全部落空，见 [[05-Prefix caching]]
- **按前缀哈希路由**：同前缀的请求打到同一副本，命中率高
- **按租户路由**：兼顾隔离和命中率，见 [[06-多租户隔离]]

**默认的轮询会显著拉低缓存命中率**，这是扩容后成本不降反升的常见原因。

## 动手做

- [ ] 把扩容触发指标从算力利用率换成等待时间，对比效果
- [ ] 测一次真实的冷启动耗时，拆解各阶段占比
- [ ] 实施镜像预拉取和权重本地化，看能压到多少
- [ ] 算你的持续 RPS，判断该不该缩到零
- [ ] 实现优雅退出，验证缩容不会杀掉正在跑的请求
- [ ] 对比轮询和按前缀哈希路由的缓存命中率差异

## 算学会了

- [ ] 用等待时间或队列深度触发扩容，不用算力利用率
- [ ] 知道冷启动是分钟级的，所以必须提前扩
- [ ] 能说出自己系统的冷启动耗时构成
- [ ] 缩容有优雅退出，按 P99 设窗口
- [ ] 路由策略考虑了前缀缓存命中率

## 坑

**按算力利用率扩容。** 显存先 OOM，扩容来不及。

**等指标到阈值再扩。** 冷启动十几分钟，用户已经走了。

**缩容直接杀实例。** 正在跑的长请求全部失败。

**扩容后用轮询路由。** 前缀缓存命中率暴跌，成本不降反升。

**盲目追求缩容到零。** 5–10 RPS 以上时常驻副本更划算。

知识库里一半内容在图里——架构图、流程图、截图、扫描件。纯文本的 RAG 对它们视而不见。

## 一句话

多模态 RAG 有两条路：**把图转成文字再走原有链路**，或者**用统一的向量空间直接检索图**；前者更省事，后者上限更高。

## 原理

### 先问一个问题

上多模态之前，先确认收益：**统计你的语料里，有多少信息只存在于非文本内容中。**

- 图只是配图、正文已经说清楚了 → **不需要**
- 关键数据只在表格截图里、流程只在架构图里 → 需要

**很多团队上多模态是因为「文档里有图」，而不是因为「图里有信息」。** 前者不构成理由。

### 两条路

**路线一：转成文字，走原有链路。**

```text
图片 → OCR / 图像描述模型 → 文本 → 切分 → embedding → 现有索引
```

优点是**完全复用现有的检索链路**——切分、混合检索、重排、评估全都不用改，见 [[03-Hybrid search（dense + BM25 + RRF）]]。

缺点是转换会丢信息：图表的空间关系、颜色编码、手写体、复杂表格的结构。

**路线二：多模态向量，直接检索图。**

用能把图和文编码到**同一个向量空间**的模型，查询是文字、召回的是图。

优点是不经过转换、保留原始信息。缺点是要引入新的模型和索引，且现有的评估、重排链路要重做。

### 务实的做法是混着来

生产上更常见的是**两条路并存**：

| 内容类型 | 走哪条 |
| --- | --- |
| 扫描件、PDF 里的正文 | OCR 转文本 |
| 表格（含截图里的表） | OCR + 结构化解析，**转成 markdown 表格** |
| 架构图、流程图 | 图像描述模型生成描述，同时保留原图 |
| 照片、产品图 | 多模态向量 |

**注意第三行的「同时保留原图」**：检索靠描述文本，但给模型的时候把原图也带上。这样检索走的是成熟链路，理解走的是模型的视觉能力，两边都不吃亏。

### 表格是最值得单独处理的

表格在企业语料里占比高、信息密度大，而且**最容易被 OCR 毁掉**——行列关系一丢，数字就全串了。

处理建议：

- **转成 markdown 表格**而不是纯文本流，结构能保住
- **表格不要跨块切分**，一张表就是一个块，见 [[01-Chunking 四种策略]]
- **给表格块加一段上下文说明**（这张表出自哪节、讲什么），这正是 contextual retrieval 的做法
- 大表可以按行分块，但**每块都带上表头**

### 成本要单独算

多模态的 token 计算和纯文本完全不同——一张图可能相当于几百到几千 token，见 [[01-图像与音频的 token 计算]]。

两处成本：

- **索引期**：OCR 或图像描述，一次性但量大
- **查询期**：如果把原图塞进上下文，每次查询都要付这个 token 钱

**第二项容易失控**：召回 5 个块，其中 3 个带图，一次请求的 token 数可能翻几倍。所以要给图片单独设预算，见 [[02-Context engineering：上下文即预算]]。

### 评估要相应调整

两段式评估的框架不变，但标注要扩展，见 [[06-检索评估两段式]]：

- **相关性标注**要包含图——「回答这个问题需要看哪几张图」
- **groundedness** 要能判断「回答里的数字是不是真的来自那张表」
- 增加一类专门的测试：**只有图里才有答案的问题**，测纯文本链路会不会瞎编

最后一项最有价值——它直接量出「上多模态之前，有多少问题是答不对的」，也就是这件事的收益上限。

### 别忽略音频和视频

同样的框架适用于音频（转录后走文本链路）和视频（抽帧 + 转录）。区别在于：

- 音频转录的质量直接决定上限，专有名词和口音是主要难点
- 视频要处理**时间维度**——检索到的应该是一个时间段，而不是整个视频

**多数场景下，把音视频转成带时间戳的文本，走原有链路就够了。**

## 动手做

- [ ] 统计语料里「信息只存在于非文本内容」的比例，判断值不值得做
- [ ] 构造一批「只有图里才有答案」的问题，测纯文本链路的准确率——这是收益上限
- [ ] 对表格单独处理：转 markdown、不跨块切、带表头，测 recall 变化
- [ ] 对比两条路线在你的语料上的 recall
- [ ] 算清索引期和查询期的成本，给图片设上下文预算
- [ ] 扩展评估标注，加入图片相关性和表格数字的 groundedness

## 算学会了

- [ ] 上多模态之前先量出收益上限
- [ ] 知道两条路线各自的取舍，会按内容类型混用
- [ ] 表格单独处理，转 markdown 且不跨块切
- [ ] 算过多模态的索引期和查询期成本
- [ ] 评估里有「只有图里才有答案」这类测试

## 坑

**因为「文档里有图」就上多模态。** 该问的是「图里有没有独有信息」。

**表格用纯文本 OCR。** 行列关系一丢，数字全串，而且看起来还挺正常。

**表格跨块切分。** 半张表比没有表更危险。

**忘了查询期成本。** 召回几个带图的块，token 数翻几倍。

**评估不改。** 用纯文本的评估集测多模态系统，测不出任何东西。

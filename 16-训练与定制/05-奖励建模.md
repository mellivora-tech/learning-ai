奖励模型是把「人类偏好」变成一个可优化的数字。而这个转换本身，就是整条链路上最容易出错的一环。

## 一句话

奖励模型是一个**需要被评估的模型**；它学到的往往不是「什么是好回答」，而是「标注者偏好什么」——两者的差距就是所有奖励攻击的来源。

## 原理

### 它在链路里的位置

经典 RLHF 是两段：

```text
偏好数据 → 训奖励模型（打分器）
                ↓
       策略模型用 RL 优化，最大化这个分数
```

DPO 的贡献就是证明了这两段可以合成一段，见 [[04-DPO 与偏好优化]]。所以**如果你走 DPO，就不需要单独训奖励模型**。

那什么时候还需要它？

- 走 PPO 这类真正的 RL
- 需要一个**独立的打分器**用于筛选、重排、拒绝采样
- 做 best-of-N：生成 N 条，用奖励模型挑最好的，见 [[02-Test-time compute scaling]]

**第三个用途在应用层最实用**，而且不需要真的做 RL。

### 奖励攻击

> [!warning] 模型会去优化分数，而不是优化质量
> 这是奖励建模的核心风险：策略模型会找到**让奖励模型给高分但实际不好**的输出。
>
> 典型形态：
> - **变长**——奖励模型学到「长的通常更好」，策略就一直写长
> - **堆格式**——分点、加粗、小标题，看起来用心
> - **过度自信**——不带犹豫的措辞得分更高
> - **迎合**——顺着用户说，不管对错
>
> 这几条和人类投票榜的偏差是同一批，见 [[04-排行榜怎么读]]——因为奖励模型学的就是人的偏好。

缓解手段：

- **长度归一化**——训练时把长度作为混杂因素处理
- **KL 约束**——限制策略偏离参考模型的程度（DPO 里的 $\beta$ 就是干这个的）
- **多个奖励模型取共识**——单个模型的漏洞不容易被同时利用
- **定期用人工评估校准**——见 [[05-人工评估作为校准工具]]

### 可校验奖励：绕开这个问题

有一类任务不需要学人类偏好——**奖励可以直接算出来**：

| 任务 | 奖励从哪来 |
| --- | --- |
| 数学 | 答案对不对 |
| 代码 | 测试跑不跑得过 |
| 结构化抽取 | schema 校验 + 字段正确率 |
| 检索 | 引用的文档是否真的支持结论 |

这就是 RLVR 的思路，也是 2026 年推理模型能力跃升的关键，见 [[08-预训练、后训练、对齐]]。

**它的优势是根本性的**：奖励绝对准确、可以无限量产、不存在奖励攻击（因为奖励就是真实目标本身）。

**所以判断顺序是：能自动校验的就别学人类偏好。** 很多团队默认要做奖励模型，其实他们的任务有客观判据。

### 训奖励模型要注意的

真要训的话：

**数据**：和偏好优化用同一批数据，注意事项也一样——同源候选、长度平衡、标注一致，见 [[04-DPO 与偏好优化]]。

**规模**：奖励模型不必和策略模型一样大。小一档通常够用，而且推理成本低（做 best-of-N 时要跑 N 次）。

**评估**：这是最容易被跳过的一步。要测：

- **和人类偏好的一致性**——用留出的偏好对测准确率
- **校准**——分数高的是不是真的更好
- **对长度的敏感度**——把长度控制住之后准确率掉多少

**第三项最能暴露问题。** 控制长度后准确率大跌，说明它学的主要是长度。

### 和 judge 的关系

奖励模型和 LLM judge 干的是类似的事——给输出打分。区别：

| | 奖励模型 | LLM judge |
| --- | --- | --- |
| 形态 | 专门训的打分器 | 通用模型 + 提示词 |
| 成本 | 低（小模型，一次前向） | 高（大模型，生成推理） |
| 灵活性 | 低（改标准要重训） | 高（改提示词即可） |
| 用途 | 训练循环、best-of-N | 评估、见 [[04-Judge 校准]] |

**评估用 judge，训练和高频筛选用奖励模型。** 两者的校准方法是相通的——都要先测和人的一致性。

## 动手做

- [ ] 先判断：你的任务有没有可自动校验的奖励，有的话别训奖励模型
- [ ] 如果确实需要，用偏好数据训一个小的，测和人类偏好的一致性
- [ ] 做长度控制实验：把长度对齐之后准确率掉多少
- [ ] 用它做一次 best-of-N，对比不筛选时的质量提升
- [ ] 观察是否出现奖励攻击的迹象：输出变长、格式堆砌、语气变自信
- [ ] 定期用人工评估校准，看一致性有没有漂移

## 算学会了

- [ ] 知道走 DPO 就不需要单独的奖励模型
- [ ] 能说出四种典型的奖励攻击形态
- [ ] 优先考虑可自动校验的奖励，而不是学人类偏好
- [ ] 会做长度控制实验来检验奖励模型学到了什么
- [ ] 分得清奖励模型和 LLM judge 的分工

## 坑

**有客观判据还去学人类偏好。** 可校验奖励又准又免费，还没有奖励攻击。

**不测长度敏感度。** 奖励模型很可能主要学到了「长的更好」。

**不做 KL 约束。** 策略会一路跑偏去钻奖励模型的漏洞。

**奖励模型和策略模型一样大。** 成本高，而小一档通常够用。

**训完不校准。** 它和人的一致性会随输入分布漂移。

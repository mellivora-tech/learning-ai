SFT 教模型「该怎么答」，偏好优化教它「哪个答得更好」。后者不需要标准答案，只需要两个候选和一个偏好。

## 一句话

偏好优化的目标函数是**「让好回答的概率高于坏回答」**，所以它只需要相对判断；而 DPO 证明了这件事不必绕道强化学习。

## 原理

### 目标变了

SFT 最大化「正确答案」的似然，见 [[08-预训练、后训练、对齐]]。偏好优化换了个问题：给定一对回答 $(y_w, y_l)$，让胜出的那个概率更高。

**这个转变很关键**：很多任务没有唯一正确答案，但人很容易判断「A 比 B 好」。**相对判断比绝对标注便宜得多，也准确得多。**

### 几条路线

| 方法 | 怎么做 | 复杂度 |
| --- | --- | --- |
| **RLHF（PPO）** | 先训奖励模型，再用强化学习优化策略 | 高——要多训两个模型 |
| **DPO** | 数学上证明可以跳过奖励模型，直接从偏好对推出损失 | **低** |
| **GRPO** | 一个 prompt 采样多份，用组内相对优劣算优势，省掉 critic | 中 |
| **RLVR** | 奖励来自可自动校验的信号，不是人类偏好 | 中 |

**DPO 是自己动手做偏好优化时的合理起点**——不需要奖励模型、不需要 RL 训练循环，就是一个改过的损失函数。

至于 2026 年前沿模型在用什么，见 [[08-预训练、后训练、对齐]]：GRPO 和 RLVR 已经取代了经典 RLHF 的位置。但那是训基座模型的语境，**应用层做偏好微调，DPO 通常够用**。

### DPO 的直觉

损失大致是：让「模型给胜出回答的相对概率」超过「参考模型给它的相对概率」，同时对败者反向。参考模型通常是 SFT 之后的那个 checkpoint。

关键的超参是 $\beta$——控制偏离参考模型的程度：

- $\beta$ 小：允许偏离更多，学得更狠，但容易跑偏
- $\beta$ 大：贴着参考模型，更稳但学不动

**从 0.1 附近起步**，观察生成质量有没有退化。

### 数据是主要难点

偏好数据的构造比 SFT 更麻烦：

**从哪来：**

- **人工对比标注**——质量最好，最贵
- **用户信号**——点赞/点踩、重新生成、复制走了没有，见 [[06-用户信号如何变成 eval 与训练数据]]
- **模型生成 + judge 打分**——便宜，但会继承 judge 的偏见，见 [[04-Judge 校准]]
- **规则构造**——比如「通过校验的 vs 没通过的」，适合有客观判据的任务

**最后一种被低估**：如果你有验证器（schema 校验、测试跑通），就能自动构造大量偏好对——正确的是 $y_w$，出错的是 $y_l$。**成本几乎为零，而且判断绝对准确。**

**要注意的：**

- **两个候选要来自同一个模型**——不然学到的是「模型 A 的风格」而不是「更好的回答」
- **偏好要一致**——不同标注者的标准要对齐，先算标注者间一致性，见 [[05-人工评估作为校准工具]]
- **别只标长度差异**——人偏好长答案，见 [[04-排行榜怎么读]]。数据里如果胜者系统性更长，模型学到的就是「说得多」

### 对齐税要盯住

偏好优化会带来副作用，见 [[08-预训练、后训练、对齐]]：

- **多样性下降**——输出趋同
- **校准变差**——模型变得更自信，包括对错误答案，见 [[05-logprobs 与置信度]]
- **可能在别的任务上退化**——见 [[06-灾难性遗忘]]

**所以偏好优化之后必须测这三样**，不能只测「偏好胜率提升了多少」。

### 什么时候值得做

| 场景 | 值得吗 |
| --- | --- |
| 有大量用户偏好信号 | **值得**——数据几乎免费 |
| 有客观验证器能自动构造偏好对 | **值得** |
| 任务有唯一正确答案 | 不必——SFT 更直接 |
| 只是想调格式 | 不必——约束解码更省 |
| 没有可靠的偏好数据来源 | 不值得——数据质量决定一切 |

**多数应用层场景其实用不上偏好优化。** 它的价值在「没有标准答案但有好坏之分」的开放式任务上。

## 动手做

- [ ] 判断你的任务有没有「好坏之分但无唯一答案」的特性
- [ ] 如果有验证器，试着自动构造一批偏好对（通过 vs 未通过）
- [ ] 检查偏好数据里胜者是不是系统性更长——是的话要重新平衡
- [ ] 用 DPO 跑通一次，$\beta$ 从 0.1 起扫
- [ ] 训完测三样：偏好胜率、输出多样性、置信度校准
- [ ] 同时测通用能力有没有退化

## 算学会了

- [ ] 能说出偏好优化和 SFT 的目标函数差别
- [ ] 知道 DPO 相对 RLHF 省掉了什么
- [ ] 会用验证器自动构造偏好对
- [ ] 检查过偏好数据的长度偏差
- [ ] 训完会测多样性和校准，不只看胜率

## 坑

**两个候选来自不同模型。** 学到的是风格差异不是质量差异。

**偏好数据里胜者系统性更长。** 模型学到「说得多就是好」。

**只看偏好胜率。** 多样性和校准的退化不会体现在这个指标里。

**没有可靠偏好来源就硬做。** 数据质量决定一切，糊弄的数据比不做更糟。

**为了调格式做偏好优化。** 约束解码几行代码就解决了。

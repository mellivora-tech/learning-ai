推理模型不会问你「这题要不要多想想」。它自己决定，而你只能给一个上限。

## 一句话

思考预算是你对推理模型**唯一的控制杆**；它该按请求价值动态给，而不是全局设一个数。

## 原理

### 你能控制的只有预算

推理模型把「怎么想」训进了权重里，见 [[08-预训练、后训练、对齐]]。你影响不了它的推理方式，能给的只有：

| 控制项 | 说明 |
| --- | --- |
| **思考 token 上限** | 最直接的一个 |
| 开 / 关思考 | 有些模型支持完全关掉 |
| 努力档位 | 有些提供低 / 中 / 高几档 |
| 超时 | 从时间维度间接约束 |

不同 provider 的接口不同，但语义都在这几项里。**注意这些是上限而非目标**——模型可能提前想完，也可能一直想到撞上限。

### 按请求价值分配

全局设一个固定预算是最省事也最浪费的做法。更好的是分档：

```python
def thinking_budget(req):
    if req.type in SIMPLE_TYPES:        # 分类、抽取、格式转换
        return 0                        # 直接关掉
    if req.stakes == "high":            # 涉及金额、不可逆操作
        return HIGH
    if req.retry_count > 0:             # 第一次没做对，加大预算
        return MEDIUM
    return LOW
```

**第三行那条很实用**：第一次用低预算试，失败了再加大重试。这是级联路由在思考预算上的应用，见 [[04-模型路由与级联]]。

### 那个隐形的账单

> [!warning] 200 个可见 token，账单上可能是三万
> 一次回答用户看到 200 个 token，而思考过程可能消耗一万到三万 token——**这些都计费，但不出现在输出里**。
>
> 五十倍到一百五十倍的差距。如果你的成本估算只按可见输出算，会低估一到两个数量级。
>
> 所以必须**单独统计思考 token**，并把它计入成本归因，见 [[04-成本归因与每次成功任务成本]]。

打点时至少要分开记：输入 token、思考 token、可见输出 token。**只记「输出 token」会把两者混在一起**，见 [[02-必打字段清单]]。

### 预算和延迟的关系

思考 token 也是一个个生成出来的，所以它直接加在延迟上：

$$
\text{总延迟} \approx \text{TTFT} + \text{TPOT} \times (\text{思考 token} + \text{可见 token})
$$

见 [[01-Prefill vs Decode]]。所以**思考预算基本等价于延迟预算**——给一万 token 的思考空间，就意味着用户可能要多等十几秒。

对交互式场景，这通常不可接受。折中做法：

- **先流式返回一个「正在思考」的状态**，见 [[04-流式与可中断 UX]]
- **给思考设一个较紧的上限**
- **或者干脆走非推理模型**，见 [[04-模型路由与级联]]

### 预算耗尽了怎么办

想到上限还没得出答案时，模型的行为因实现而异——有的会强行给一个答案，有的会截断。

工程上要：

- **检测这种情况**——通常能从 `finish_reason` 或思考 token 数看出来，见 [[03-截断处理与 finish_reason]]
- **别直接把半成品当答案用**
- **要么加大预算重试，要么降级，要么转人工**，见 [[04-降级链]]

**这类失败很容易被当成「模型能力不够」**，实际上只是预算给小了。

### 和 agent 预算的关系

思考预算是 agent 五类硬预算里 token 成本那一项的组成部分，见 [[01-五类硬预算]]。

多步 agent 里要特别注意：**每一步都可能触发思考**，二十步下来思考 token 会累积成很大一笔。所以：

- agent 的总预算要把思考 token 算进去
- 简单的步骤（比如格式化输出）应该关掉思考
- 只在真正需要推理的步骤上给预算

## 算学会了

- [ ] 知道自己能控制的只有预算，不是推理方式
- [ ] 思考 token 单独打点，成本估算不会低估一个数量级
- [ ] 按请求价值分档给预算，而不是全局一个数
- [ ] 能检测预算耗尽并正确处理
- [ ] agent 的总预算把思考 token 算进去了

## 坑

**成本只按可见输出算。** 会低估一到两个数量级。

**全局设一个固定预算。** 简单请求浪费，复杂请求不够。

**把思考 token 和输出 token 混在一起记。** 分不清钱花在哪。

**预算耗尽的半成品当答案用。** 而且会被误诊成模型能力问题。

**agent 里每一步都开思考。** 二十步累积下来是很大一笔。

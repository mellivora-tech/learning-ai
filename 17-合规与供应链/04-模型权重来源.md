从 HuggingFace 下一个模型，就是往你的生产环境里引入了一个几十 GB 的二进制依赖。它可能有许可证问题，也可能在加载时执行代码。

## 一句话

模型是依赖，要按依赖来管：**核对许可证、固定版本、校验哈希、用不执行代码的格式**。

## 原理

### 许可证：能不能商用

「开源模型」这个说法很有误导性——多数只开放权重，而且许可证限制各不相同，见 [[00-模型是怎么来的]]。

| 类型 | 商用 | 说明 |
| --- | --- | --- |
| Apache 2.0 / MIT | ✅ | 最宽松 |
| **CC-BY-NC** | ❌ | **非商业**，用在产品里有法律风险 |
| **社区许可证**（如 Llama 系） | ⚠️ | 有条件，比如用户量阈值、命名要求 |
| 自定义 | ⚠️ | 得逐条读 |

**必须实际打开许可证文件看**，不能只看 HuggingFace 页面上那个标签——标签有时和仓库里的 `LICENSE` 不一致。

**衍生物也受约束**：用某个模型做微调、做蒸馏，产出的新模型通常继承原许可证的限制，见 [[07-蒸馏]]。用一个禁止商用的模型蒸馏出小模型，小模型一样不能商用。

### 格式：pickle 能执行任意代码

模型权重的两种主流格式，安全性差别是本质的：

| 格式 | 机制 | 风险 |
| --- | --- | --- |
| **pickle**（`.bin`、`.pt`、`.ckpt`） | Python 序列化，**反序列化时会执行代码** | **加载即可能被攻陷** |
| **safetensors**（`.safetensors`） | **纯数据格式**，不含可执行内容 | 通过了独立安全审计，无严重的任意代码执行漏洞 |

**结论很简单：优先用 safetensors，尽量不加载来源不明的 pickle 文件。**

> [!danger] 扫描器本身也可能被绕过
> PickleScan 是检测恶意 pickle 的主要开源工具。2025 年 12 月披露了三个零日绕过漏洞（CVE-2025-10155 / 10156 / 10157，CVSS 4.0 均为 9.3）。
>
> 也就是说**「扫过了所以安全」这个推论不成立**。真正可靠的做法是用不允许执行代码的格式，而不是依赖扫描。

被投毒的开放权重模型在 OWASP 的分类里是 **LLM03:2025 供应链**——模型就是一个被攻陷的依赖，见 [[02-纵深防御]]。

### 完整性：下的是不是你以为的那个

| 措施 | 说明 |
| --- | --- |
| **固定版本** | 用 commit hash 或 revision，别用 `main` |
| **校验文件哈希** | 记下来，重新下载时比对 |
| **走内部镜像** | 下一次，之后都从内部仓库取 |
| 检查仓库信誉 | 官方组织账号 vs 个人转载 |

**「别用 main」是最重要的一条**。仓库随时可能更新，你的生产环境可能在某次重启后加载到一个不同的模型，而且没有任何提示——和 [[07-数据版本化]] 里说的问题同源。

**内部镜像还顺带解决了**：上游删库、限流、以及数据驻留要求，见 [[01-数据驻留]]。

### 加载时的隔离

即使做了以上，第一次加载新模型时仍值得隔离：

- 在**沙箱环境**里首次加载，见 [[10-沙箱化代码执行]]
- 观察有没有意外的网络连接或文件写入
- 确认之后再进生产镜像

**`trust_remote_code=True` 要特别警惕**——它会执行模型仓库里的 Python 代码。有些模型确实需要它，但那意味着你在运行一个陌生人写的脚本，必须先读过那些代码。

### 模型也要进 SBOM

把模型当依赖管理，意味着它应该出现在你的物料清单里：

```
model: Qwen/Qwen3-8B
revision: <commit sha>
license: Apache-2.0
format: safetensors
sha256: <权重文件哈希>
source: 内部镜像 / 上游 URL
first_loaded: 2026-07-15
```

**这份记录在两个时刻会救你**：许可证审计的时候，和上游爆出问题需要排查影响面的时候。

### 行为层面的风险

除了代码执行，模型本身的行为也可能有问题：

- **后门**——特定触发词下输出异常内容
- **偏见与不当输出**
- **能力与宣称不符**

**这些扫描工具查不出来**，只能靠评测：拿你自己的 golden set 和对抗测试集跑一遍，见 [[03-对抗测试集]]。换模型必须重跑全套评测，见 [[02-回归测试与 CI 门禁]]。

## 坑

**只看 HuggingFace 页面的许可证标签。** 有时和仓库里的 `LICENSE` 不一致。

**忘了衍生物继承限制。** 用禁止商用的模型蒸馏出的小模型，一样不能商用。

**依赖 pickle 扫描器。** PickleScan 自己有 CVSS 9.3 的绕过漏洞，用 safetensors 才是解法。

**用 `main` 作为版本。** 某次重启后加载到不同的模型，无提示。

**随手开 `trust_remote_code=True`。** 等于运行陌生人写的脚本。

**换模型不重跑评测。** 后门和行为异常扫描器查不出来，只有评测能发现。

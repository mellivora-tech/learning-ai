监管方问「三个月前这条建议是怎么给出来的」，你得能答上来。而 LLM 应用里这个问题特别难——因为同样的输入下次跑出来可能不一样。

## 一句话

审计日志要能**重建当时的决策依据**：不只是输入输出，还有检索到的片段、用了哪些工具、模型与提示词版本——而且这些记录本身要不可篡改。

## 原理

### 和可观测性不是一回事

两者经常共用一套埋点，但目的和要求完全不同，见 [[01-Trace 与 Span]]：

| | 可观测性 | 审计日志 |
| --- | --- | --- |
| 目的 | 排查问题、优化性能 | **证明当时发生了什么** |
| 保留期 | 几天到几周 | **几年**（按法规） |
| 采样 | 可以采样 | **不能采样**，关键操作必须全量 |
| 可变更 | 可以删、可以改 | **不可篡改** |
| 谁看 | 工程师 | 监管方、法务、客户 |

**「不能采样」和「不可篡改」是审计日志独有的**，直接影响存储方案的选择——不能和可观测性数据放同一个地方然后设个短保留期。

### 一条审计记录要有什么

| 字段 | 为什么 |
| --- | --- |
| **时间戳**（带时区） | 基本 |
| **主体**——谁发起的 | 用户 id、租户 id |
| **动作**——做了什么 | 尤其是不可逆操作 |
| **输入**（可脱敏） | 见 [[01-数据驻留]] |
| **输出** | 实际给出的结果 |
| **检索到的片段** | **决策依据的核心** |
| 调用的工具与参数 | agent 场景必须有，见 [[05-工具合约五段式模板]] |
| **模型 id 与版本** | 同样输入不同版本结果不同 |
| **提示词版本** | 见 [[07-数据版本化]] |
| 人工介入记录 | 谁确认的、改了什么，见 [[03-HITL 交互设计]] |
| trace id | 关联到技术侧的调用链 |

**「检索到的片段」是 LLM 应用特有且最关键的一项**。没有它，「模型为什么这么说」这个问题永远答不了——而这恰恰是监管方最常问的。

### 不确定性怎么记

LLM 的输出有随机性，这给审计带来一个传统系统没有的问题：**同样的输入重跑一次结果不同，怎么证明当时确实是这个输出？**

处理办法：

- **记录采样参数**（temperature、top_p、seed），见 [[04-采样参数]]
- **实际输出必须原样存下来**——不能靠「重跑一遍看看」
- 关键场景考虑 `temperature=0` + 固定 seed，提高可复现性

**中间那条是重点**：审计日志存的是**事实**（当时输出了什么），不是**可复现的过程**。这一点和传统系统不同，别指望重跑能还原。

### 不可篡改怎么做

由低到高：

| 手段 | 强度 |
| --- | --- |
| 只追加的存储 + 权限控制 | 基础 |
| **写入即计算 hash，链式串起来** | 中——改任一条后面全对不上 |
| 定期把 hash 存到外部 | 较高 |
| 第三方存证服务 | 最高，看行业要求 |

**第二档性价比最高**，实现起来也简单：每条记录带上一条的 hash，形成链。

### 查得出来才有用

存了但查不到等于没存。至少要支持：

- **按用户 / 租户查**——「这个客户的所有交互」
- **按时间范围查**
- **按 trace id 查**——从技术告警反查
- **按动作类型查**——「所有的付款操作」

**别把审计日志只存成压缩文件扔进对象存储**。真需要的时候（通常时间很紧）翻不出来。至少建这几个索引。

### 保留期与删除权的冲突

一个真实的矛盾：**法规要求保留几年，而 GDPR 给了用户删除权**，见 [[03-EU AI Act、GDPR、HIPAA]]。

常见解法：

- **审计日志里存的是脱敏后的引用，而不是原始个人数据**——删原始数据时审计链仍然完整
- 或者明确援引「法定保留义务」作为拒绝删除的依据（要法务确认）

**第一条更干净**：审计记录里存 `user_ref: u_8f3a...`，真实身份在另一张可删的表里。删除权行使时删那张表，审计链不断。

## 动手做

- [ ] 确认审计日志和可观测性数据是分开存的
- [ ] 逐条对照字段清单，补齐缺的（尤其是检索片段和模型版本）
- [ ] 确认输出是原样存下来的，不是靠重跑
- [ ] 实现 hash 链，验证改一条后面全对不上
- [ ] 建索引：按用户、按时间、按 trace id、按动作类型
- [ ] 实测一次「查三个月前某用户的某次交互」，计时
- [ ] 设计删除权与保留期的处理方式，让法务确认

## 算学会了

- [ ] 审计日志独立于可观测性，全量且不可篡改
- [ ] 记录里有检索片段和模型版本，能重建决策依据
- [ ] 能在几分钟内查出指定用户指定时间的记录
- [ ] hash 链能检测出篡改
- [ ] 删除权和保留期的冲突有明确处理方案

## 坑

**和可观测性共用一套并设短保留期。** 需要的时候已经被清了。

**审计日志采样。** 采样等于「大部分时候能证明」，在合规上没有意义。

**不记检索片段。** 「模型为什么这么说」永远答不了，而这是最常被问的。

**指望重跑还原输出。** LLM 有随机性，重跑不是证据。

**存了但没建索引。** 真要查的时候翻不出来，而那时候通常时间很紧。

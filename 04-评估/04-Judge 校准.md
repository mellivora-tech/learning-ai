拿一个模型去评另一个模型的输出，听起来循环论证，实际上是自由生成任务唯一可规模化的评估手段。前提是你得先评估这个裁判。

## 一句话

judge 本身是一个需要被评估的模型——先用人工标注测出它和人的一致性，达标了才能拿它的分数当依据。

## 原理

### 什么时候需要 judge

分类、抽取这类有标准答案的任务，直接比对就行，不需要 judge。需要它的是**没有唯一正确答案**的场景：回答质量好不好、摘要抓没抓住重点、语气合不合适、有没有编造。

这类任务人工评估最准，但一次几百条、每周跑一遍的成本谁也扛不住。judge 是唯一能规模化的替代，见 [[05-人工评估作为校准工具]]。

### 先测一致性，再用它

**这一步跳过了，后面所有分数都不可信。**

做法：人工标 100 条，同一批让 judge 也标，算两者的一致率。但**不要用裸的一致率**——如果 80% 的样本都是「好」，随便一个全判「好」的裁判也有 80% 一致率。

要用 **Cohen's κ**，它扣掉了随机猜对的部分：

$$
\kappa = \frac{p_o - p_e}{1 - p_e}
$$

$p_o$ 是实际一致率，$p_e$ 是按各自的标注分布随机能达到的一致率。

| κ | 一般怎么解读 |
| --- | --- |
| < 0.4 | 一致性差，这个 judge 不能用 |
| 0.4–0.6 | 中等，只能看趋势不能看绝对值 |
| 0.6–0.8 | 较好，可以用 |
| > 0.8 | 很好 |

κ 上不去的话，先改 judge 的提示词和评分标准，改不动就说明这个维度本身定义不清——**那是你的问题，不是模型的问题**。

### 三个让分数失真的偏差

**位置偏差。** 让 judge 比较 A 和 B 时，它系统性地偏好排在前面（或后面）的那个。

解法：**交换顺序各跑一次**，两次结论不一致的那些样本标成「平局」。这一步做完，很多看似显著的差距会消失。

**自我偏好。** 模型倾向于给自己（或同家族模型）的输出打高分。所以**别用同一个模型评自己**——用另一家的模型当裁判，或者至少换一个系列。

**长度与格式偏好。** 和人类投票榜一样，judge 也偏爱长的、分点的、语气笃定的输出，见 [[04-排行榜怎么读]]。评分标准里要显式写「长度不作为评分依据」，但别指望它完全消除。

### 打分不如比较

让 judge 给 1–10 分，你会得到一堆 7 和 8，区分度很差，而且不同批次之间的标准会漂。

**成对比较**稳得多：给它两个输出，问哪个更好。人类做这道题也更准，判断成本更低。

要得到排名的话，把两两比较的结果用 Bradley–Terry 聚合，和排行榜用的是同一套方法，见 [[04-排行榜怎么读]]。

如果非要绝对分数，那就**用带锚点的少档量表**：不是 1–10，而是三到五档，每档给具体的例子说明什么样算这一档。

### judge 提示词怎么写

几条能显著提升 κ 的做法：

- **一次只评一个维度**。事实准确性、完整性、语气各评一次，别糅成一个「质量分」
- **给评分标准和例子**，每档配一个真实样本
- **要求先给理由再给结论**，比直接输出分数一致性更高
- **明确写出不该考虑什么**：长度、格式、是否使用了专业术语
- **输出结构化**，方便解析和统计，见 [[01-结构化输出三档]]

### 成本要控制住

judge 会被跑很多次，模型选贵了 CI 会慢到没人愿意等，见 [[02-回归测试与 CI 门禁]]。

务实的做法：**用中档模型当 judge，用 κ 证明它够用。** 很多场景下小模型在单一明确维度上的一致性并不比大模型差多少，而成本差一个量级。

> [!warning] judge 的分数不能跨版本比
> 换了 judge 模型、改了评分提示词，历史分数就作废了——你不知道分数变化是被评的系统变了还是裁判变了。
> **judge 的模型和提示词要版本化，和 golden set 一起进 git。** 换裁判时要么重跑历史基线，要么明确标注断点。

## 动手做

- [ ] 人工标 100 条，同一批跑 judge，算 Cohen's κ
- [ ] κ 低于 0.6 就改提示词重来，记录每次改动带来的 κ 变化
- [ ] 做位置偏差测试：同一对输出交换顺序各评一次，统计结论翻转的比例
- [ ] 用同家族模型和不同家族模型各当一次裁判，对比它们给自家输出的分数
- [ ] 把绝对打分换成成对比较，看区分度是否提升
- [ ] 把 judge 的模型和提示词版本化进 git

## 算学会了

- [ ] 把 judge 当成一个需要被评估的模型，用它之前先测 κ
- [ ] 知道裸一致率为什么不够，能解释 κ 扣掉了什么
- [ ] 会做位置偏差测试，并把翻转的样本处理成平局
- [ ] 不用同一个模型评自己
- [ ] judge 的模型与提示词进了版本控制

## 坑

**直接用 judge 分数不做校准。** 最常见的错误。没有 κ 支撑的 judge 分数只是一串好看的数字。

**用裸一致率。** 类别不平衡时会给出严重虚高的结论。

**用被评模型自己当裁判。** 自我偏好会系统性抬高分数，而且抬得看不出来。

**追求细粒度打分。** 1–10 分的区分度还不如三档量表，且更不稳定。

**改了 judge 却继续和历史分数比。** 这会让你把裁判的变化当成系统的进步。

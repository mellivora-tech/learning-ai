人工评估最准，但也最贵最慢。所以它的定位不该是「日常怎么测」，而是「用什么来保证自动化的那套没跑偏」。

## 一句话

人工评估是**校准工具**，不是评估手段——它的产出不是分数，是「judge 和 golden set 还可不可信」这个判断。

## 原理

### 三层评估的分工

| 层 | 频率 | 成本 | 作用 |
| --- | --- | --- | --- |
| golden set 比对 | 每次提交 | 几乎为零 | 有标准答案的部分，挡回归 |
| judge 打分 | 每次提交 | 低 | 自由生成的部分，规模化 |
| **人工盲评** | 每周或每月 | 高 | **校准上面两层** |

这个结构的关键在最后一行：**人工评估的输出喂回给前两层，而不是直接用来做发布决策。**

为什么？因为人工评估慢到跟不上迭代速度。等你标完 200 条，代码已经改过五版了。它能做的是定期回答一个问题：**我一直在看的那些自动化分数，还对应真实质量吗？**

### 具体校准什么

**校准 judge。** 抽一批样本人工标，和 judge 的结论算 κ，看有没有漂移。judge 提示词没动、模型没换，κ 也可能因为**输入分布变化**而下降——业务变了，judge 见到的东西和当初校准时不一样了。具体做法见 [[04-Judge 校准]]。

**校准 golden set。** 检查两件事：

- 期望结果标得对不对（早期标注常有错，尤其是边界情况）
- 分布还代表不代表现在的真实流量

第二条更容易被忽略。半年前抽的样本，业务转型之后可能测的全是没人用的路径了。

**发现盲区。** 自动化只测你想到要测的维度。人看会发现别的：语气变生硬了、开始频繁道歉、中英文夹杂、输出越来越长。**这些不在任何指标里，但用户感知得到。**

### 盲评：必须的

评估自己的系统时，人的偏见极强。看到「这是新版本的输出」，评价自然就高了。

所以必须**盲**：

- 隐去哪个是新版、哪个是旧版
- 随机打乱顺序（同时对抗位置偏差，人和模型都有这个毛病）
- 最好让没参与这次改动的人来评

**成对比较优于打分**，理由和 judge 那边一样：人做「A 和 B 哪个好」比做「这个打几分」更准也更快。

### 一个够用的流程

1. **抽样 50–100 条**，分层：高频路径、已知难点、最近改动影响到的区域
2. **两个版本各跑一遍**，输出去标识、打乱顺序
3. **两个人独立评**，只做成对比较
4. **算两人之间的一致性**——人和人对不上的话，说明评价标准本身没定义清楚，这比结论更值得关注
5. **和 judge 的结论对比**，算 κ
6. **产出三件事**：judge 还能不能用、golden set 要不要补要不要改、有没有指标之外的问题

第 4 步经常被跳过，但它最有信息量。**两个懂业务的人对同一个输出打分打不到一起去，那这个维度就不该被自动化评估。**

### 频率怎么定

不需要很勤。判断标准是「上次校准之后，有没有发生可能让自动化失准的事」：

- 换了模型或 provider
- 业务形态或用户群变了
- judge 的提示词改了
- 线上投诉的类型出现新的模式
- 距离上次超过一个季度

平稳期一个月一次够了，大改动前后各做一次。

> [!warning] 别让人工评估变成发布流程的一环
> 一旦「上线前必须人工评 200 条」写进流程，两件事一定会发生：发布变慢，然后人开始糊弄——匆匆扫一眼全打「差不多」。
> 人工评估要**离线做、定期做、和发布解耦**。挡发布是 CI 门禁的事，见 [[02-回归测试与 CI 门禁]]。

### 它和用户信号的关系

人工评估是主动抽样，用户信号（点赞、重试、放弃、复制）是被动收集。后者量大、免费、更贴近真实偏好，但噪声也大。

务实的组合：**用用户信号找出问题集中的区域，再拿人工评估去那些区域精查。** 信号的收集与利用见 [[06-用户信号如何变成 eval 与训练数据]]。

## 动手做

- [ ] 设计一个盲评表单：隐去版本、随机顺序、只做成对比较
- [ ] 抽 50 条，找两个人独立评，先算**人和人**的一致性
- [ ] 一致性低的那些维度，把评分标准写清楚重来一次
- [ ] 把同一批交给 judge，算 κ，判断 judge 还能不能用
- [ ] 从盲评里找出至少一个自动化指标没覆盖的问题，补进 golden set
- [ ] 定一个校准触发清单（换模型、改 judge、业务变化、满一季度）

## 算学会了

- [ ] 把人工评估当校准工具，不当日常评估手段
- [ ] 盲评是默认做法，不是可选项
- [ ] 会先算人和人的一致性，再谈人和模型的一致性
- [ ] 每次校准都产出「judge 还能不能用」这个明确结论
- [ ] 人工评估和发布流程是解耦的

## 坑

**拿人工评估当发布门禁。** 会让发布变慢，然后评估质量下降到没有意义。

**不盲评。** 知道哪个是新版本之后，评价基本不可信。

**只算人和模型的一致性。** 人和人对不上的时候，这个数字没有意义。

**样本随便抽。** 全是简单样本的话，judge 和人都能评对，校准不出任何东西。要刻意包含难点。

**评完不产出行动。** 校准的价值在于结论——judge 要不要换、golden set 要不要改。只留一个分数等于白做。

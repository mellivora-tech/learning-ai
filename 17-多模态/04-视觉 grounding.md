模型说「发票金额是 1250 元」——它是从图上读出来的，还是编的？grounding 就是让它同时给出「我是从这个位置读到的」。

## 一句话

要求模型返回**每个结论对应的坐标框**，把无法核对的断言变成可以核对的断言——这是视觉任务里对抗幻觉最有效的手段。

## 原理

### 为什么视觉任务特别需要这个

文本任务里，模型引用的原文你能一眼比对。视觉任务里不行：

- 用户不会逐字核对一张扫描件
- 模型编出的值往往**格式完全正确**（金额就是金额的样子）
- 错误不会报错，只是悄悄错了

**所以「让模型指出位置」不是锦上添花，是把不可验证变成可验证。**

### 怎么要它

在结构化输出的 schema 里带上坐标，见 [[01-结构化输出三档]]：

```json
{
  "fields": [
    {
      "name": "总金额",
      "value": "1250.00",
      "bbox": [0.62, 0.81, 0.78, 0.85],
      "page": 2
    }
  ]
}
```

坐标用**归一化的比例**（0 到 1）比用像素稳——不用告诉模型原图尺寸，也不受缩放影响，见 [[01-图像与音频的 token 计算]]。

### 坐标准不准

这是最需要实测的一点。不同模型的定位能力差别巨大：

- 有些模型能给出相当准的框
- 有些给出的框大致对但边界很粗
- 有些**完全是编的**——框和内容对不上

**必须实测**：拿一批标注好的样本，算 IoU（框的重叠度）。如果模型的框基本不对，那这个字段就别要了——一个错误的坐标比没有坐标更糟，它让人误以为核对过了。

### 有坐标之后能做什么

| 用途 | 说明 |
| --- | --- |
| **人工复核** | 点字段跳到原图高亮，复核成本大幅下降，见 [[03-HITL 交互设计]] |
| **交叉校验** | 用传统 OCR 读那个框里的文字，和模型给的值比对 |
| **置信度信号** | 框给不出来或明显不合理 → 这个字段不可信 |
| **自动检测幻觉** | 框在空白处 → 大概率是编的 |

**第二条是最有价值的**：模型给位置、OCR 给字符，两者一致才采信。这是一个近乎免费的验证器，见 [[06-四层参数校验]]。

不一致的处理：

- 差别很小（比如空格）→ 采信
- 差别明显 → 标为低置信，转人工，见 [[03-升级到人与结构化中间状态]]

### 别对坐标要求过高

现实一点：

- **大致框对了就够用**——目的是让人能找到位置，不是像素级精确
- 表格里的单元格定位通常比自由版面准
- 手写和低质量扫描件上定位会明显变差

**如果你的场景需要像素级精确，那需要的是专门的检测模型，不是通用视觉大模型。**

### 评估怎么做

除了字段值的准确率，加两项，见 [[01-Golden set]]：

- **定位准确率**——框和标注的 IoU 超过阈值的比例
- **交叉校验一致率**——模型值和框内 OCR 一致的比例

**第二项特别有用**：它不需要人工标注坐标，用现成的 OCR 就能自动跑，可以放进 CI，见 [[02-回归测试与 CI 门禁]]。

## 坑

**假设模型给的坐标是对的。** 有些模型完全是编的，必须实测 IoU。

**用像素坐标。** 受缩放影响，归一化比例更稳。

**要求像素级精确。** 通用视觉模型做不到，需要专门的检测模型。

**有坐标但不用来校验。** 交叉校验是近乎免费的验证器，不用就浪费了。

**错误的坐标比没有更糟。** 它让人误以为核对过了。

「用多模态模型直接读文档」和「用传统 OCR 抽文字」这两条路，2026 年的生产系统给出的答案是：都用。

## 一句话

**便宜快的 OCR 处理大多数文档，视觉模型只处理它搞不定的那部分**——这样能拿到 OCR 的成本和视觉模型的准确率。

## 原理

### 两条路各自的问题

| | 传统 OCR | 多模态模型 |
| --- | --- | --- |
| 成本 | 很低 | **高**（几千视觉 token 一页） |
| 速度 | 快 | 慢 |
| 印刷体规整版面 | **很好** | 好 |
| 复杂版面、表格、手写 | **差** | **好** |
| 理解语义、抽字段 | **不会**（只出文字） | **会** |
| 幻觉 | 不会（只会认错字） | **会**（可能编出没有的字段） |

**最后一行是最关键的差异**：OCR 错了是认错字，多模态模型错了可能是凭空编一个看起来很合理的值，见 [[06-四层参数校验]]。

### 生产管道长什么样

![[OCR 与视觉模型混合管道.excalidraw.md|700]]

混合管道的设计目标是：**让绝大多数文档走便宜的那条路，只把视觉模型花在它真正能赢的那一小撮上**。省下多少取决于你的文档里「规整版面」占比多高——这个比例得自己统计，不同业务能差出好几倍。

具体来说：

1. **先跑传统 OCR**——快、便宜
2. **判断质量**——置信度低？版面复杂？关键字段缺失？
3. **够好的**：把文字送 LLM 抽字段、出结构化结果，见 [[01-结构化输出三档]]
4. **不够的**：回落到多模态模型直接看图

### 质量判据怎么定

第 2 步的判据决定整个管道的经济性，几个可用的信号：

| 信号 | 说明 |
| --- | --- |
| **OCR 置信度** | 多数引擎会给，低于阈值就回落 |
| **版面复杂度** | 检测到表格、多栏、手写就直接走视觉 |
| **关键字段缺失** | 抽完发现必填字段没有，回落重来 |
| **校验失败** | 金额对不上、日期格式不对，见 [[06-四层参数校验]] |
| 文档类型 | 已知某类文档 OCR 一直不行，直接走视觉 |

**第三、四条是最实用的**——它们不依赖 OCR 引擎的自我评估（那个经常过于乐观），而是用下游的结果来判断。

### 版面信息不能丢

纯文字流会丢掉版面结构，而版面往往就是语义：

- 表格的行列关系
- 标题的层级
- 「这个数字属于哪一列」

所以 OCR 那一路要保留**位置信息**（每段文字的坐标框），送给 LLM 时用某种方式表达出来（比如 Markdown 表格，或者带坐标的结构）。

**只送纯文字流是这条路最常见的失败原因**——LLM 拿到一堆没有结构的字，表格全乱。

### 结果要能追溯

不管走哪一路，每个抽出来的字段最好能指回原文档的位置：

- 页码
- 坐标框
- 原始文本片段

**这是人工复核的前提**，见 [[03-HITL 交互设计]]。用户看到一个金额，要能一键跳到原文档上高亮那个位置——没有这个能力，复核的成本会高到没人愿意做。

这和 RAG 里的引用是同一个道理，见 [[06-幽灵文档测试]]。

### 怎么评估

OCR 管道的 eval 要分层，见 [[01-Golden set]]：

- **字符级准确率**——OCR 那一层
- **字段级准确率**——抽取那一层，这个更重要
- **回落率**——多少文档走了昂贵路径，直接对应成本
- **成本与延迟**——每份文档的实际开销

**字段级准确率要按字段分开看**：整体 95% 可能掩盖了「金额字段只有 70%」这种致命问题，而金额恰恰是最不能错的。

## 动手做

- [ ] 拿一批真实文档，分别跑纯 OCR 和纯视觉模型，对比准确率和成本
- [ ] 找出 OCR 搞不定的文档类型，统计占比
- [ ] 实现质量判据，先用「关键字段缺失」这一条
- [ ] 测混合管道的实际回落率和综合成本
- [ ] 确认 OCR 那一路保留了位置信息，且送给 LLM 时表达出来了
- [ ] 给每个抽出的字段加上页码和坐标，实现点击跳转
- [ ] 按字段分开统计准确率，找出最差的那个

## 算学会了

- [ ] 管道是混合的，不是纯 OCR 或纯视觉
- [ ] 有明确的回落判据，且基于下游结果而非 OCR 自评
- [ ] OCR 那一路保留了版面和位置信息
- [ ] 每个字段可追溯到原文档位置
- [ ] 按字段分开评估准确率，知道最差的是哪个

## 坑

**二选一。** 纯 OCR 在复杂版面上不行，纯视觉对全量文档太贵。

**只送纯文字流给 LLM。** 丢了版面结构，表格全乱。

**只看 OCR 引擎的置信度。** 它经常过于乐观，用下游校验结果更可靠。

**不保留位置信息。** 人工复核成本高到没人做。

**只看整体准确率。** 会掩盖「金额字段只有 70%」这种致命问题。

**忘了视觉模型会幻觉。** 它可能编出一个格式完全正确但不存在的字段值。

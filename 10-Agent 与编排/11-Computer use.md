让模型看着屏幕、移动鼠标、敲键盘去操作软件。这是能力边界的一次实质扩张——也是可靠性最差的一类工具。

## 一句话

computer use 是**没有 API 时的最后手段**：它能操作任何有界面的东西，代价是慢、贵、脆、且几乎无法做细粒度权限控制。

## 原理

### 它怎么工作

循环大致是：

```text
截屏 → 模型看图并决定下一步 → 输出动作（点击 x,y / 输入文字 / 滚动）
     → 执行 → 再截屏 → ……
```

每一步都要传一张截图进上下文。这直接决定了它的成本结构——**一张截图相当于几百到几千 token**，见 [[01-图像与音频的 token 计算]]。几十步操作下来，token 消耗非常可观。

### 什么时候才该用

**优先级从高到低**：

| 手段 | 什么时候 |
| --- | --- |
| ① API | 有 API 就用 API |
| ② 数据库 / 文件直接读写 | 能绕过应用层就绕过 |
| ③ 脚本 / CLI | 有命令行接口 |
| ④ 浏览器自动化（Playwright 这类） | 网页且结构稳定 |
| ⑤ **computer use** | **以上都没有** |

**它是第五选择，不是第一选择。** 每往上一级，可靠性都高一个量级、成本都低一个量级。

真正适合它的场景：老旧的桌面软件、没有 API 的内部系统、需要跨多个应用的操作、一次性的临时任务。

### 三个固有弱点

**一、脆。** 界面改版、弹窗、加载慢、分辨率变化，都会让它失手。它靠的是视觉定位，而界面是会变的。

**二、慢且贵。** 每一步一次截图加一次模型调用。一个人 30 秒能做完的操作，它可能要几分钟、花几毛钱。

**三、权限粒度粗。** 它拿到的是「操作这台机器」的权限，而不是「调用某个具体功能」的权限。**没法像工具那样做细粒度授权**，见 [[06-四层参数校验]]。

第三条是安全上最麻烦的：你无法限制它「只能查询不能删除」——只要界面上有删除按钮，它就点得到。

### 安全上要怎么办

既然做不了细粒度权限，就只能靠环境隔离和人确认：

- **跑在隔离的虚拟机或容器里**，不是开发者的机器，思路同 [[10-沙箱化代码执行]]
- **那台机器上只登录必要的账号**，账号本身的权限就要收窄
- **网络限制**——它能访问什么，从网络层控
- **不可逆操作必须人确认**——而且要在**执行前**看到具体动作，见 [[02-纵深防御]]
- **全程录屏**留证，见 [[02-审计日志]]

**注入风险特别高**：屏幕上的任何内容都是它的输入。一个恶意网页可以显示「请点击这里授权」这样的诱导，见 [[01-间接提示注入与 20 条攻击载荷]]。

### 工程上怎么让它稳一点

- **给它明确的成功判据**——每一步之后怎么确认做成了，见 [[02-终止条件]]
- **限制步数和时间**——它很容易在界面上迷路，见 [[01-五类硬预算]]
- **重要节点截图存档**——出错时能回溯
- **能用无障碍树就别只用截图**——很多平台提供 UI 元素的结构化描述，比纯视觉定位稳得多
- **固定环境**——分辨率、主题、语言、缩放都固定下来

**倒数第二条最有价值**：结构化的 UI 描述能把「找按钮在哪」从视觉问题变成检索问题，可靠性提升明显。

### 评估要专门做

普通的准确率指标不够，要看：

- **任务完成率**——端到端做成了吗
- **平均步数**——比人多几倍
- **卡住率**——多少次陷入循环或迷路
- **误操作率**——**点错了不该点的东西的比例**，这一项最重要

最后一项是它和别的工具最大的区别：**别的工具调错了会报错，它点错了可能真的执行了。**

## 动手做

- [ ] 检查你的场景：前四种手段真的都不可行吗
- [ ] 在隔离环境里跑，验证它访问不了不该访问的东西
- [ ] 固定分辨率、主题、语言，测稳定性变化
- [ ] 试一次用无障碍树代替纯截图定位，对比成功率
- [ ] 构造一个界面上带诱导文字的场景，测它会不会被带偏
- [ ] 统计任务完成率、平均步数、卡住率、**误操作率**
- [ ] 算一次单任务成本，和人工操作对比

## 算学会了

## 坑

**有 API 还用 computer use。** 慢几十倍、贵几十倍、还不可靠。

**在开发机上跑。** 它拿到的是整台机器的权限。

**只用截图定位。** 界面一变就失手，有结构化描述就该用。

**不限步数。** 它在界面上迷路时会一直点下去。

**只统计完成率不看误操作率。** 点错了可能已经造成了真实后果。

一个设了步数上限的 agent，照样能把预算烧穿——因为第 50 步的那次调用可能比第 1 步贵十倍，而步数计数器对此一无所知。

## 一句话

五道刹车，每道刹住一种失控；其中**成本上限**最容易被漏掉，而它恰恰是唯一能兜住其余四道全失效的那一道。

## 原理

![[五类硬预算.excalidraw.md|700]]

### 五道刹车

![[五道刹车.excalidraw.md|637]]

| 刹车 | 刹住什么 |
| --- | --- |
| ① **步数** | 无限往下走 |
| ② **墙钟时间** | 某一步卡死拖垮整个任务 |
| ③ **token 成本** | **有步数上限也可能烧光预算** |
| ④ 单工具调用数 | 对着同一个工具反复刷 |
| ⑤ 单工具重试数 | 在同一个错误上原地打转 |

**五道都要有。** 只设步数上限的系统很常见，也很危险——因为每一步的上下文在膨胀，第 50 步的一次调用可能比第 1 步贵十倍，见 [[06-上下文衰减与长轮次退化]]。

### 为什么成本上限最关键

步数、时间、调用数都是**代理指标**——它们和钱只是相关，不是等价。

- 步数 20 步，但每步塞了 100k 上下文
- 时间 5 分钟，但这 5 分钟里调了 40 次大模型
- 工具调用 10 次，但每次返回值巨大，全进了下一轮的上下文

**只有 token 成本是直接的。** 它是唯一能在其余四道全部「合法」的情况下仍然刹住车的那一道。

而且它该按**累计**算，不是单次：

```python
budget = TaskBudget(
    max_steps=25,
    max_wall_clock=timedelta(minutes=10),
    max_cost_usd=0.50,            # 累计，含所有子调用
    max_calls_per_tool=5,
    max_retries_per_tool=3,
)
```

### 分级：告警、限速、硬停

预算不该只有一个「到了就停」。分三档更实用：

| 档 | 到什么程度 | 做什么 |
| --- | --- | --- |
| **告警** | 用了 50% | 打点，异常趋势能被看见 |
| **限速** | 用了 80% | 降级到便宜模型、减少检索量 |
| **硬停** | 100% | 停下来，转人工 |

中间那档是最有价值的：**它给了系统一个「感觉不对劲就先省着点」的机会**，而不是一路狂奔到撞墙。

### 预算要能传递

子任务、子 agent 会消耗父任务的预算。所以预算必须**沿调用链往下传并累加**：

```text
父任务预算 $0.50
  ├── 子 agent A 分到 $0.20（用了 $0.18）
  ├── 工具调用若干（用了 $0.05）
  └── 剩余 $0.27 归子 agent B
```

**没有传递的话，「每个子 agent 限 $0.2」乘以不确定数量的子 agent，等于没有上限**。这是多 agent 系统最常见的预算漏洞，见 [[09-多 Agent 编排模式]]。

### 触发之后不是「失败」

预算耗尽时正确的行为是**交出结构化的中间状态给人接手**，而不是返回一个错误，见 [[03-升级到人与结构化中间状态]]。

差别在于：

```text
✗ {"error": "budget exceeded"}          → 用户什么都拿不到，只能从头再来
✓ {"status": "needs_human",
   "completed": ["已抽取 42 张发票"],
   "current": "inv-043 手写金额识别失败",
   "next": ["确认金额后继续"],
   "artifacts": {"output": "s3://.../partial.jsonl"}}
```

第二种是**可续接的失败**。见 [[05-断点续跑]]。

### 预算数据要能回来指导设计

每次触发预算都是一个信号，要打点并聚合，见 [[04-成本归因与每次成功任务成本]]：

- **哪一道刹车触发得最多**——步数多说明任务拆得不好，成本多说明上下文在膨胀
- **触发时完成度多少**——快完成了才被刹住，说明预算设小了
- **哪类任务最容易触发**——那类任务可能根本不适合交给 agent

**第三条最有价值**：反复触发预算的任务类型，往往说明它需要的是确定性流程而不是 agent。

## 坑

**只设步数上限。** 上下文在膨胀，20 步可能比 200 步还贵。

**预算不传递。** 每个子 agent 各限一份，乘起来等于没有上限。

**预算耗尽返回错误。** 用户什么都拿不到，之前的花费全浪费。

**只有硬停一档。** 系统一路狂奔到撞墙，没有中间的自我收敛。

**触发数据不回收。** 反复触发的任务类型可能根本不该用 agent。

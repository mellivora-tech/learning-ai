降级路径平时不走，出事才走。而出事的时候你不知道它还能不能用——因为从来没人测过。

## 一句话

没测过的降级路径等于没有；验证方法是**主动杀掉依赖**，看系统实际走到哪一级、输出成什么样、告警响没响。

## 原理

![[LLM 要多注入的两类故障.excalidraw.md|700]]

### 该杀哪些

按对 agent 的影响排：

| 杀什么 | 预期行为 |
| --- | --- |
| **检索服务** | 明确声明未使用知识库，**不是凭记忆编**，见 [[04-降级链]] |
| **某个工具** | 告知模型该工具不可用，让它换路子或转人工 |
| **主模型 provider** | 切备用 provider，**且 prompt 与 schema 已验证兼容** |
| 记忆服务 | 退化成无记忆模式，明确告知 |
| 数据库 | 只读降级或拒绝写操作 |
| 全部工具 | 转纯对话模式或直接转人工 |

**每一行的「预期行为」要先写下来，再去测。** 否则测完只会得到「它没崩」这种没信息量的结论。

### 备用 provider 必须验证过

> [!warning] 「假设兼容」是最常见的翻车点
> 配了备用 provider，以为切过去就能用。实际上：
> - **工具调用格式不同**——参数 schema 的表达方式各家有差异
> - **system prompt 的处理不同**——有的 provider 对长 system prompt 有特殊行为
> - **停止符不同**——见 [[02-开源权重包里有什么]]
> - **结构化输出支持程度不同**——严格模式不是每家都有，见 [[01-结构化输出三档]]
> - **上下文长度不同**——主模型能塞进去的，备用可能塞不下
>
> **备用 provider 上的 prompt 和 schema 必须跑过完整 eval**，而不是「应该差不多」，见 [[02-回归测试与 CI 门禁]]。

一个务实的做法：把备用 provider 也接进 CI，每次改 prompt 时两边都跑。这样切换时才有底。

### 怎么做混沌测试

**从测试环境开始，逐步往生产走**：

1. **测试环境全量杀**——每个依赖轮流杀一遍，记录实际行为
2. **对比预期**——和事先写下的预期行为逐项对照
3. **生产环境小流量**——把 1% 流量的某个依赖指向一个会失败的桩
4. **观察真实指标**——告警响了吗、用户侧表现如何、成本怎么变

第 3 步很多团队不敢做，但它是唯一能验证「生产配置真的对」的方式。**测试环境的配置和生产总有差异**，而降级路径恰恰最容易在那些差异上出问题。

### 要检查的不只是「没崩」

每次演练至少记这五项：

| 检查项 | 为什么 |
| --- | --- |
| 实际走到了第几级 | 可能跳级了，或者根本没触发 |
| 用户看到了什么 | 有没有明确告知降级，见 [[06-降级 UX]] |
| **告警响了吗** | 最容易漏的一项 |
| 成本怎么变 | 降级可能更贵（换了大模型、拆了多次请求） |
| 恢复之后能不能自动回到主路径 | 熔断器半开逻辑，见 [[07-韧性组件]] |

**第三项和第五项最常被漏。** 告警没响意味着线上真出事时没人知道；不能自动恢复意味着故障过去了系统还在降级模式跑。

### agent 场景特有的两点

**一、部分失败比全部失败更麻烦。** 工具 A 挂了但工具 B 正常时，agent 可能会反复尝试 A、绕圈子。这时候要靠无进展检测兜住，见 [[02-终止条件]]。

所以测试时不要只测「全挂」，更要测「挂一半」。

**二、降级会改变 agent 的行为路径。** 检索挂了之后，agent 可能改用别的工具、多问几轮、或者干脆放弃——**这条新路径的成本和风险都没被测过**。

所以混沌测试要同时观察：降级后 agent 的步数、成本、是否触发了别的预算，见 [[01-五类硬预算]]。

### 演练要成为例行

一次性的演练价值有限，因为系统在变。做法：

- **每次大改动后跑一遍**核心依赖的杀测
- **定期例行**（比如每月）跑全量
- **把演练脚本化**，让它能在 CI 里跑

**演练结果要归档**，这样能看出「上次能降级、这次不能了」这种退化。

## 坑

**假设备用 provider 兼容。** 工具格式、停止符、结构化输出支持都可能不同。

**只测「全挂」。** 部分失败会让 agent 绕圈子，更难处理。

**不检查告警。** 降级正常但没人知道，等于线上出事时你是瞎的。

**不测恢复。** 故障过去了系统还在降级模式跑，用户一直拿着更差的结果。

**只在测试环境测。** 生产配置的差异恰恰最容易出问题。

agent 跑了八分钟，做了七成，然后返回一句「处理失败」。人接手时只能从零开始——那八分钟和那笔钱全白花了。

## 一句话

失败要**可续接**：交出结构化的中间状态，人能从断点接着做，而不是重来一遍。

## 原理

### 三种触发

| 触发 | 该给人什么提示 |
| --- | --- |
| 预算耗尽 | 「做到了 Y，还剩 Z」，见 [[01-五类硬预算]] |
| 无进展 / 振荡 | 「反复在做 X 但没效果」，见 [[02-终止条件]] |
| 高危操作待确认 | 「准备做 W，请确认」，见 [[02-纵深防御]] |

**三种的语气和内容都不同。** 混成一个「需要人工介入」的通用错误，人接手时得自己重新调查。

### 交出去的东西长什么样

```json
{
  "status": "needs_human",
  "reason": "budget_exceeded",
  "progress": {
    "completed": 42,
    "total": 87,
    "artifacts": {"partial_output": "s3://bucket/run-8821/partial.jsonl"}
  },
  "current_blocker": {
    "item": "inv-043",
    "what_happened": "手写金额识别失败，OCR 置信度 0.31",
    "tried": ["提高图像对比度重试", "换用 vision 模型", "尝试从备注栏推断"]
  },
  "suggested_next": [
    "人工确认 inv-043 的金额后，从第 43 条继续",
    "或者跳过这条，标记为 needs_review"
  ],
  "resume_token": "run-8821:item-43"
}
```

五个部分，缺一不可：

**① 状态与原因**——为什么停的，机器可读。

**② 进度与产物**——已经做完的部分在哪。**这是省钱的关键**，那 42 条不用重做。

**③ 当前阻塞点**——卡在哪、发生了什么、**试过什么**。第三项最有价值：人不用把 agent 试过的路再走一遍。

**④ 建议的下一步**——给人选项，而不是让人从头想。

**⑤ 续跑令牌**——人处理完之后，系统能从这儿接上，见 [[05-断点续跑]]。

### 「试过什么」这一项最容易漏

人接手时第一个问题永远是「它试过什么了」。没有这一项的话，人会重复 agent 已经试过的所有路径——**而 agent 往往在那些路径上花了大部分预算**。

记录格式要具体：不是「尝试了多种方法」，而是「用 X 参数调了 Y 工具，返回 Z」。

### 续跑要真的能续

交出中间状态只是一半，另一半是人处理完之后能接回去：

1. 人补充了缺失的信息（比如确认了那个金额）
2. 系统用 `resume_token` 恢复上下文和进度
3. **从第 43 条继续，而不是从第 1 条**

这要求整条链路是可续跑的，见 [[05-断点续跑]] 和 [[02-状态机]]。**没有那套基础设施的话，「升级到人」就只能是「重新开始」的委婉说法。**

### 人在环上，不在环里

一个实用的划分：

- **人在环里**（human-in-the-loop）——每一步都要人确认。安全但慢，agent 的价值大打折扣
- **人在环上**（human-on-the-loop）——agent 自主跑，人监督并在关键点介入

**多数场景该用后者**：agent 处理量，人守住不可逆的那道门。判据很清楚——**凡是不可逆的操作，必须人批准**，见 [[02-纵深防御]]。

可逆和不可逆的区分要在工具合约里写明，见 [[05-工具合约五段式模板]]。

### 升级的质量要能被衡量

几个值得看的指标：

- **升级率**——太高说明 agent 能力不匹配任务，太低可能说明它在硬撑
- **人接手后的完成率**——低的话说明交出去的状态不够用
- **接手耗时**——长说明信息不足，人在重新调查
- **重复升级率**——同一类问题反复升级，说明该改流程而不是靠人兜

第二和第三项直接检验中间状态的质量。**接手耗时长，就是「试过什么」那一项没写好的信号。**

## 算学会了

- [ ] 失败是可续接的，不是从头再来
- [ ] 交出的状态包含「试过什么」，人不用重走一遍
- [ ] 三种触发给出的提示不同
- [ ] 采用「人在环上」而非「人在环里」，不可逆操作必须人批准
- [ ] 用接手耗时反向检验中间状态的质量

## 坑

**返回一个笼统的错误。** 之前的工作全废，人从零开始。

**不记录「试过什么」。** 人会把 agent 试过的路再走一遍。

**交了状态但接不回去。** 「升级到人」变成「重新开始」的委婉说法。

**每一步都要人确认。** agent 的价值被抹平，人也会疲劳到随手点通过。

**升级率高就想着调提示词。** 可能是这类任务本来就不该交给 agent。

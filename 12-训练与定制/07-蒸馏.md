用大模型标数据，训一个小模型去顶替它。这条路能把成本砍一个数量级——只要你的任务足够窄。

## 一句话

蒸馏是**用大模型的输出当训练数据**去教小模型；它的边界很清晰——**任务一变宽，小模型立刻塌**。

## 原理

### 基本做法

```text
① 收集真实输入（线上流量，不要编）
② 用大模型（teacher）生成输出
③ 人工抽检修正
④ 用这批数据 SFT 一个小模型（student）
⑤ 和 teacher 对比评估
```

**第 ③ 步最容易被跳过**，但它决定上限——teacher 的错误会被 student 完整继承，而且学得很牢。

### 为什么值得做

一个 7B 模型顶替一个大模型，收益是复合的：

| 维度 | 改善 |
| --- | --- |
| 单次成本 | 低一个数量级，见 [[06-硬件要多少钱]] |
| 延迟 | decode 速度和模型大小成反比，见 [[01-一张卡的四个关键数字]] |
| 部署 | 单卡就能跑，可私有化 |
| 并发 | 显存占用小，KV cache 空间大，见 [[03-KV cache 管理与显存测算]] |

**对高频、窄任务的场景，这是最有效的降本手段。**

### 那条边界

> [!warning] 任务一变宽，小模型立刻塌
> 这是蒸馏最重要的一条边界。小模型能在**训练时覆盖到的任务分布**上打平大模型，但泛化能力差得多。
>
> 具体表现：
> - 换一种问法就不行了
> - 边缘情况处理明显更差
> - 需要多步推理的部分退化最严重
> - 遇到没见过的格式直接乱来
>
> **所以蒸馏适合「输入分布稳定、任务定义清晰」的场景**，不适合开放式对话或者需求经常变的功能。

### 数据要覆盖真实分布

student 的能力边界就是训练数据的边界，所以数据的**分布**比数量更重要：

- **输入必须来自真实流量**——编的输入会系统性避开脏数据，见 [[01-Golden set]]
- **要覆盖长尾**——按频率抽样会让边缘情况严重不足，要刻意补
- **要包含失败样本**——teacher 也答不好的那些，student 至少要学会不乱答
- **要有拒答样本**——见 [[02-SFT 数据构造]]

**第二条最容易出问题**：线上流量的分布是长尾的，随机抽 5000 条可能 90% 都是同一类简单请求，训出来的 student 在那 10% 上完全不行。

### 蒸软标签还是硬标签

| | 硬标签（只用输出文本） | 软标签（用 logits 分布） |
| --- | --- | --- |
| 实现 | 简单，就是 SFT | 复杂，要拿到 teacher 的完整分布 |
| 信息量 | 只有「答案是什么」 | 还有「其他选项有多可能」 |
| 效果 | 基准 | 通常更好 |
| 可行性 | 闭源 API 也能做 | **需要能访问 teacher 的 logits** |

**用闭源 API 当 teacher 时只能用硬标签。** 自建 teacher 的话可以试软标签，收益通常明显。

### 许可证是硬约束

> [!danger] 用别家模型的输出训自己的模型，可能违反条款
> 很多模型的服务条款明确禁止用其输出训练竞争性模型。开源权重模型的许可证也各不相同。
>
> **动手之前先读条款**，见 [[04-模型权重来源]]。这是唯一一个会带来法务后果的环节。

### 评估要和 teacher 对比

蒸馏的成功判据不是「student 的绝对分数」，而是**「相对 teacher 差多少，成本省多少」**：

| 指标 | 说明 |
| --- | --- |
| 任务准确率 | 和 teacher 的差距 |
| **分布外表现** | 用训练时没覆盖的样本测——这是边界 |
| 单次成本 | 省了几倍 |
| P95 延迟 | 快了几倍 |
| **每次成功任务成本** | 综合判据，见 [[04-成本归因与每次成功任务成本]] |

**第二项是决定能不能上线的关键。** 分布内打平但分布外崩溃的 student，上线后会在长尾请求上持续出问题。

### 和量化的关系

蒸馏和量化都是降本手段，但机制不同：

- **量化**：同一个模型，减少每个参数的字节数，见 [[09-量化]]
- **蒸馏**：换一个更小的模型，参数量本身就少

**两者可以叠加**：先蒸馏出一个 7B，再把它量化到 FP8。收益相乘。

顺序上先蒸馏后量化，因为量化后的模型再拿去当 student 训练会更麻烦。

## 动手做

- [ ] 确认许可证允许用 teacher 的输出做训练
- [ ] 从真实流量抽输入，**刻意补足长尾**，不要按频率随机抽
- [ ] 用 teacher 生成输出，人工抽检修正一批
- [ ] 训一个小模型，和 teacher 对比五个指标
- [ ] **专门用训练分布外的样本测 student**，找出它的边界
- [ ] 算「每次成功任务成本」，看降本幅度是否值得这次投入
- [ ] 试一次蒸馏后再量化，看收益能不能相乘

## 算学会了

- [ ] 知道蒸馏的边界是「任务一变宽就塌」
- [ ] 数据的分布比数量重要，会刻意补长尾
- [ ] 上线前用分布外样本测过 student 的边界
- [ ] 动手前确认过许可证
- [ ] 判据是「相对 teacher 差多少、成本省多少」而非绝对分数

## 坑

**用编的输入生成数据。** 分布不对，student 在真实流量上不行。

**按频率随机抽样。** 长尾严重不足，边缘情况全崩。

**不做分布外测试。** 分布内打平、上线后在长尾上持续出问题。

**跳过人工抽检。** teacher 的错误会被完整继承且学得很牢。

**不看许可证。** 这是唯一会带来法务后果的一步。

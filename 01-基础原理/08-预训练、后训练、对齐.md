预训练、SFT、对齐这三步，流程上是先后关系，机制上是**三个不同的目标函数**。搞清楚各自在优化什么，「该微调还是该 RAG」这类问题就不用问了。

## 一句话

预训练优化「下一个 token 是什么」，SFT 优化「该怎么回答」，偏好优化改成「好回答要比坏回答概率高」——目标函数一换，能改动的东西就换了。

## 原理

> 这一篇讲的是**目标函数**。四个阶段各自的数据量、算力量级和成本账，见 [[00-模型是怎么来的]]；自己动手训的做法见 [[02-SFT 数据构造]]。

### 预训练：一个目标长出所有能力

目标函数就一个——最大化下一个 token 的对数似然，等价于最小化交叉熵：

$$
\mathcal{L} = -\sum_{t} \log P(x_t \mid x_{<t})
$$

没有任何任务标签，没有人工标注，纯粹是「把这段文本接下去」。

**为什么这一个目标能长出翻译、推理、写代码的能力？** 因为要把海量文本准确地接下去，模型被迫学会那些文本背后的结构。一段代码要接得对，就得懂语法；一道题的解答要接得对，就得跟上推理链条。**能力是压缩数据的副产品。**

这也解释了为什么事实性知识在这一步定型：那些事实在语料里出现了成千上万次，模型为了预测准必须记住它们。

### SFT：同一个损失，只换了算在哪

SFT 的损失函数和预训练**一模一样**，还是交叉熵。区别只有一处：**只在「回答」那部分算 loss，指令部分不算**。

```text
指令：用一句话解释 KV cache          ← 不算 loss
回答：把算过的 key 和 value 存下来…   ← 算 loss
```

这个细微差别改变了模型学到的东西：它不再是「续写任何文本」，而是「在看到指令之后，产出符合这种模式的回答」。学到的是**条件分布的形状**——被问就答、答完就停、按这种语气和结构。

**所以 SFT 改行为不改知识。** 几万条样本改不动 15 万亿 token 里长出来的事实，但足以改变回答的组织方式。这就是那条判据的机制来源：**想让模型知道新东西用 RAG，想让它改变做事方式才用微调**，见 [[01-四条路线选型：prompt、RAG、LoRA、蒸馏]]。

### 偏好优化：目标彻底换了

前两步都在最大化「某个正确答案的概率」。偏好优化换了个问题：**给定一对回答，让好的那个概率高于坏的。**

这是根本性的变化——它不需要标准答案，只需要「A 比 B 好」这种相对判断，而后者人类给得起、也给得准得多。

几种做法，按时间和复杂度：

| 方法            | 怎么做                                       | 代价                            |
| ------------- | ----------------------------------------- | ----------------------------- |
| **RLHF（PPO）** | 先用偏好对训一个奖励模型，再用强化学习优化                     | 要多训一个奖励模型和一个 critic，工程复杂、显存吃紧 |
| **DPO**       | 数学上证明可以跳过奖励模型，直接从偏好对推导出损失                 | 简单得多，但对数据质量敏感                 |
| **GRPO**      | 一个 prompt 采样多份回答，用组内相对好坏算优势，**省掉 critic** | 显存和算力都省，是推理模型后训练的常用基线         |
| **RLVR**      | 奖励不来自人类偏好，而来自**可自动校验的信号**（代码跑没跑过、答案对不对）   | 只适用于有客观判据的任务                  |

> [!warning] RLHF 那套「标准配方」已经不是主流了
> 一年前「预训练 + RLHF 人类偏好标注」还是默认答案，现在不是了。截至 2026 年，各家的后训练栈各不相同——DeepSeek-R1、Nemotron 3 Super、GPT-5.3 Codex 用的都不一样。
> 主线的两个变化：**GRPO 取代 PPO**（去掉 critic，用组内相对优势），**RLVR 取代部分人类偏好**（用可自动校验的奖励）。后者是推理模型能力跃升的关键——数学题对不对、代码跑不跑得过，这些信号比人类打分又准又便宜，还能无限量产。
> 后训练现在贡献了模型可用能力的**大部分**，见 [[04-推理模型的成本与延迟曲线]]。

### 对齐税

偏好优化让模型更合人意，但通常伴随一些损失：

- **多样性下降**——输出趋同，创意任务上尤其明显
- **校准变差**——模型学会了「说得笃定更受欢迎」，于是不确定时也表现得确定。这是 [[05-logprobs 与置信度]] 里那个「高置信度不等于正确」的机制来源
- **某些基准掉点**——对齐得越狠越明显

这就是所谓的对齐税。它是取舍不是缺陷，但要知道自己付了什么。

**这也是 base 模型仍然有人要的原因**：想自己做后训练的话，从没被别人对齐过的地基上开始更干净，见 [[00-模型是怎么来的]]。

### 一张对照表

| | 目标函数 | 改的是 | 需要什么数据 |
| --- | --- | --- | --- |
| 预训练 | 下一个 token 的交叉熵 | **知识与能力** | 海量无标注文本 |
| SFT | 同上，只在回答部分算 | **行为模式** | 指令-回答对 |
| 偏好优化 | 好回答概率 > 坏回答 | **偏好与安全** | 成对比较，或可校验信号 |

**从上到下，数据越来越少、越来越贵、改动的东西越来越表层。** 记住这个方向，多数「该用哪种方法」的问题就有答案了。

## 坑

**以为 SFT 能灌知识。** 损失函数和预训练一样，但数据量差几个数量级，改不动事实。

**拿一年前的后训练知识做判断。** RLHF 那套标准配方已经不是主流，现在是 GRPO 和 RLVR 的天下，而且各家不一样。

**忽略对齐税。** 对齐后的模型置信度不可信、多样性下降，这两点会直接影响你的置信度过滤和创意类任务。

**在没有客观判据的任务上想用 RLVR。** 它的前提是奖励能自动校验，主观任务用不了。

**把 base 当 instruct 用。** 它没做过第三步，不会遵守指令。

**这条线的方向很一致：一步步把 RLHF 的零件拆掉。** PPO 需要奖励模型加价值网络，DPO 去掉了奖励模型，GRPO 去掉了价值网络。每去掉一个，工程复杂度和显存需求都降一截——**所以看到新方法时，先问它省掉了哪个零件、代价是什么**。

attention 本身看不见顺序，「猫追老鼠」和「老鼠追猫」对它是一样的。顺序是从外面加进去的——而加的方式决定了这个模型能读多长。

## 一句话

位置信息靠外部注入，2021 年之后基本统一到 RoPE；把上下文拉长的各种方法都能让线往右延，但**延不平**——重要信息埋在训练长度之外时会急剧掉点。

## 原理

### 为什么必须外部注入

attention 是**置换等变**的：把输入 token 打乱顺序，输出只会跟着同样打乱，没有任何额外信息告诉它谁在前面，见 [[01-Transformer 与 attention]]。

所以位置必须显式加进去。历史上试过三代：

| 做法 | 怎么加 | 问题 |
| --- | --- | --- |
| 正弦绝对位置（2017） | 给每个位置算一个固定向量，加到 embedding 上 | 是绝对位置，外推能力有限 |
| 学习式绝对位置 | 位置也做成可训练的 embedding | 超出训练长度就完全没有对应的向量 |
| **RoPE**（2021） | 把 Q 和 K 按位置**旋转**一个角度 | 目前主流 |

### RoPE 在做什么

核心想法很漂亮：不去改 token 的表示，而是**在算 attention 之前，把 Q 和 K 按各自的位置旋转一个角度**。

旋转角度正比于位置。于是两个向量做点积时，结果只取决于它们的**角度差**——也就是相对位置。绝对位置在点积里自动抵消了。

这带来两个好处：

- **相对位置自然涌现**，不用额外设计
- 只作用在 Q、K 上，**不动 V**，也不动残差流

`config.json` 里的 `rope_theta` 控制旋转的基频。Qwen3-8B 是 1000000，比早期模型的 10000 大得多——**基频调大本身就是一种为长上下文做的准备**，见 [[02-开源权重包里有什么]]。

### 外推：把线往右延

模型训练时只见过 `max_position_embeddings` 那么长的序列。超过之后旋转角度进入没见过的区间，表现会崩。

几种把它拉长的方法：

- **位置插值（PI）**——把位置坐标等比压缩，让长序列「假装」还在训练范围内。简单，但压缩了高频分量，短距离的分辨率会损失
- **NTK-aware**——不均匀地缩放不同频率，保住高频（近距离）细节。不微调就能扩到几倍
- **YaRN**——分频段处理，高频保留、低频插值。比 PI 和 NTK-aware 效果好，且据其论文所需训练步数少 2.5 倍、数据少 10 倍

### 但它们都有同一个天花板

![[外推的悬崖.excalidraw.md|700]]

> [!warning] 这是本篇最该记住的一条
> 截至 2026 年的研究结论：**现有的 RoPE 缩放方法，在没有额外长上下文微调的情况下，无法有效泛化到超出训练长度的序列**。而且 YaRN 这类频率缩放技术有一个特定的失效模式——**重要信息埋在序列深处、且超出训练上下文时，下游任务表现急剧下降**。
> 换句话说：能塞进去 ≠ 能用。这就是标称长度和有效长度分家的技术原因，见 [[03-评测基准都在测什么]]。

所以看到一个模型宣称支持很长的上下文，要分清是哪一种：

- **原生训练到那个长度**——可信度高
- **靠外推缩放达到**——要看实测

`config.json` 里的 `max_position_embeddings` 和 `rope_scaling` 两个字段能看出端倪：后者不为空，说明用了缩放。

### 实践上怎么办

**测，别信。** 用 RULER 或大海捞针这类测试，在你实际会用到的长度上、把信息埋在不同深度，实测召回率。这个数才是你的有效长度。

**别把关键信息放在深处。** 既然深处的召回最不可靠，那就在工程上规避：重要的放开头和结尾，中间放可有可无的。这也和「attention sink」那个现象一致，见 [[01-Transformer 与 attention]]。

**长不等于该长。** 上下文越长，attention 计算量按平方涨、KV cache 按线性涨，见 [[03-KV cache 管理与显存测算]]。多数场景下把检索做好、只塞相关的进去，比硬塞 128k 又快又准，见 [[02-Context engineering：上下文即预算]]。

## 动手做

- [ ] 从 `config.json` 读出 `max_position_embeddings` 和 `rope_theta`，看有没有 `rope_scaling`
- [ ] 做一次大海捞针：把一句话埋在 25%、50%、75%、95% 四个深度，各测召回率
- [ ] 把总长度从训练长度扫到两倍、四倍，看召回率在哪个点开始塌
- [ ] 对比同一个模型开不开 YaRN 的表现差异
- [ ] 用实测有效长度反推：你的业务真正需要多长，需不需要付这个代价

## 坑

**信标称上下文长度。** 那是 `max_position_embeddings`，不是实测有效长度。

**以为外推方法免费。** 缩放会损失分辨率，深处信息掉点尤其明显。

**把关键信息埋在中间。** 那是召回最差的位置。

**上下文能开多长就开多长。** 计算量按平方涨，而质量未必跟着涨。

**换 `rope_scaling` 配置不重测。** 改了缩放参数等于换了位置语义，之前的 eval 结论全部作废。

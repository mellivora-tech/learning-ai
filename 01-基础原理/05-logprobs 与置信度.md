模型不只给你一个答案，还顺带给了它对这个答案有多确定。这个信号免费、随手可得，而且大多数系统完全没用上。

## 一句话

logprob 是「模型觉得这个 token 有多可能」，能用来做置信度过滤和零成本分类；但要记住：**它衡量的是模型的自信，不是正确性**，两者只有弱相关。

## 原理

### 它是什么

模型每一步输出的 logits 过完 softmax 就是概率分布，取对数就是 logprob。多数 API 支持返回被选中 token 的 logprob，以及排前几名的候选及其 logprob。

一段生成的 logprob 序列长这样：

```text
token      logprob    概率
"发票"      -0.02      98%
"金额"      -0.15      86%
"为"        -0.01      99%
"1280"     -2.31      10%     ← 这里模型很犹豫
".00"      -0.08      92%
```

**那个 -2.31 是信息。** 模型在金额上不确定，而这恰恰是最不能错的字段。

### 三个立刻能用的场景

**一、置信度过滤。** 把一段生成的平均 token 概率当置信度：

$$
\text{confidence} = \exp\left(\frac{1}{T}\sum_{t=1}^{T} \log P(x_t)\right)
$$

低于阈值的转人工、降级、或者触发重试。注意要用**平均**而不是联合概率——联合概率随长度指数衰减，长回答永远显得没信心。

更精细的做法是**只看关键字段**：抽取任务里，整段的平均值会被大量确定的连接词稀释，盯住金额、日期、ID 这些字段所在的那几个 token 更准。

**二、零成本分类。** 做选择题时，不用让模型输出「A」再解析，直接比较各选项 token 的 logprob 谁高。

好处是：不受输出格式影响、弱模型也能用、而且**天然得到每个选项的概率**而不只是一个答案。多数评测框架跑多选题就是这么做的，见 [[03-评测基准都在测什么]]。

**三、候选重排。** 生成 N 份候选，按 logprob 排序挑最好的。注意要做长度归一化，否则短的总是赢，见 [[02-Test-time compute scaling]]。

### 那个必须知道的局限

> [!warning] 高置信度不等于正确
> 模型可以非常自信地编造。这不是偶发，是系统性的：**经过 RLHF 等偏好对齐之后，模型的校准普遍变差**——它学会了「说得笃定的回答更受欢迎」，于是不确定的时候也倾向于表现得确定，见 [[08-预训练、后训练、对齐]]。
> 所以 logprob 能筛掉一部分「模型明显在犹豫」的输出，但筛不掉「模型自信地错了」。**它是一道便宜的粗筛，不是质量保证。**

要知道它在你的场景里有多可靠，得画**校准曲线**：把样本按置信度分桶，每桶算实际准确率。理想情况下置信度 0.8 的那桶准确率就是 80%，实际通常是一条压在对角线下方的曲线——**普遍过度自信**。

画出来之后你至少知道：阈值定在哪能拦住多少、误伤多少。没画过就定阈值，那是在猜。

### 几个技术细节

**temperature 会改变 logprob。** API 返回的通常是采样后分布的对数概率，temperature 越高分布越平，同一个 token 的 logprob 越低。做置信度比较时要固定 temperature，否则不同请求之间不可比，见 [[04-采样参数]]。

**长度归一化不能省。** 比较不同长度的候选时，用平均 logprob 而非总和。

**tokenizer 会影响它。** 同一个词在不同模型上切成的 token 数不同，逐 token 的概率也就没法跨模型比，见 [[03-Tokenization]]。

**不是所有 provider 都给。** 有些闭源 API 不返回 logprob，或者只给 top-k 个候选。选型时如果打算依赖这个信号，要先确认拿得到，见 [[05-怎么给一个任务挑模型]]。

### 在系统里怎么用

一个务实的组合：

1. **logprob 做粗筛**——低置信度的直接走人工或降级路径，成本几乎为零
2. **高置信度的抽样送 judge**——只对通过粗筛的做昂贵检查，见 [[04-Judge 校准]]
3. **把置信度打进 trace**——事后能回答「出错的那些，当时置信度是多少」，见 [[02-必打字段清单]]

第三步最容易被跳过，但它是校准曲线的数据来源。

## 动手做

- [ ] 打开 API 的 logprobs，把一段生成逐 token 的概率打印出来，找出模型最犹豫的位置
- [ ] 实现平均 token 概率的置信度函数，对一批真实输出打分
- [ ] 人工标注这批输出的对错，画校准曲线——看模型有多过度自信
- [ ] 从曲线上选一个阈值，算出拦截率和误伤率
- [ ] 在抽取任务上对比「整段平均」和「只看关键字段」两种置信度，看哪个更能预测错误
- [ ] 用 logprob 比较法做一次多选题分类，和「让模型输出字母再解析」对比准确率

## 算学会了

- [ ] 能用 logprob 算出置信度，且知道要用平均而非联合概率
- [ ] 画过自己场景的校准曲线，知道模型有多过度自信
- [ ] 阈值是从曲线上选的，不是拍的
- [ ] 知道 logprob 筛不掉「自信地错了」这一类
- [ ] 会用 logprob 比较法做分类，不依赖输出格式

## 坑

**把置信度当正确率。** 最危险的误用。模型能非常自信地编造，尤其在对齐之后。

**用联合概率。** 随长度指数衰减，长回答会被系统性判成低置信度。

**不做长度归一化就比较候选。** 短的永远赢。

**跨 temperature 或跨模型比 logprob。** 分布形状和 tokenizer 都不同，数值不可比。

**只算整段平均。** 关键字段的犹豫会被大量确定的虚词稀释掉。

「怎么配才最优」这个问题没有答案。有答案的是：「给定这条 SLO，怎么配吞吐最高」。

## 一句话

吞吐和尾延迟是一对儿对立的量，所有配置组合构成一条前沿曲线；调优的全部内容就是**先划一条 SLO 线，再取线下吞吐最大的那个点**。

## 原理

### 为什么不存在「最优配置」

![[吞吐与延迟的帕累托前沿.excalidraw.md|700]]

把 `max_num_seqs`、`max_num_batched_tokens` 这些参数扫一遍，每组配置得到一个（吞吐，P95 延迟）坐标点。连起来就是一条前沿——**在这条线上，想要更高的吞吐必须付出更高的延迟，反之亦然。**

线上的每个点都是「最优」的（没有别的配置能同时更快更省），线下的点都是浪费。所以问题不是「哪个最优」，而是**「我的 SLO 允许我站在这条线的哪个位置」**。

这也是为什么别人的配置不能照抄——他们的 SLO 和你的不一样。

### 那几个参数各把你往哪边推

| 参数 | 调大 | 主要影响 |
| --- | --- | --- |
| `max_num_seqs` | 吞吐 ↑，P99 ↑ | 受 KV cache 显存约束，见 [[03-KV cache 管理与显存测算]] |
| `max_num_batched_tokens` | 吞吐 ↑，TPOT 抖动 ↑ | 允许更多 prefill 混进来，见 [[07-Continuous batching]] |
| `max_model_len` | 并发 ↓ | 直接吃 KV cache 空间 |
| `gpu_memory_utilization` | 并发 ↑，OOM 风险 ↑ | 见 [[04-PagedAttention 与分页显存]] |
| 量化 | 两边都改善 | 少有的双赢，见 [[09-量化]] |
| 投机解码 | 低并发时延迟 ↓，高并发时反而变差 | 见 [[08-投机解码]] |

**注意最后两行**：量化是把整条前沿往外推（同样的延迟下吞吐更高），而不是在前沿上移动位置。这类改进比调参值钱得多——**先把前沿推出去，再在上面选点**。

### 怎么扫

1. **定义负载**——用真实的请求长度分布，不要用固定长度，见 [[02-指标体系]]
2. **网格扫描**——`max_num_seqs` × `max_num_batched_tokens` 各取几档，笛卡尔积
3. **每组开环压测**——按固定速率发，压到饱和
4. **记录四个数**——吞吐、P50/P95/P99 延迟（TTFT 和 TPOT 各一套）、抢占次数
5. **画散点，取外沿**——那条外沿就是前沿

第 4 步里的抢占次数容易被忽略，但它是解释「为什么这个点的 P99 特别差」的关键，见 [[06-驱逐与内存压力]]。

### 从 SLO 反推配置

假设 SLO 是「P95 首字 < 2s，P95 每字间隔 < 50ms」：

1. 在散点图上画两条线，划出满足条件的区域
2. 区域内取吞吐最大的那个点
3. 那个点对应的参数组合就是答案
4. **留 20% 余量**——线上流量会波动，卡在临界点上一抖就破 SLO

**能这样反推出配置，就说明你真的懂这个系统了**；靠一组组试出来的，换个模型或换张卡就得从头再来。

### 前沿本身也会动

它不是一次测完就固定的。这几件事会让它整体移动：

- 换模型、换量化格式 → **往外推**
- 上下文变长、请求分布变化 → **往内缩**
- 换卡（尤其带宽变了）→ 往外推，见 [[01-一张卡的四个关键数字]]
- 引擎版本升级 → 通常往外推

所以这条曲线值得定期重测，尤其在换模型或换硬件之后。

## 动手做

- [ ] 用真实长度分布做开环压测，扫 `max_num_seqs` × `max_num_batched_tokens` 的网格
- [ ] 每组记录吞吐、P95/P99 的 TTFT 与 TPOT、抢占次数
- [ ] 画散点图，标出外沿——那就是你的前沿
- [ ] 给定一条 SLO，在图上反推出配置，留 20% 余量
- [ ] 开启量化再扫一遍，验证前沿整体外推了多少
- [ ] 换一个上下文长度再扫一遍，看前沿往内缩多少

## 算学会了

- [ ] 给你一条 SLO，能反推出配置，而不是靠试
- [ ] 知道不存在「最优配置」，只存在「符合这条 SLO 的最优点」
- [ ] 分得清「在前沿上移动」和「把前沿推出去」，优先做后者
- [ ] 记录抢占次数，能解释某些点的 P99 为什么特别差
- [ ] 换模型或换卡之后会重测前沿

## 坑

**照抄别人的配置。** 他们的 SLO、请求分布、硬件都和你不同。

**只优化吞吐。** 吞吐可以靠堆 batch 无限刷高，代价是尾延迟爆炸。

**卡在临界点上线。** 流量一波动就破 SLO，必须留余量。

**只在低并发下测。** 看不到拐点，也看不到抢占何时开始。

**测完就当永久结论。** 换模型、换卡、请求分布变化都会移动前沿。

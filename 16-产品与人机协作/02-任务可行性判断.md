最省钱的一次技术判断，是在启动之前认出「这个任务现在做不成」。

## 一句话

先问**这个任务人做起来要多久、错了代价多大、有没有客观判据**——这三个答案决定了它是该全自动、该人机协作，还是根本不该做。

## 原理

### 三个问题

**一、人做要多久？**

| 人的耗时 | 含义 |
| --- | --- |
| 几秒 | 自动化收益小，可能不值得做 |
| **几分钟到几小时** | **甜区**——收益明显且任务边界通常清晰 |
| 几天 | 拆开，别指望一次做完，见 [[12-任务分解策略]] |

**二、错了代价多大？**

| 代价 | 该怎么做 |
| --- | --- |
| 用户重试一次就行 | 可以全自动 |
| 要人工修 | 人机协作，见 [[03-HITL 交互设计]] |
| **不可逆（付款、发邮件、删数据）** | **必须人工确认**，见 [[03-升级到人与结构化中间状态]] |
| 合规或安全后果 | 可能根本不该自动化 |

**三、有没有客观判据？**

能不能写出一条规则，让两个人判出同样的结果，见 [[01-怎么定义「好」]]。**没有客观判据的任务，你既无法优化也无法验收**——它会变成一个永远在「感觉好像好了一点」的项目。

### 现在做不成的几类

诚实一点，有些事 2026 年的模型仍然不擅长（这个清单会过期，要定期重测）：

| 类型 | 为什么 |
| --- | --- |
| **需要精确计算** | 交给代码执行，别让模型算，见 [[10-沙箱化代码执行]] |
| **需要实时私有数据** | 走检索或工具，不是模型能力问题，见 [[03-Hybrid search（dense + BM25 + RRF）]] |
| **超长链条不容错** | 每步 95% 正确，20 步之后只剩 36%，见 [[02-终止条件]] |
| **需要为结果承担责任** | 模型不能承担责任，人才能 |
| 高度主观且无共识 | 没有客观判据 |

**第三条是最常被低估的**。它是纯数学：单步再准，链条一长成功率就崩。所以长任务要么拆短、要么每步加校验，见 [[07-幂等性与故障注入]]。

### 先做一次「上限测试」

启动前花半天做这件事，能省几个月：

1. 挑 20 条最典型的真实任务
2. **手工**给模型最理想的上下文（人工挑好的资料、精心写的提示词）
3. 看它能做对几条

**这个数就是上限。** 因为真实系统里检索会漏、上下文有噪声，只会更差。

- **上限低于 50%**：现在别做，或者大幅缩小任务范围
- **上限 50–80%**：可行，但要设计人机协作
- **上限高于 90%**：可以考虑较高程度的自动化

**很多项目跳过这一步，直接进入「优化检索、优化提示词」的循环**，几个月后才发现上限本来就不够。

### 缩小范围通常比提升能力容易

上限不够时，第一反应应该是缩范围而不是换模型：

| 原任务 | 缩小后 |
| --- | --- |
| 「回答任何客户问题」 | 「回答产品文档能覆盖的问题，其余转人工」 |
| 「自动处理所有发票」 | 「自动处理三家主要供应商的标准格式发票」 |
| 「写完整报告」 | 「写初稿，人来改」 |

**缩小后的任务往往能做到 90% 以上，而原任务卡在 60%。** 而且窄任务上小模型就够用，见 [[07-蒸馏]]。

### 别忘了算账

可行不等于值得，见 [[04-成本归因与每次成功任务成本]]：

$$
\text{收益} = (\text{人工耗时} - \text{复核耗时}) \times \text{频次} - \text{每次成功任务成本}
$$

**「复核耗时」那一项经常被漏掉**。如果人还是得逐字检查输出，节省的时间可能接近零——这时候要么提高可信度到能免检，要么让复核变得便宜（比如可追溯，见 [[06-幽灵文档测试]]）。

## 动手做

- [ ] 对每个候选任务回答那三个问题
- [ ] 做一次上限测试：20 条任务、理想上下文、看做对几条
- [ ] 上限不够时，先试缩小范围而不是换模型
- [ ] 列出不可逆操作，确认它们都要人工确认
- [ ] 算收益公式，把复核耗时算进去
- [ ] 定期重测那份「现在做不成」的清单

## 算学会了

- [ ] 启动前做过上限测试，知道天花板在哪
- [ ] 知道错误代价，且不可逆操作有人工确认
- [ ] 任务有客观判据
- [ ] 上限不够时先想缩范围
- [ ] 收益计算里包含了复核耗时

## 坑

**跳过上限测试直接做。** 几个月后才发现上限本来就不够。

**先想换更强的模型。** 缩小范围通常更有效也更便宜。

**忽略链条长度对成功率的影响。** 每步 95%、20 步只剩 36%。

**收益计算不算复核耗时。** 如果人还得逐字检查，节省接近零。

**把没有客观判据的任务立项。** 它会变成一个永远在「感觉好了一点」的项目。

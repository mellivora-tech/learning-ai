把对话都存下来，听起来最保险。实际上是给自己攒了一堆越来越难检索的噪声。

## 一句话

写入的判据是**「以后还会被用到，且不容易变」**——不满足这两条的别存；存的时候要存结论不存原文。

## 原理

### 什么值得存

两个条件同时满足才写：

**会被反复用到。** 用户的语言偏好会一直生效，「他 3 月 5 日问了个问题」不会。

**足够稳定。** 「在上海」能管很久，「正在开会」十分钟后就错了。

按这两条筛，四类记忆的处理方式差别很大，分类见 [[01-短期与长期记忆分层]]：

| 类型 | 存不存 | 怎么存 |
| --- | --- | --- |
| 事实型 | 存 | 结构化键值，带来源和时间 |
| 偏好型 | 存 | 结构化键值 |
| 状态型 | 存，但必须带过期 | 带 TTL，见 [[05-遗忘与过期机制]] |
| 情节型 | 多数不存 | 真要存就存摘要，别存原文 |

### 存结论，不存原文

这是写入环节最重要的一条。

对比一下：

```text
✗ 原文：「我们公司用的是 PostgreSQL 14，不过在考虑升级，
        因为 15 的分区表性能更好，但是 DBA 说要等 Q3……」

✓ 结论：{ "db": "PostgreSQL 14", "source": "会话 2026-03-11", "confidence": "high" }
        { "plan": "考虑升级到 15", "eta": "Q3", "confidence": "low" }
```

结论型存储的好处：**可检索、可比对、可去重、可过期**。原文型存储会让检索变成大海捞针，而且没法判断两条记忆是不是在说同一件事，见 [[04-记忆冲突消解]]。

每条记忆至少带三个元数据：

- **来源**——哪次会话、哪句话说的，出问题能回查
- **时间**——用来判断新旧，冲突时新的通常胜出
- **置信度**——用户明确说的 vs 模型推断出来的，两者不该同等对待

第三项常被忽略，但它是防止「模型自己猜的东西变成事实」的唯一防线。

### 什么时候写

三种时机，各有取舍：

| 时机 | 优点 | 缺点 |
| --- | --- | --- |
| 每轮实时抽取 | 不丢信息 | 每轮多一次调用，贵；容易存进临时状态 |
| 会话结束时总结 | 便宜、能看到全貌 | 会话中断就丢了 |
| 异步批处理 | 不影响主链路延迟 | 有延迟，同一会话内用不上 |

**多数场景下会话结束时总结加异步批处理是够用的组合**。每轮实时抽取只在「同一会话内就要用到刚说的事」时才必要。

### 别让模型自己决定存什么

给模型一个 `save_memory` 工具让它自主决定，看着优雅，实际问题很多：

- 存得过多（它倾向于觉得什么都重要）
- 存得随意（同一个事实换个说法又存一遍）
- 存进临时状态（把「我现在有点急」当长期偏好）

更稳的做法是**用固定的 schema 抽取**：

```json
{
  "facts":       [{"key": "...", "value": "...", "confidence": "..."}],
  "preferences": [{"key": "...", "value": "..."}],
  "ttl_items":   [{"key": "...", "value": "...", "expires": "..."}]
}
```

schema 约束住了「能存什么」，剩下的只是填空。这也让去重和冲突检测变得可行，见 [[01-结构化输出三档]]。

### 写入要幂等

同一个事实被说了三次，不该产生三条记忆。所以写入前要查重：

- **键相同**——直接更新，保留新的值和时间
- **语义相近但值不同**——这是冲突，走冲突处理，见 [[04-记忆冲突消解]]
- **完全新的**——插入

没有这一步的话，存档会以对话轮数的速度膨胀，而信息量并没有同步增长。

### 隐私是硬约束

记忆系统天然存的是用户数据，所以：

- **明确哪些字段不许存**（身份证、银行卡、健康信息等，视合规要求而定）
- **提供删除入口**——用户要求删除时，记忆存档也要删干净，见 [[01-数据驻留]]
- **按租户隔离**——记忆检索的 cache key 和索引都要带租户维度，见 [[06-多租户隔离]]

这几条属于上线前必须过的，不是优化项。

## 算学会了

- [ ] 写入判据是「会被反复用到 + 足够稳定」，不满足就不存
- [ ] 存结论不存原文，每条带来源、时间、置信度
- [ ] 用固定 schema 抽取，不让模型自由决定
- [ ] 写入是幂等的，同一事实不会产生多条
- [ ] 知道哪些字段绝对不能存，且有删除入口

## 坑

**把对话原文全存。** 检索质量会随存档增长快速下降。

**让模型自主决定存什么。** 它会存太多、存重复、存临时状态。

**不带置信度。** 模型推断出来的东西和用户明说的混在一起，几轮之后分不清了。

**写入不幂等。** 存档以对话轮数膨胀，信息量却没涨。

**忘了删除入口。** 合规要求删除时，发现记忆存档删不干净。

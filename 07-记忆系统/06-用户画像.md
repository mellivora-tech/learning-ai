把散落的记忆聚成一个「这个人是谁」的结构，是记忆系统里最有产品价值、也最容易越界的一步。

## 一句话

画像是记忆的**聚合视图**——它让每轮对话不必重新检索一堆碎片；但它也把「模型的猜测」固化成了「关于这个人的结论」，所以边界要划清楚。

## 原理

### 画像和记忆的关系

记忆是一条条散的事实，画像是它们的**结构化聚合**：

```json
{
  "identity":    {"role": "后端工程师", "domain": "电商", "confidence": "high"},
  "tech_stack":  {"db": "PostgreSQL", "lang": "Go", "confidence": "high"},
  "preferences": {"language": "中文", "verbosity": "简短", "code_style": "带注释"},
  "constraints": {"no_external_api": true},
  "updated": "2026-07-31"
}
```

好处很实在：**它可以全量塞进上下文**（几百 token），不需要每轮做检索，也就没有召回失败的风险，见 [[03-记忆检索与召回]]。

**画像应该小**。它是提炼不是堆砌——大到塞不下的时候，说明该把细节留在记忆层，只把最常用的提上来。

### 怎么生成

两条路：

**规则聚合。** 从结构化记忆里按 key 直接映射。可控、可解释、便宜。适合字段固定的场景。

**模型总结。** 让模型读一批记忆写出画像。灵活，但会引入推断——而推断出来的东西容易被当成事实。

**推荐组合**：确定性字段走规则，需要归纳的字段走模型但**明确标注置信度**，见 [[02-记忆写入策略]]。

### 那条必须划的线

> [!warning] 别让画像变成对人的判断
> 存「偏好简短回答」是记录行为。存「这个用户不太懂技术」是**对人下判断**——而且是模型推断出来的判断。
>
> 后者的问题：
> - 可能就是错的，而且会自我强化（认定他不懂 → 回答更浅 → 更看不出他懂）
> - 用户看到会很不舒服，尤其是被误判的时候
> - 涉及能力、性格、经济状况这类推断，在很多地区有合规风险
>
> **判据：这条画像如果直接展示给用户看，你会不会尴尬？** 会的话就不该存。

安全的画像内容大致是：**用户明确表达过的偏好、可观察的客观事实、他自己提供的信息**。不安全的是：能力评价、性格判断、敏感属性的推断。

### 让用户能看和能改

这一条同时解决准确性和信任两个问题：

- **可见**——用户能看到系统记住了什么
- **可改**——错了能直接改，而不是靠反复说
- **可清空**——一键重置

代价是要做一个界面，收益是画像质量会显著提升——**用户自己维护的画像，比模型推断的准得多**。而且这也是合规上的删除入口，见 [[05-遗忘与过期机制]]。

### 多角色与多场景

同一个人在不同场景下可能要不同的画像：

- 工作场景 vs 个人场景
- 不同项目、不同租户

**共用一份画像会互相污染。** 处理方式是给画像加 scope，或者干脆按场景分开存。这和记忆冲突里「适用范围不同」是同一类问题，见 [[04-记忆冲突消解]]。

另外要留意**账号共用**——一个账号背后可能是多个人，画像会被搅成四不像。冲突频率异常升高是这种情况的信号。

### 效果怎么衡量

画像的价值不该靠感觉判断：

- **A/B 测**：有画像和无画像两组，比任务成功率和轮数
- **画像准确率**：抽样让用户确认，看有多少条是错的
- **修正率**：用户主动改了多少——高说明推断质量差

第三个指标最直接。**修正率高不是坏事**（说明用户在用这个功能），但如果集中在模型推断出来的那些字段上，就该收紧推断了。

## 动手做

- [ ] 设计画像 schema，控制在几百 token 内
- [ ] 确定性字段走规则聚合，归纳字段走模型并标置信度
- [ ] 逐条检查：哪些字段直接展示给用户会尴尬——那些删掉
- [ ] 做一个可见可改的界面，跑一周统计修正率
- [ ] 给画像加 scope，验证多场景不互相污染
- [ ] A/B 测有无画像的任务成功率差异

## 算学会了

- [ ] 画像是聚合视图，小到能全量塞进上下文
- [ ] 有明确的边界：记录行为不下判断
- [ ] 用「直接给用户看会不会尴尬」当判据
- [ ] 用户能看能改能清空
- [ ] 用修正率反向检查推断质量

## 坑

**画像里存对人的判断。** 可能错、会自我强化、有合规风险。

**画像越做越大。** 大到塞不下就失去了「不用检索」这个核心好处。

**不给用户看。** 错了没人纠正，越用越偏。

**多场景共用一份。** 工作和个人偏好互相污染。

**把推断和事实混在一起存。** 几轮之后分不清哪些是用户说的。

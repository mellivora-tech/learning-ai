模型调用了一个真实存在的转账工具，参数格式完全正确，金额也在合理范围——只是那个收款人 ID 是它编的。

## 一句话

幻觉工具调用最常见的形态是**「真工具 + 假 ID」**，而这一类只有第三层（指称校验）拦得住；schema 校验和值域校验都会放它过去。

## 原理

![[四层参数校验.excalidraw.md|540]]

### 四层

![[四层参数校验.excalidraw.md|597]]

| 层 | 问什么 | 谁来做 |
| --- | --- | --- |
| ① **语法** | 字段齐吗、类型对吗 | schema 校验，约束解码已覆盖 |
| ② **语义** | 值在合理范围吗、单位对吗 | 业务规则 |
| ③ **指称** | **这个 ID 真的存在吗** | 查库 |
| ④ **授权** | **当前用户**有权这么做吗 | 权限系统 |

**每一层只能拦住自己那一类。** 上一层通过不代表下一层没问题——这是最常被误解的地方，见 [[01-结构化输出三档]]。

### ① 语法

约束解码基本已经解决了这一层。没用约束解码的话，用 JSON Schema 校验。

需要注意的是**必填与可选的区分**：模型漏填一个可选字段是正常的，漏填必填字段是错误——两者的处理不同。

### ② 语义

格式对不代表值合理：

- **值域**：退款金额是负数、日期在未来、数量超过库存
- **单位**：`amount: 1280` 是元还是分？这类错误在跨系统时最常见
- **格式约定**：订单号形如 `ORD-2026-000123`，但模型给了 `123`
- **枚举**：`reason_code` 必须是那四个值之一

**单位问题值得单独强调**。把单位编进参数名（`amount_cny` 而不是 `amount`）能消掉一大半，见 [[05-工具合约五段式模板]]。

### ③ 指称：这一层最重要

> [!danger] 真工具 + 假 ID
> 模型调用了正确的工具，参数格式完美，值也合理——但引用的实体根本不存在。
>
> 这是幻觉工具调用最常见的形态，因为它**通过了前两层的所有检查**。ID 长得像真的（模型很擅长生成看起来合理的标识符），格式也对，只是数据库里没有。
>
> 更危险的变体是**「像但不是」**——`ORD-2026-000123` 存在，但用户说的其实是 `ORD-2026-000132`。这时候操作会成功执行，只是执行在了错误的对象上。

所以规则是：**所有实体 ID 在使用前必须验证存在性。**

而且不只是「存在」，还要验证：

- **状态对不对**——订单存在，但已经退过款了
- **归属对不对**——订单存在，但不是这个用户的（这就滑向第四层了）
- **来源可信吗**——这个 ID 是用户明确给的，还是模型从上下文里推断的

最后一条是个很实用的启发：**模型推断出来的 ID 要比用户明确给出的 ID 多一层确认**。工具合约里可以写明这一点。

### ④ 授权：必须按「当前用户」判

这一层最容易出错的地方不是忘了做，而是**做错了主体**。

```text
✗ 用服务账号的权限查询 → 服务账号什么都能看 → 等于没有授权检查
✓ 用当前请求的用户身份判权限
```

LLM 应用里这个错误特别容易犯，因为模型和工具之间隔着一层，请求上下文里的用户身份很容易在传递中丢失。

要点：

- **用户身份要贯穿整条调用链**，从入口一路传到工具执行
- **权限检查在检索/执行时做，不是在生成后过滤**，见 [[04-权限过滤时机]]
- **多租户下还要带租户维度**，见 [[06-多租户隔离]]

### 校验失败之后

不同层的失败，处理不同：

| 失败层 | 处理 |
| --- | --- |
| ① 语法 | 走修复循环，见 [[02-修复循环（报错回灌）]] |
| ② 语义 | 修复循环，报错要说清哪个值不合理 |
| ③ 指称 | **不要让模型自己重试**——它会编一个新 ID。应该反查候选让它选，或者问用户 |
| ④ 授权 | **直接拒绝，不重试、不降级**，并记录审计日志 |

第三行的处理值得注意：ID 不存在时让模型重试，它大概率会再编一个。正确做法是把「可选的真实 ID 列表」给它，或者直接向用户确认。

第四行是红线：授权失败绝不能被修复循环或降级链绕过，见 [[04-降级链]]。

## 坑

**以为 schema 校验够了。** 它只覆盖第一层，「真工具 + 假 ID」照样通过。

**用服务账号判权限。** 等于没有授权检查，而且很难发现。

**指称失败让模型重试。** 它会编一个新的 ID。

**授权失败走降级链。** 降级的边界是「更差但正确」，不是绕过检查。

**忽略单位。** 元和分差一百倍，而两个值都通过 schema 校验。

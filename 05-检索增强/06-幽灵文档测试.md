这个 bug 永远不会报错。它唯一的症状是：某天有人发现系统引用了一份三个月前就该删掉的文档。

## 一句话

删除传播的失效是**静默**的，所以只能靠一个主动去找它的自动化测试——删一篇、查一篇、查得到就报警。

## 原理

### 为什么必须专门测

普通 bug 有报错、有异常日志、有失败指标。幽灵文档一样都没有：

- 检索照常返回结果
- 模型照常生成回答
- 所有指标都正常
- **唯一的异常是回答的内容不该出现**

而内容层面的异常，只有人工看或者专门的测试才发现得了，见 [[05-Freshness 与 tombstone 删除传播]]。

### 测试怎么写

核心逻辑三步：

```python
def test_ghost_document():
    # 1. 灌一篇带独有标记的文档
    marker = f"GHOSTTEST-{run_id}"          # 保证语料里绝不会自然出现
    doc_id = ingest(f"这是一份测试文档，标记 {marker}。……")
    wait_until_searchable(doc_id)

    # 2. 确认它能被检索到（否则测的就不是删除）
    assert marker in search(marker), "文档根本没进索引，测试无效"

    # 3. 删除，等传播，再查
    delete(doc_id)
    wait_for_propagation()
    hits = search(marker)
    assert not hits, f"幽灵文档：删除后仍能召回 {hits}"
```

**第 2 步不能省。** 少了它，测试可能因为「文档压根没进索引」而假通过——那是另一个 bug，但会被误当成删除成功。

### 要覆盖的几种删除

一个测试不够，删除有好几种形态：

| 形态 | 要验证 |
| --- | --- |
| 单篇删除 | 该篇的**所有块**都不可召回 |
| 批量删除 | 全部删掉，没有漏网 |
| 更新（删旧建新） | 只召回新版本，旧版本消失 |
| **合规删除** | 向量索引、备份、日志里都清了 |
| 租户级删除 | 该租户的全部内容不可召回，且不影响别的租户 |

**第四行要单独测**，因为它的要求最严：不是「检索不到」，而是「数据真的不存在了」，见 [[01-数据驻留]]。

### 用不同的查询方式各测一遍

删除可能只在某一条检索路径上失效：

- **向量检索**能召回吗
- **BM25**能召回吗——两路是不同的索引，见 [[03-Hybrid search（dense + BM25 + RRF）]]
- **元数据过滤**（按 doc_id 直查）能查到吗
- **重排之后**还在结果里吗

见过只删了向量索引、忘了删倒排索引的情况——纯向量测试会通过，混合检索时幽灵就冒出来了。

### 接进 CI 和线上巡检

**CI 里**：每次改动检索链路、索引配置、同步管道时跑，见 [[02-回归测试与 CI 门禁]]。

**线上巡检**：定期（比如每小时）在生产环境跑一遍。理由是这类问题往往由**运维操作**引起——索引重建、迁移、扩容，而这些操作不走 CI。

线上巡检要注意：

- 用明显的测试标记，避免污染真实数据
- 测试文档要能被清理掉，别越积越多
- 巡检失败要**告警到人**，不是记个日志

### 顺便测反向：新增有没有进去

同一套框架可以顺带测新鲜度：

```python
doc_id = ingest(f"新增测试 {marker}")
t0 = time.time()
wait_until(lambda: marker in search(marker), timeout=SLA)
record_metric("index_lag_seconds", time.time() - t0)
```

**这个延迟指标很有用**：它直接量出「文档进系统到能被搜到」要多久，是新鲜度 SLA 的实测值，见 [[03-漂移监控三条线]]。

### 这个测试的元价值

roadmap 把它单独列出来，理由是它体现了一类思维方式：

> **有些 bug 不会主动找上门，只能靠你主动去找。**

同类的还有：语义缓存的假命中（见 [[05-Semantic caching 与假命中]]）、压缩抹掉安全约束（见 [[03-Compaction 与外部记忆文件]]）、静默降级（见 [[04-降级链]]）。

**共同特征是：失败时系统表现完全正常。** 遇到这类问题，唯一的办法就是构造一个专门的探针去戳它。

## 坑

**只测「删了之后查不到」。** 少了「删之前能查到」这一步，测试会假通过。

**只测向量检索。** 混合检索下有两个索引，可能只删了一个。

**只在 CI 跑。** 索引重建、迁移这类运维操作不走 CI，而它们恰恰是主要成因。

**测试文档不清理。** 越积越多，污染真实语料。

**巡检失败只记日志。** 没人看的日志等于没发现。

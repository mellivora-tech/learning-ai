## 交付物

一份选型报告，加一个能复跑的评测脚本。报告里必须有：

- 硬约束清单，以及每条砍掉了哪些候选
- 短名单怎么来的（用了哪个榜、为什么是那个榜）
- 30–50 条**真实**样本的评测结果表：准确率、单次成本、P95 延迟、失败模式各一列
- 最终选择，以及「**为什么不是更贵的那个**」——这一句是整份报告的重点
- **失效条件**：什么情况下这个结论要重来
- 存成版本化文件的样本集，直接作为 [[01-Golden set]] 的第一版

## 做法

1. 挑一个手头真实的任务，不要用玩具题目
2. 把任务写成一句**可判定**的话——两个人拿同一条输出能判出同样的结果，见 [[01-怎么定义「好」]]
3. 写硬约束：数据能不能出内网、许可证、上下文长度、延迟预算、自建还是 API
4. 用榜单收到 3–5 个候选，跨档位选（比如 7B / 32B / 闭源大模型各一个），见 [[04-排行榜怎么读]]
5. 从线上流量抽样并标注，含脏数据和边缘情况
6. 同一套提示词跑全部候选，注意**每个模型用它自己的 chat template**
7. 记四类数字，特别记下每个模型**错在哪类输入上**
8. 找出「最小够用」的那一档，算它和最贵那档的成本差

第 6 步那个提醒值得单独拎出来：**用错 chat template 会让某个模型的分数莫名其妙地低**，而现象看起来像是「这个模型不行」。

### 评测脚本骨架

```python
import json, time, statistics as st

CANDIDATES = ["模型A", "模型B", "模型C"]
SAMPLES = [json.loads(l) for l in open("eval.jsonl", encoding="utf-8")]

def judge(pred, expected):
    # 能程序化判定就别用 judge 模型
    return all(pred.get(k) == v for k, v in expected.items())

for m in CANDIDATES:
    ok, lat, cost = 0, [], 0.0
    for s in SAMPLES:
        t0 = time.perf_counter()
        pred, usage = call(m, s["input"])       # 你自己的调用封装
        lat.append(time.perf_counter() - t0)
        ok += judge(pred, s["expected"])
        cost += price(m, usage)
    n = len(SAMPLES)
    print(f"{m}: 成功率 {ok/n:.0%}  P95 {st.quantiles(lat, n=20)[18]:.2f}s  "
          f"每次成功 ¥{cost/max(ok,1):.4f}")
```

**注意最后是 `cost/ok` 而不是 `cost/n`**——失败的调用也花了钱，按成功次数摊才是真实成本，见 [[04-成本归因与每次成功任务成本]]。

## 复盘

- 榜单排名和你的实测排序一致吗？不一致的地方说明了什么
- 最便宜那档和最贵那档，eval 差了多少？**这个差值值那个价钱吗**
- 失败模式集中在哪类输入上？那类输入占真实流量多少
- 有没有哪条硬约束是事后才发现的——尤其是许可证和数据驻留，见 [[04-模型权重来源]]
- 半年后有人问「为什么不用 C」，你的报告答得上来吗

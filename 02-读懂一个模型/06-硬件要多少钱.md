技术报告里写「278 万卡时」，那到底是多少钱？一张卡多少钱、租一小时多少钱、什么时候自建划算——这几个数不知道，成本讨论全是空的。

## 一句话

卡时是硬件世界的通用货币：训练用它计价，推理用它折算；而**自建的账按卡时走，API 的账按 token 走**，两边换算到同一个单位，才知道该走哪条路。

## 原理

> [!warning] 本篇所有价格都是 2026 年 7 月的量级
> GPU 价格波动极大，同一张卡在不同云上能差 8 倍，而且逐季度在变。**下面的数字只用来建立量级感，做决策时必须去查当天的报价。** 会保值的是算账的方法，不是数字本身。

### 买一张卡多少钱

| 卡    | 显存     | 买断价（美元）    |
| ---- | ------ | ---------- |
| H100 | 80 GB  | 2.5 万–4 万  |
| H200 | 141 GB | 比 H100 高一档 |
| B200 | 192 GB | 3 万–5 万    |

一台八卡机器，光卡钱就是二三十万美元，还没算主板、网络、机柜、电。这也是为什么绝大多数团队不买卡——**买卡是重资产生意，不是工程决策**。

### 租一小时多少钱

这才是多数人真正面对的价格。同一张 H100，2026 年年中的行情：

| 来源 | 每 GPU·小时（美元） |
| --- | --- |
| 小型云、算力市场 | 1.4–2.0 |
| 中型云 | 3–5 |
| 三大公有云按需实例 | 10–12 |

**差了八倍。** 同一张卡、同样的性能，价格取决于你从谁手上租。三大云贵在合规、SLA 和跟已有基础设施打通；算力市场便宜在你得自己扛可用性。

国内的行情（2026 年年中，人民币每小时）：

| 卡 | 每小时 |
| --- | --- |
| H100 | 85–95 元 |
| A100 80GB | 35–40 元 |
| 昇腾 910B（64 GB） | 18–22 元 |
| RTX 4090 | 28–32 元 |

昇腾 910B 是 64 GB HBM2e、带宽约 1200 GB/s。显存比 H100 小一档，这直接决定了它能跑多大的模型、KV cache 能开多长，见 [[03-KV cache 管理与显存测算]]。规格数字各自意味着什么、国产卡的实际发挥率如何，见 [[01-一张卡的四个关键数字]] 和 [[05-国产卡与生态差距]]。

> [!tip] 报价里没写的那部分
> **利用率。** 卡按小时计费，不管你用没用。一张卡月租按 24×30 算，跑得满和跑一半，单位成本差一倍。
> **闲置时段。** 白天满、夜里空的业务，实际利用率可能只有三成。
> **不是所有时间都在算。** 加载模型、等请求、显存碎片整理都在烧钱。

### 把卡时换成钱

有了单价，技术报告里那些数字就有了实感。拿 DeepSeek-V3 的公开账本算：

| 阶段 | H800 卡时 | 按 2 美元/时 |
| --- | --- | --- |
| 预训练 | 266.4 万 | 约 533 万美元 |
| 上下文扩展 | 11.9 万 | 约 24 万 |
| 后训练 | 0.5 万 | **约 1 万** |
| 合计 | 278.8 万 | **约 558 万美元** |

报告里自己按 2 美元/卡时估的总价就是 557.6 万美元。这个数字之所以出名，是因为它比同期同级别模型的传闻成本低了一大截。

后训练那行值得多看一眼：**一万美元**。这就是为什么开源社区能玩得起——等大厂放出 base 模型，各自做后训练的门槛低到个人可承受，见 [[00-模型是怎么来的]]。

### 自建还是调 API

![[自建还是调 API.excalidraw.md|700]]

两边的计费单位根本不同，这是全部纠结的根源：

- **自建**：成本 = 卡时 × 单价。**和你用不用它无关**，卡开着就在烧钱。
- **API**：成本 = token 量 × 单价。不用就不花。

国产模型 API 的量级（2026 年年中）：旗舰款约每百万 token 输入 4 元、输出 12 元；轻量款能低到十分之一。见 [[04-成本归因与每次成功任务成本]]。

**怎么算平衡点：**

1. 估你一个月要跑多少 token（输入输出分开算，输出通常贵三倍）
2. 乘 API 单价，得到「走 API 的月成本」
3. 估自建要几张卡（按显存和并发反推，见 [[01-GPU 容量规划]]），乘月租
4. 两边比

结论通常是这个形状：**流量小的时候 API 完胜，流量大到能把卡跑满，自建才开始划算。** 中间那段最难受——量不上不下，自建利用率上不去，API 又贵得肉疼。

> [!warning] 但这笔账经常不是钱说了算
> 数据不许出内网、要私有化交付、要改模型本身——这几条任何一条成立，平衡点算出来是多少都不重要，只能自建，见 [[01-数据驻留]]。
> 反过来，团队没有会运维 GPU 的人，那自建省下的钱大概率会以别的形式还回去。

### 推理侧的卡时都花在哪

同样是一小时，能服务多少请求，差别可以很大：

- **批处理没做好**：卡大部分时间在等，见 [[07-Continuous batching]]
- **KV cache 管理差**：并发上不去，显存先满了，见 [[04-PagedAttention 与分页显存]]
- **前缀没缓存**：同一段 system prompt 每次重算，见 [[05-Prefix caching]]

所以「一张卡每小时多少钱」只是分子，**分母是这一小时里你真的服务了多少请求**。同一张卡上，调优前后的单位成本差几倍是常事。这也是推理引擎存在的全部意义，见 [[00-一个模型到底是什么]]。

## 动手做

- [ ] 去三个不同的云上查同一张卡的当天报价，把价差记下来——这个价差比任何优化都大
- [ ] 拿你现在的月 token 用量，算走 API 的月成本
- [ ] 估自建要几张卡，按当天租价算月成本，找出平衡点在多少 token
- [ ] 跑一小时压测，算出「每一千次成功请求的卡时成本」，而不是只看卡时单价
- [ ] 把利用率也算进去：如果只有 30% 时间在跑，实际单位成本要除以 0.3

## 算学会了

- [ ] 看到「多少万卡时」能立刻换算成大致的钱
- [ ] 知道同一张卡在不同云上能差几倍，不会拿一个报价当行情
- [ ] 能算自建与 API 的平衡点，说得出你的量在平衡点哪一侧
- [ ] 报成本时报的是「每次成功任务多少钱」，不是「每卡时多少钱」
- [ ] 知道哪几条硬约束会让这笔账直接作废

## 坑

**只比卡时单价，不比利用率。** 便宜一半但只能跑三成利用率的方案，实际更贵。分母比分子重要。

**拿一个报价当行情。** 八倍价差意味着「H100 多少钱一小时」这个问题没有单一答案，问的时候必须带上从谁那里租。

**忘了输出比输入贵。** API 计价里输出通常是输入的三倍上下。估算时把两边分开算，不然会低估一大截，见 [[01-Prefill vs Decode]]。

**自建时按峰值买卡。** 按峰值配容量，谷时那些卡就是在烧钱。要么弹性伸缩，要么接受高峰降级，见 [[02-自动扩缩容]]。

**以为省下的钱是净赚。** 自建省的是 API 费，但换来了运维、扩容、故障处理的人力成本。团队没这个人的话，这笔账要重算。

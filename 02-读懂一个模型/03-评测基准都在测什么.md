随便打开一张 model card 都能抄到一串这样的数字：MMLU 88.6、GSM8K 94.2、HumanEval 81.7。它们是怎么算出来的，以及为什么不能直接回答「这个模型对我好不好用」。

## 一句话

每个基准只测一种很窄的能力，而且分数强烈依赖跑法；不把跑法看清楚，横向比较就是在比两件不同的事。

## 原理

### 常见基准，各测什么

现状一列是 2026 年 7 月的判断，会变，但「哪些已经饱和」这个分类方式不会：

| 基准 | 题型 | 测的是 | 现状 |
| --- | --- | --- | --- |
| MMLU | 57 学科多选题 | 知识广度 | **已饱和**，前沿模型平均约 92%，没区分度了 |
| MMLU-Pro | 同上但 10 选项、强制 CoT | 知识 + 抗干扰 | 接替 MMLU 的位置 |
| GSM8K | 小学数学应用题 | 多步算术推理 | **已刷穿** |
| MATH | 竞赛数学 | 符号推理 | 仍有区分度 |
| AIME | 高难竞赛数学 | 深度推理 | 推理模型的主战场 |
| GPQA-Diamond | 博士级科学问答 | 专家推理，防搜索 | 有区分度，非专家博士约 34% |
| HumanEval / MBPP | Python 函数补全 | 写小函数 | **已饱和** |
| SWE-bench Verified | 真实 GitHub issue 修复 | 端到端工程能力 | 区分度大，和生产表现相关性高 |
| IFEval | 带约束的指令 | 指令遵循 | 和产品体验相关性高 |
| RULER / 大海捞针 | 长文本里找信息 | 长上下文**有效性** | 和标称窗口常常差好几倍 |

> [!tip] 2026 年的三件套
> 知识看 **MMLU-Pro**，推理看 **GPQA-Diamond**，编码与 agent 看 **SWE-bench Verified**。后两个的共同点是**答案可验证**——这也是它们和生产表现相关性更高的原因。看到还在拿 MMLU 和 HumanEval 当卖点的宣传材料，基本可以判断它写得比较早，或者刻意挑了好看的。

最后一行值得单独说。上下文窗口这几年涨得非常猛：2026 年多数前沿模型标称 100 万 token 以上，Llama 4 Scout 甚至标到 1000 万。但**标称长度和有效长度是两回事**——塞得进去，不代表塞到那个位置还找得到。标称的只是 `max_position_embeddings` 这个配置项，有效长度得靠 RULER 这类测试量。

这一行的现状描述会过期，但那个判断不会：**容量早就不是难点了，「塞进去还能用」才是。** 见 [[07-位置编码与长度外推]]。

### 分数是怎么算出来的

**多选题**（MMLU、GPQA）有两种跑法，结果能差好几分：

- 比较模型给 A/B/C/D 四个 token 的 logprob，谁高算选谁——不需要模型「会输出格式」
- 让模型直接输出字母，再解析——考验指令遵循，弱模型会因为格式问题丢分

前面还会拼几个例题，叫 **few-shot**。`5-shot` 就是给 5 个做过的例子再问。shot 数不同分数不同，所以对比时必须确认是同一个设置。

**代码题**（HumanEval、MBPP）用 **pass@k**：让模型生成 k 份答案，只要有一份跑通全部单元测试就算这题过。所以 `pass@1` 和 `pass@10` 是完全不同的数字，后者天然高得多。看到 pass@k 先问 k 是几。

**数学题**（GSM8K、MATH）通常抽取最终答案做字符串比对。这带来一个副作用：开不开思维链差别巨大。同一个模型，直接答和让它一步步想，GSM8K 能差几十个点。

**开放问答**用 judge 模型打分，那套方法本身的可靠性问题见 [[04-Judge 校准]]。

> [!info] 为什么同一个模型在不同榜上分数不一样
> 不是有人作弊，是设置不同：shot 数、要不要 CoT、温度、提示词模板、答案抽取规则。这些都会动分数，而榜单未必写清楚。所以**跨榜比较基本没有意义**，只能在同一个榜里横向看。

### 三个让分数失真的东西

**污染。** 基准题目在互联网上公开，于是进了下一代模型的预训练数据。模型不是推理出来的，是背出来的。这没法彻底避免——这也是为什么新基准不断出现、老基准不断贬值。GPQA 名字里的 "Google-proof" 就是在对抗这件事。

**饱和。** 一个基准用久了，头部模型会挤在很窄的区间里，差一两分基本是噪声。到这一步它就只能用来筛掉差的，不能用来选出好的——MMLU 和 HumanEval 都已经走完了这条路。

**提示词敏感。** 同一个模型换个提示词模板，分数波动几个点很常见。所以榜单前几名之间的微小差距，多半在噪声范围内。

> [!warning] 最该记住的一条
> 基准分数高，只说明它在**那批题**上表现好。你的任务是客服工单分类、是从 PDF 里抽字段、是按你们的 schema 输出 JSON——这些没有任何一个基准在测。
> 基准的正确用法是**缩小候选**，从几十个模型收到三五个；最终选谁必须拿你自己的数据跑，见 [[01-Golden set]]。

### 推理模型让事情更复杂了

会「思考」的模型（先输出一段推理再给答案）在数学和代码基准上分数明显更高，但：

- 它吐的 token 多几倍，成本和延迟跟着涨，见 [[04-推理模型的成本与延迟曲线]]
- 有的榜单允许它想很久，有的限制预算，规则不同分数不可比
- 在简单任务上它未必更好，还更贵

所以看到「某模型 AIME 提升 20 个点」，先问它花了多少 token。

## 动手做

- [ ] 挑一个基准，去看它的原始题目长什么样——很多人对 MMLU 的想象和实际题目差很远
- [ ] 拿同一个模型，用 0-shot 和 5-shot 各跑一次 MMLU 的一个子集，记录分差
- [ ] 同一批数学题，开 CoT 和不开各跑一次，看差多少
- [ ] 用 `lm-evaluation-harness` 复现一个官方报的分数，看能不能对上——对不上的地方就是设置差异
- [ ] 从自己业务里挑 30 条真实样本，跑三个基准分接近的模型，看排序和榜单一不一致

## 算学会了

- [ ] 看到一个分数，会先问 shot 数、有没有 CoT、pass@k 的 k 是几
- [ ] 能解释为什么跨榜单比较没意义
- [ ] 知道哪些基准已经饱和、不再有区分度
- [ ] 明白基准的作用是缩小候选，不是做最终决定
- [ ] 看到推理模型的高分，会追问它花了多少 token

## 坑

**拿基准分当采购依据。** 分数最高的模型在你的任务上排第三，这种事非常常见。基准和你的任务分布不一样，仅此而已。

**跨榜比较。** A 榜的 MMLU 和 B 榜的 MMLU 可能用了不同的 shot 数和抽取规则。看着都叫 MMLU，其实是两个测试。

**忽略污染。** 一个新模型在老基准上分数惊人，第一反应该是「训练数据里有没有这批题」，而不是「它好强」。

**把标称上下文当有效上下文。** 标称的是「塞得进」，不是「塞进去还找得到」。要看长上下文基准的实测值。

**只看平均分。** MMLU 是 57 个学科的平均。你只关心医疗，那就该看医疗那个子项，而不是总分。

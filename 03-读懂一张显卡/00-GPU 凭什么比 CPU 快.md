模型跑在 GPU 上，几乎没人问过为什么不是 CPU。答案不是「GPU 更快」——它在很多事上比 CPU 慢得多。

## 一句话

GPU 用几万个弱核换掉了 CPU 的几十个强核，只在「一万件一模一样的事同时做」这一种场景下赢，而矩阵乘法恰好就是这种场景。

## 原理

### 两种造芯片的思路

![[CPU 与 GPU 的分工.excalidraw.md|700]]

**CPU 的假设是：任务复杂、一件一件来。** 所以它把晶体管砸在让单个核尽可能聪明——分支预测猜你下一步要跳哪、乱序执行把不相关的指令提前算、几十 MB 的缓存兜住内存延迟。一颗现代服务器 CPU 几十个核，每个核都是这么武装到牙齿的。

**GPU 的假设是：任务简单、但有几万份。** 所以它反过来——把每个核削到很弱，砍掉分支预测、砍掉大缓存，省下来的晶体管拿去堆核数。一张 H100 上有上万个计算单元。

关键在于这些核**不是各干各的**：它们被编成组，同一时刻执行**同一条指令**，只是喂给各自不同的数据。这套模型叫 SIMT（单指令多线程）。

所以 GPU 快的前提是「大家干的活一模一样」。一旦同一组里的线程走了不同分支——有的进 if 有的进 else——硬件只能让两拨轮流跑，另一拨干等着。这叫**线程束分化**，是 GPU 编程里最典型的性能塌方。

> [!info] 一个直观的比方
> CPU 是几十个博士，每人能独立解一道难题，遇到岔路自己判断。
> GPU 是一万个小学生，排成方阵，老师喊一声「第 3 步：把手里的两个数相乘」，全体同时照做。喊一声就完成一万次乘法——但前提是这一万个人这一步真的干同一件事。有人要算减法？对不起，先等着。

### 为什么矩阵乘法正好合适

模型推理的绝大部分工作量是矩阵乘法，见 [[01-Transformer 与 attention]]。一次矩阵乘法拆开看，是几百万次彼此**完全独立**的「乘一下、加进去」：

- 没有分支——每个元素的算法一模一样
- 没有依赖——算第 5 个元素不需要知道第 4 个的结果
- 数量巨大——几百万到几十亿次

三条正好命中 GPU 的强项，也正好是 CPU 的弱项：CPU 那些分支预测、乱序执行的本事在这儿一点用没有，白白占着晶体管。

这就是为什么不是「GPU 比 CPU 快多少倍」的问题——**在这个特定形状的任务上，两者根本不在一个量级；换个形状的任务，结论可能完全反过来。**

### CUDA 是什么，为什么绕不开

硬件再好也得有人能使唤它。CUDA 是 NVIDIA 的那一整套东西：写 GPU 代码的语言扩展、编译器、驱动，以及最重要的——上面那一层层库。

`cuBLAS` 管矩阵乘法、`cuDNN` 管神经网络算子、`NCCL` 管多卡通信、`Nsight` 管性能分析。PyTorch 你写的那行 `a @ b`，最终落到的是 cuBLAS 里某个被手工调优过很多年的 kernel。

这套东西积累了近二十年，是 NVIDIA 真正的护城河——**不在硬件，在这上面**。别家的卡就算算力标称追上了，实际能发挥出多少，取决于它的软件栈成熟到什么程度，见 [[05-国产卡与生态差距]]。

### 光有算力不够

一个常见的误解是拿 TFLOPS 排卡：谁的算力数字大谁强。

实际上算力经常是用不满的，因为数据喂不进去。GPU 的计算单元快，但数据得先从显存搬过来，而**显存带宽的增长远远跟不上算力的增长**。绝大多数时候，卡不是算不动，是在等数据。

这件事对推理成本的影响比算力大得多，展开见 [[02-算力经常用不满：两种瓶颈]]。

## 坑

**拿 TFLOPS 单独排卡。** 算力是标称的天花板，实际发挥受带宽和软件栈两头掣肘。两张标称算力相同的卡，实测差一倍很常见。

**以为 GPU 什么都快。** 串行逻辑、大量分支、小数据量的任务，GPU 可能比 CPU 慢。数据在 CPU 和 GPU 之间来回搬的开销也经常被忽略。

**忽略软件栈。** 「这张卡算力是 H100 的 80%」和「这张卡跑你的模型能到 H100 的 80%」是两回事，中间隔着整个编译器和算子库。

用户没有输入任何恶意内容。恶意指令藏在他让 agent 读的那份 PDF 里——而这占了 2026 年观测到的注入事件的一半以上。

## 一句话

不可信内容有六个入口，用户输入只是其中一个；**把检索文档、工具返回、网页内容一律当数据而不是指令**，是这一节唯一的立场。

## 原理

### 直接注入 vs 间接注入

**直接注入**是用户自己在输入框里写「忘掉上面的规则」。它显眼、好防、而且用户是攻击者本人。

**间接注入**是恶意指令藏在 agent 读到的内容里：

![[不可信内容的六个入口.excalidraw.md|700]]

有统计称，**2026 年观测到的注入事件里超过 55% 是间接的**。原因很直接——间接注入有三个优势：

- **用户看不见**，他只是让 agent 「总结一下这份文档」
- **走的是可信数据通道**，绕过了针对用户输入的所有过滤
- **可以提前埋设**，攻击者不需要在场

### 攻击面随功能增长

每加一个数据源就多一个入口：

| 加了什么 | 新增的入口 |
| --- | --- |
| RAG | 知识库里的任何一篇文档 |
| 网页浏览 | 任何被访问的页面 |
| 邮件处理 | 任何一封收到的邮件 |
| 代码仓库读取 | 注释、README、issue |
| MCP / 第三方工具 | 工具的返回值、工具描述本身 |
| 多 agent | 别的 agent 的输出 |

**最后两行最容易被忽略。** 工具描述本身如果来自外部（比如动态加载的 MCP server），它就是一个注入面，见 [[08-MCP]]。

### 自己写 20 条载荷

roadmap 把这条单列为「本节最重要的一个动作」，理由是：**只有针对你自己系统结构的载荷才测得出真问题**。

八个类别，各写两三条：

| 类别 | 测什么 |
| --- | --- |
| **指令覆盖** | 让它忽略系统提示 |
| **角色劫持** | 伪造对话结构、假扮系统消息 |
| **信息外泄** | 诱导它吐出系统提示或其他用户的数据 |
| **工具滥用** | 诱导它调用不该调的工具，尤其写操作 |
| **越权检索** | 诱导它去查它无权访问的东西 |
| **外泄通道** | 诱导它把数据编进一个 URL 里（markdown 图片是经典形态） |
| **编码混淆** | 用 base64、零宽字符、同形异义字包装上面这些 |
| **多轮铺垫** | 分几轮慢慢建立一个错误的前提 |

**每类都要埋在不同的入口试一遍**——同一条载荷，放在用户输入里可能被拦住，放在检索文档里可能就过了。

> [!warning] 种子载荷必须自己想
> 让模型帮你生成攻击载荷，生成出来的往往是它**自己容易防住**的那种。
> 真正有效的载荷来自理解你系统的具体结构：你的系统提示长什么样、有哪些写操作工具、检索了哪些源、输出会被渲染成什么。
> 模型可以帮你扩写变体，但那 20 条种子得自己写。

### 穿透率是主指标

跑完之后报的是**穿透率**——多少条攻击成功了，并按严重级别分开，见 [[03-对抗测试集]]：

| 级别 | 例子 | 门禁 |
| --- | --- | --- |
| critical | 泄露系统提示、跨租户数据、执行了未授权写操作 | **必须为 0** |
| high | 输出了不该输出的内容但无实际损害 | 有阈值且不许上升 |
| medium | 行为异常但无风险 | 记录趋势 |

critical 那档接进 CI，见 [[02-回归测试与 CI 门禁]]。

### 防不住到什么程度

> [!danger] 训练出来的抗性到不了「够用」
> 有研究指出：**训练模型抵抗注入能降低攻击成功率，但达不到高风险操作可接受的安全阈值**——即便是防护最好的模型，攻击成功率仍在 **1% 左右**。
>
> 1% 不是 0。一天一万次调用就是一百次成功。
>
> 所以结论很明确：**任何依赖模型自身判断的防御都是概率性的**，高风险操作必须有确定性的那一层兜底，见 [[02-纵深防御]]。

### 几类防御手段

按性质分：

- **结构化分隔 / spotlighting**——对外部内容做结构变换，让模型能区分「数据」和「指令」。概率性，但便宜且有效
- **模型侧对齐**（StruQ、SecAlign 这类）——训练模型识别并拒绝注入。概率性
- **监督 agent**（GuardAgent 这类）——用第二个模型监控行为偏离。概率性，且自己也可能被绕
- **最小权限**——它拿不到的权限就用不了。**确定性**
- **人确认**——**确定性**，也是唯一真正可靠的那一层

**前三种降低概率，后两种限制爆炸半径。** 两类都要有。

## 坑

**只防用户输入。** 一半以上的注入走的是别的入口。

**让模型生成攻击载荷。** 生成的是它自己容易防住的那种。

**忽略工具描述本身。** 动态加载的工具描述是一个真实的注入面。

**以为对齐好的模型就安全了。** 1% 的成功率在高频调用下是个大数字。

**只测一遍就完事。** 攻击面随功能增长，每加一个数据源都要补测。

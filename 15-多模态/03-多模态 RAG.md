文档里的关键信息经常在图表里。纯文本 RAG 会把这些图当成不存在——用户问「第三季度趋势」，那张折线图明明就在那儿，却检索不到。

## 一句话

多模态 RAG 的核心选择是**在索引时把图转成文字，还是在检索时直接匹配图像**——前者简单可控，后者上限更高。

## 原理

### 两条路线

| | **图转文字后索引** | **直接索引图像** |
| --- | --- | --- |
| 做法 | 用视觉模型给每张图生成描述，索引描述 | 用图文共享的 embedding 直接索引图 |
| 检索 | 走普通文本检索，见 [[03-Hybrid search（dense + BM25 + RRF）]] | 用文本查询在图像向量里搜 |
| 成本 | 索引时贵一次，检索便宜 | 索引便宜，但要跨模态 embedding |
| 可控性 | **高**——描述可读、可审、可改 | 低——出问题不好排查 |
| 上限 | 受限于描述质量 | **更高** |

**默认从第一条开始。** 它复用了整套现有的文本检索基建、可调试、失败时看得懂原因。第二条在图像占主导的场景（比如产品图库）才更划算。

### 图转文字，描述怎么写

这一步的质量决定一切。经验：

**别只写「这是一张折线图」。** 要把图里的信息展开：

```
图表类型：折线图
标题：2025 年各季度营收
数据：Q1 1200 万，Q2 1450 万，Q3 1380 万，Q4 1890 万
趋势：整体上升，Q3 有小幅回落
坐标轴：横轴为季度，纵轴为营收（万元）
```

这样的描述能被文本检索命中「Q3 回落」「营收趋势」这类查询，而「这是一张折线图」什么也命中不了。

**表格要转成结构化文本**（Markdown 表格），别转成散文——散文丢了行列关系。

### 上下文要跟着图走

图不是孤立的，它周围的文字（图注、正文里提到它的段落）往往是理解它的关键。索引时应该：

- 把**图注**和描述拼在一起
- 保留**所属章节标题**
- 记住它在文档的哪一页

这和文本 chunk 保留上下文是同一个道理，见 [[01-Chunking 四种策略]]。

### 检索到之后送什么

命中一张图之后，送给模型的可以是：

| 送什么 | 什么时候 |
| --- | --- |
| **只送描述** | 描述够详细、成本敏感时 |
| **送原图** | 需要精确读数、看细节时 |
| **描述 + 原图** | 最稳，但最贵 |

**注意送原图意味着几千个视觉 token**，见 [[01-图像与音频的 token 计算]]。多命中几张图，上下文预算就爆了，见 [[02-Context engineering：上下文即预算]]。

**一个实用策略**：检索阶段用描述，只对最相关的一到两张送原图。

### 引用要指到图

用户看到「Q3 营收 1380 万」，要能点回那张原图。所以：

- 每个 chunk 记住来源图的**页码和位置**
- 回答里的引用能渲染成图片缩略图

**这比文本引用更重要**——因为从图里读出的数字，用户更没法凭直觉判断对错，见 [[06-幽灵文档测试]]。

### 怎么评估

golden set 要专门包含**只能从图里回答的问题**，见 [[01-Golden set]]：

- 「Q3 的营收是多少」——答案只在折线图里
- 「哪个季度环比下降」——需要读趋势
- 「表格第三行第二列是什么」——需要读表格结构

**如果不专门构造这类问题，评估会完全看不出多模态检索有没有用**——因为文本 RAG 在纯文本问题上表现一样好。

## 动手做

- [ ] 统计你的文档里图表承载了多少关键信息，判断值不值得做
- [ ] 用视觉模型给图生成描述，对比「一句话描述」和「展开数据」的检索命中率
- [ ] 把表格转成 Markdown 而非散文，测检索效果差异
- [ ] 索引时把图注和章节标题拼进去
- [ ] 构造一批「只能从图里回答」的 golden 问题
- [ ] 对比「只送描述」和「送原图」的答案质量与成本
- [ ] 实现引用回跳到原图的位置

## 算学会了

- [ ] 明确选了「转文字」还是「直接索引图像」，且说得出理由
- [ ] 图描述展开了数据，不是一句话概括
- [ ] 表格转成了结构化文本
- [ ] golden set 里有只能从图回答的问题
- [ ] 知道送原图的 token 代价，且有策略控制

## 坑

**直接上跨模态 embedding。** 图转文字这条路更可控、能复用现有基建，多数场景够用。

**图描述写成一句话。** 「这是一张折线图」什么查询都命中不了。

**表格转成散文。** 丢了行列关系，模型读不出「第三行第二列」。

**命中的图全送原图。** 几千视觉 token 一张，几张就爆预算。

**golden set 里没有图专属问题。** 评估完全看不出多模态有没有用。

「格式错了，请重新输出」——这句提示词几乎没有信息量，模型只能重新猜一遍。而把校验器的原始报错原样贴给它，一次就能修对。

## 一句话

修复的关键不是重试，是**带着具体报错重试**；而且要有次数上限，因为三次修不好的，第四次多半也修不好。

## 原理

### 定向修复 vs 盲目重试

对比一下：

```text
✗ 盲目重试
   「上次的输出格式不对，请重新生成。」
   → 模型不知道哪里错了，重新猜

✓ 定向修复
   「你上次的输出：{原样贴回}
     校验失败：$.items[2].amount — expected number, got string "1,280.00"
     请只修正这个问题。」
   → 模型知道是第 3 项的金额带了千分位逗号，直接改
```

**差别在于信息量。** 第二种把校验器的原始报错、出错的路径、期望与实际都给了模型，它不需要猜。

一次修复成功率通常能从三四成提到八成以上——这是投入产出比很高的一处改动。

### 报错要原样给

不要把校验器的报错「翻译」成人话再给模型。原始报错里的结构化信息（JSON path、期望类型、实际值）恰恰是最有用的部分。

好的报错至少包含：

| 要素 | 例子 |
| --- | --- |
| 出错位置 | `$.items[2].amount` |
| 期望 | `number` |
| 实际 | `string "1,280.00"` |
| 约束 | `minimum: 0` |

**如果你的校验器给不出这些，先换一个校验器**。这比优化提示词有用得多。

### 只贴错误的部分

输出很长时，把整段贴回去很浪费上下文，而且会稀释注意力，见 [[02-Context engineering：上下文即预算]]。

更好的做法是**只贴出错的片段加上下文几行**，配上完整的错误路径。模型能定位到，就不需要看全文。

### 次数上限与退出

修复循环必须有上限，通常 2–3 次。理由：

- 修复 N 次的成功率是快速递减的
- 每次修复都在花钱，见 [[04-成本归因与每次成功任务成本]]
- 失控的修复循环是 agent 空转的典型形态，见 [[02-终止条件]]

**用完次数之后不是失败，是降级。** 走降级链的下一级，见 [[04-降级链]]。

### 一个容易忽略的情况

修复循环最尴尬的失败是**模型每次都在同一处犯同样的错**。这通常说明：

- schema 本身有歧义（两个字段名太像、类型定义不清）
- 输入里根本就没有那个信息（模型只能编）
- 提示词和 schema 互相矛盾

**检测方法**：统计「同一个校验错误连续出现两次」的比例。这个比例高就说明问题不在模型，在 schema 或输入。**这时候继续修复是浪费**，应该直接降级或转人工。

### 修复也要打点

每次修复都要记录：

- 第几次修复
- 校验器报了什么错
- 修没修成

这些数据的用处：

**错误类型分布**告诉你 schema 哪里设计得不好——某个字段反复出错，说明它的定义有问题。

**一次修复成功率**是修复循环健康度的直接指标，见 [[02-必打字段清单]]。

**修复占总成本比例**——高的话说明上游（提示词、schema、约束解码）该改进了，见 [[01-结构化输出三档]]。

### 别用它掩盖上游问题

修复循环是安全网，不是主要手段。如果修复触发率很高（比如超过三成），正确的反应是回头改上游：

1. 上约束解码，把格式问题从源头消掉
2. 简化 schema
3. 改进字段命名
4. 换更强的模型

**修复循环应该是偶尔触发的兜底，不是常规路径。**

## 动手做

- [ ] 把「格式错了请重试」改成原始报错回灌，对比一次修复成功率
- [ ] 只贴出错片段而非全文，看修复成功率和 token 消耗的变化
- [ ] 设 3 次上限，用完转降级链，验证不会无限循环
- [ ] 统计「同一错误连续出现两次」的比例，找出 schema 里有歧义的字段
- [ ] 统计修复触发率，超过三成的话回头改上游
- [ ] 算修复占总成本的比例

## 算学会了

- [ ] 修复提示里带的是具体报错，不是「格式错了」
- [ ] 修复有次数上限，用完走降级而不是失败
- [ ] 会用「同一错误重复出现」判断问题在 schema 而非模型
- [ ] 修复触发率、一次修复成功率都在指标里
- [ ] 把修复当兜底而非常规路径

## 坑

**重试不带报错。** 模型只能重新猜，成功率和第一次差不多。

**把报错翻译成人话。** 结构化信息（路径、类型、约束）才是最有用的部分。

**无限修复。** 三次不行就该降级，继续只是烧钱。

**用修复掩盖 schema 问题。** 反复在同一处出错，说明 schema 该改了。

**不统计修复触发率。** 修复成了常规路径而不自知，成本悄悄翻倍。

「让它记住用户说过的话」听着是一个功能，实际是三层存储加两条搬运规则。

## 一句话

窗口内、近期可召回、长期存档——三层的代价依次递减；设计的全部内容是**什么该往下沉，什么该被取回来**。

## 原理

### 三层

![[记忆的三层.excalidraw.md|632]]

这个分层最有影响力的表述来自 MemGPT / Letta，它把 LLM 类比成操作系统在管自己的内存：

| 层 | 类比 | 里面装什么 | 代价 |
| --- | --- | --- | --- |
| **主上下文** | RAM | 这一轮真正送进模型的 | 最贵：占预算、会衰减 |
| **近期召回** | 最近打开的文件 | 最近几轮对话 | 中等：存着不花钱，取回才花 |
| **长期存档** | 磁盘 | 跨会话的事实与偏好 | 最便宜：完全不占预算 |

只有第一层是模型「看得见」的。另外两层要通过检索或工具调用才能进来。

**理解这一点就理解了记忆系统的全部难点**：模型不知道自己不知道什么。存档里有的东西，如果检索没取回来，对它而言就等于不存在。

### 和上下文工程的分工

这两件事经常被混为一谈：

| | 管什么 | 时间尺度 |
| --- | --- | --- |
| 上下文工程 | 单次请求内窗口怎么分配 | 一次请求 / 一个会话 |
| 记忆系统 | **跨会话**的持久化 | 天、周、月 |

上下文工程解决「这一轮塞什么」，见 [[02-Context engineering：上下文即预算]]；记忆系统解决「下周他再来，我还记得什么」。

压缩（compaction）站在两者交界处——它把窗口里的东西往下沉，见 [[03-Compaction 与外部记忆文件]]。

### 两条搬运规则

**往下沉（什么该被记住）。** 不是所有东西都值得存。判据见 [[02-记忆写入策略]]，核心是：**只存会被反复用到的、稳定的事实**，而不是把对话原文倒进去。

**取回来（什么该被召回）。** 每一轮要判断存档里有没有和当前话题相关的东西。做法见 [[03-记忆检索与召回]]。

这两条都不是「越多越好」——存得多会脏，召回得多会挤占预算并引入干扰。

### 记什么

一个够用的分类：

| 类型 | 例子 | 变化频率 |
| --- | --- | --- |
| **事实型** | 用户在上海、公司用 PostgreSQL | 低 |
| **偏好型** | 喜欢简短回答、要中文 | 低 |
| **状态型** | 这个工单还在处理中 | 高 |
| **情节型** | 上次问过退款政策 | 一次性 |

前两类值得长期存，第三类要有过期机制（见 [[05-遗忘与过期机制]]），第四类多数不值得存——它的价值随时间快速衰减。

**最常见的设计错误是把第四类当第一类存**，结果存档里全是「用户在 3 月 5 日问了一个问题」这种噪声。

### 两种实现路线

社区里大致分两派：

**记忆层**（Mem0 这类）——一个可以挂在任何框架上的组件，负责存和取。适合「记住这个用户」是产品功能的场景。

**有状态运行时**（Letta 这类）——把记忆做成 agent 运行时的一部分，暴露可编辑的记忆块，agent 自己管自己的记忆。适合需要长时程连贯性的自主 agent。

选哪个取决于**记忆是功能还是骨架**。前者挂一个组件就够，后者要重构整个运行方式。

### 从最简单的开始

不必一上来就上框架。多数场景下，这个就够用很久了：

```text
外部记忆文件（每个用户一份）
├── 事实：结构化的键值对
├── 偏好：结构化的键值对
└── 摘要：最近 N 次会话的要点
```

好处是可检查、可人工修正、可版本化。等它撑不住了再考虑向量检索和专门的记忆框架，见 [[03-记忆检索与召回]]。

## 动手做

- [ ] 给一个多会话场景设计三层结构，明确各层存什么
- [ ] 用一个文件当长期存档跑通最小闭环：写入 → 下次会话读回
- [ ] 把四类记忆分开存，观察一周后各类的数量增长
- [ ] 统计存档里有多少条从来没被召回过——那部分就是白存的
- [ ] 做一次「上次说过的偏好这次还生不生效」测试
- [ ] 对比有无长期记忆时的多会话任务成功率

## 算学会了

- [ ] 能说清三层各自的代价，以及为什么模型只看得见第一层
- [ ] 分得清上下文工程和记忆系统各管什么
- [ ] 会按四类分开处理，不把情节型当事实型存
- [ ] 知道存得多会脏、召回得多会干扰
- [ ] 从文件起步，而不是一上来就上框架

## 坑

**把对话原文全存进去。** 存档很快变成一堆噪声，检索质量崩掉。

**只存不删。** 状态型记忆过期之后还在，会把模型带偏，见 [[05-遗忘与过期机制]]。

**以为存了就等于记住了。** 存档里有但检索不出来，对模型而言不存在。

**一上来就上记忆框架。** 多数场景一个文件加简单检索能撑很久，框架带来的复杂度未必值。

**不统计召回率。** 存了一堆从没被用过的东西，成本白花还拖慢检索。

Megatron、DeepSpeed、FSDP、TRL、LLaMA-Factory——名字一堆，其实分成两拨，而你大概率只会碰到其中一拨。

## 一句话

预训练框架解决的是「一张卡放不下」，微调框架解决的是「让普通人也能训」；AI Engineer 日常碰到的几乎全是后者。

## 原理

### 先说为什么需要框架

训一个 70B 的模型，光算显存这一笔账就够劝退：

| 要存的东西 | FP16/BF16 下的大小 |
| --- | --- |
| 权重 | 140 GB |
| 梯度 | 140 GB |
| Adam 优化器状态（两份统计量，通常 FP32） | 560 GB |
| 激活值 | 看 batch 和序列长度，几十到几百 GB |

加起来 840 GB 起步。而单卡显存是 80–200 GB 这个量级（H100 是 80 GB，后面的卡更大但没有大一个数量级）。**差了十倍上下，不是调调参数能解决的**，必须把模型本身拆到多张卡上。框架存在的理由就这一条。

卡会换代，这笔账的结构不会变：**训练要存的东西是权重的六倍往上，而单卡显存永远追不上模型增长的速度。**

顺便，这也解释了那个经典的天真估算为什么错得离谱：推理只需要装权重（140 GB），训练要装上面全部。同一个模型，两本完全不同的账，见 [[00-一个模型到底是什么]]。

### 四种切法

![[一张卡放不下怎么切.excalidraw.md|700]]

**数据并行（DP）** 最朴素：每张卡放一整份模型，各自吃不同的数据，算完梯度对一次平均。它只解决「训得快」，不解决「放不下」——每张卡该装不下还是装不下。

**ZeRO / FSDP** 是 DP 的进化版，思路是：既然每张卡都存着一模一样的东西，那就别都存了。把优化器状态、梯度、参数依次切开分到各卡，用到谁的部分再从谁那里取。ZeRO 分三级，切得一级比一级狠。这是今天最常用的一种。

**张量并行（TP）** 把单个权重矩阵横着切开，四张卡各算一部分再拼起来。它能把单层的显存压下去，代价是每算一层就得通信一次——所以基本只在一台机器内部用，跨机器带宽扛不住。

**流水线并行（PP）** 把层分段，卡 1 管第 1–8 层，卡 2 管第 9–16 层，数据像流水线一样往下走。问题是气泡：卡 4 干活的时候卡 1 在发呆。要靠把 batch 切成小份错开来填。

实际训大模型时这几种是**叠着用**的，叫 3D 并行（DP + TP + PP），长上下文再加一维序列并行就成了 4D。

### 演进：从「能训」到「训得动 70B」

| 年份 | 出现的东西 | 解决了什么 |
| --- | --- | --- |
| 2017 | [Horovod](https://arxiv.org/abs/1802.05799)（Uber） | 把多机数据并行做得好用，此前要手写通信 |
| 2018 | [GPipe](https://arxiv.org/abs/1811.06965)（Google） | 流水线并行，用微批切分填气泡 |
| 2019 | [Megatron-LM](https://arxiv.org/abs/1909.08053)（NVIDIA） | 张量并行，单层也能切开 |
| 2019 | [ZeRO](https://arxiv.org/abs/1910.02054)（Microsoft，DeepSpeed） | 消除数据并行里的冗余存储 |
| 2021 | Megatron-DeepSpeed 等组合 | 3D 并行成为训千亿模型的标配 |
| 2022 | PyTorch **FSDP** | 把 ZeRO-3 那套原生化，不用装第三方框架 |
| 2024 | [TorchTitan](https://arxiv.org/abs/2410.06511)（PyTorch 官方） | 4D 并行的干净参考实现，代码可读 |

这条线的主题是**逐步把「显存装不下」这件事从研究问题变成配置问题**。2019 年要训个百亿模型得自己写并行策略，现在改几行 YAML。

截至 2026 年 7 月，生产上的三分格局和各自的适用场景：

| 框架 | 什么时候选它 |
| --- | --- |
| **FSDP2**（PyTorch 原生） | 默认选项。用 DTensor 做张量级切分，在现代 PyTorch 环境里阻力最小。TorchTitan 是它的旗舰实现 |
| **Megatron-LM**（NVIDIA） | 千亿以上的前沿规模，每一个百分点的效率都要抠。已发表的前沿模型基本都用它的 3D 并行——Llama 3 405B 就是在 16K 张 H100 上用这套栈训的 |
| **DeepSpeed**（Microsoft） | 训 MoE、需要 ZeRO-3 配大量 CPU offload、或者团队已有积累 |

> [!info] 一个正在发生的变化
> 训练框架和推理引擎的边界在消融——训练框架开始带推理能力，推理引擎开始带训练能力。RL 后训练是主要推手：像 veRL 这样的 RL 框架同时挂着训练后端（FSDP2、Megatron）和 rollout 生成后端（vLLM、SGLang、TensorRT-LLM），一套流程里两边都要用。
> 另一条线是端到端 FP8：让模型从预训练第一步到最后一个生成 token 全程保持 FP8，把栈统一起来。这条还在路上。

上面这张表会随版本变，但选择逻辑不太会变：**默认用原生的那个，规模顶到天花板才换专用的，有特殊结构（MoE）才找对应的。**

### 另一拨：微调栈

上面那些是给预训练用的。你更可能碰到的是这些：

| 工具 | 干什么 | 什么时候用 |
| --- | --- | --- |
| [TRL](https://github.com/huggingface/trl)（HuggingFace） | SFT、DPO、GRPO 等训练器 | 想写代码控制细节 |
| [PEFT](https://github.com/huggingface/peft)（HuggingFace） | LoRA、QLoRA 等省显存的微调法 | 几乎总是要用，见 [[03-LoRA 与 QLoRA]] |
| [LLaMA-Factory](https://arxiv.org/abs/2403.13372) | 配置化的一站式微调，带 Web UI | 想快速试，不想写训练循环 |
| Axolotl | YAML 驱动的微调 | 同上，社区配方多 |
| Unsloth | 单卡场景的速度与显存优化 | 只有一张消费卡 |
| veRL、OpenRLHF | 大规模 RL 训练（PPO、GRPO） | 要做强化学习后训练 |

两拨的分界线很清楚：**预训练框架的问题是「怎么把模型拆到几千张卡上」，微调框架的问题是「怎么让一两张卡也能训」。** 后者靠的是 LoRA 这类只训一小部分参数的方法，把那 840 GB 的账压到几十 GB。

> [!tip] 一个省事的判断
> 除非你在训基座模型，否则 Megatron 和 DeepSpeed 这两个名字你只需要认得，不需要会用。日常需要动手的是 PEFT 加上 TRL 或 LLaMA-Factory 里的一个。

### 为什么这些还是值得知道

不训模型也会撞上它们：

- **读技术报告时**。「我们用 3D 并行在上万张卡上训了两个月」——知道这几个词才能判断这个模型是什么量级的投入。
- **估成本时**。别人报的训练成本合不合理，看并行策略和卡时就能大致判断。
- **做 LoRA 时**。为什么 LoRA 能把显存需求砍掉一个量级？因为它冻住原权重，只训一小撮新参数，于是上面那张表里最大的两项——梯度和优化器状态——只按新参数算。理解了并行那笔账，LoRA 省的到底是哪部分就一目了然。

## 动手做

- [ ] 手算一遍你想微调的模型全参训练要多少显存（权重 + 梯度 + 优化器状态），再和你手上的卡对比
- [ ] 同一个模型同一批数据，分别用全参微调和 LoRA 跑，用 `nvidia-smi` 记录峰值显存，验证省的是哪几项
- [ ] 用 LLaMA-Factory 或 TRL 跑通一次最小的 SFT，哪怕只有 100 条数据——目的是把流程走通，不是要效果
- [ ] 找一篇大模型技术报告，把它的并行配置抄出来（TP 几、PP 几、DP 几），算算总卡数对不对得上

## 算学会了

- [ ] 能说出训练显存的四个去处，以及为什么优化器状态通常是最大的一项
- [ ] 能解释 DP 和 ZeRO/FSDP 的区别，以及为什么前者不解决「放不下」
- [ ] 知道 TP 为什么基本只在单机内用
- [ ] 看到「3D 并行」能说出是哪三个维度
- [ ] 能解释 LoRA 省显存省在哪一项上

## 坑

**以为数据并行能解决显存不够。** DP 是让训练更快，不是让模型放得下。这两件事经常被混为一谈，然后加卡加到破产也没解决问题。

**照搬别人的并行配置。** TP 的大小和你的机内互联带宽强相关，别人 8 卡 NVLink 上跑得好的配置，换到 PCIe 机器上可能慢一半。

**忘了激活值。** 前面三项好算，激活值随 batch size 和序列长度变，最容易在算完账后被现实打脸。梯度检查点（gradient checkpointing）就是用算力换这部分显存的。

**以为框架越新越该用。** TorchTitan 代码干净适合学习，但生产上成熟度和社区配方还是 Megatron、DeepSpeed 那边厚。学和用可以是两个选择。

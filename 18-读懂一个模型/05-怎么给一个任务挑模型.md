把前面几篇的东西变成一个决定：这个任务，用哪个模型。

## 一句话

先用硬约束砍掉大半，再用榜单收到三五个，最后拿自己的几十条真实样本定夺——顺序反了就会在没意义的比较上耗掉几周。

## 原理

### 先砍硬约束

这一步不涉及任何「哪个更聪明」的判断，纯粹是排除法，但能砍掉一大半候选：

**能不能用闭源 API。** 数据不许出境、不许出内网的话，闭源模型直接出局，剩下的全是开源权重，见 [[01-数据驻留]]。

**许可证允不允许你这么用。** 有的禁商用，有的按月活设门槛，有的要求衍生模型署名。这条查起来两分钟，漏了会很麻烦，见 [[04-模型权重来源]]。

**上下文要多长。** 注意是**有效**长度不是标称长度——2026 年标称百万 token 已是常态，但能塞进去和塞进去还找得到是两回事，见 [[03-评测基准都在测什么]] 里长上下文那部分。

**延迟能忍多少。** 要求首字 500ms 内的场景，会思考的推理模型基本没戏，见 [[04-推理模型的成本与延迟曲线]]。

**自建还是调 API。** 自建的话显存放不下就是放不下，见 [[01-GPU 容量规划]]。

### 再用榜单收窄

砍完之后通常还剩十几个。用榜单收到三五个，规则见 [[04-排行榜怎么读]]：挑任务形态最接近的那个榜，前几名当并列处理。

**别在这一步纠结。** 榜单的分辨率不足以区分第 2 和第 5，多花的时间都浪费了。目标只是拿到一个短名单。

### 最后拿自己的数据定夺

这一步不能省，而且它比前两步加起来都重要。

**攒 20–50 条真实样本。** 从线上流量里抽，不要编——编出来的样本会不自觉地避开真实数据里那些脏的、歧义的、格式怪的情况，而模型恰恰是在那些地方分高下。

**标注期望结果。** 不需要完美，「这个算对、这个算错」就够。

**同一套提示词跑全部候选。** 注意每个模型都要用它自己的 chat template，见 [[02-开源权重包里有什么]]。

**记四个数**：准确率、单次成本、P95 延迟、失败模式。最后一项最容易被忽略却最有用——两个准确率都是 85% 的模型，一个错在边缘情况、一个错在最常见的路径上，对产品的意义完全不同。

然后这批样本别扔，它就是你的 golden set 的第一版，见 [[01-Golden set]]。

> [!tip] 一个常见的意外
> 跑完之后经常发现，便宜小模型在你的窄任务上和贵模型差不多。这不奇怪——榜单测的是通用能力，你的任务只用到其中很小一块。**能力用不完的部分，你也在为它付钱。**

### 几个反复出现的判断

**默认从便宜的开始试。** 先看小模型够不够，不够再往上换。反过来做的话，你永远不知道自己是不是在为用不上的能力付钱。

**别急着微调。** 提示词、few-shot 例子、工具、检索，这些的迭代成本比微调低一个量级。这四样都试过还不行，才轮到微调，见 [[01-四条路线选型：prompt、RAG、LoRA、蒸馏]]。

**分档路由。** 简单请求走小模型，复杂的走大模型，或者小模型先试、校验不过再升级。前提是**验证成本要低**——验证比重做还贵的话就别做，见 [[04-模型路由与级联]]。

**留好换模型的余地。** 模型会更新、会降价、会被更好的替代。把模型调用收在一层后面，别让 provider 特有的字段散落到各处。换 provider 时 prompt 和 schema 要重新验证，别假设兼容，见 [[05-故障降级与混沌测试]]。

### 一个例子

假设任务是「从上传的 PDF 发票里抽 8 个字段，输出 JSON」：

1. **硬约束**：财务数据不出内网 → 只能开源自建；发票 PDF 转文本后约 3k tokens → 上下文没压力；批处理场景 → 延迟不敏感
2. **收窄**：这是结构化抽取，看 IFEval 这类指令遵循基准比看 MMLU 有用；候选收到 7B / 14B / 32B 三档各一个
3. **定夺**：拿 50 张真实发票（含扫描歪的、有手写的、缺项的）跑三个模型，比字段级准确率、JSON 合规率、单张成本

大概率的结果是 7B 加上约束解码就够了，见 [[01-结构化输出三档]]。而如果一上来就按 MMLU 排名选了最贵的那个，你会多花十倍的钱，还不知道自己多花了。

## 动手做

- [ ] 给手头一个真实任务写下硬约束清单，看能砍掉多少候选
- [ ] 从线上流量抽 30 条真实样本并标注期望结果——不许编
- [ ] 同一套提示词跑三个不同档位的模型，记准确率、成本、P95 延迟、失败模式
- [ ] 找出「最小够用」的那一档，算清楚它和最贵那档的成本差
- [ ] 把这批样本存成版本化的文件，作为 golden set 第一版

## 算学会了

- [ ] 有一套固定流程：硬约束 → 榜单收窄 → 自己数据定夺，不会一上来就比分数
- [ ] 默认从便宜的开始试，能说出自己为哪些能力付了钱
- [ ] 选型报告里除了准确率，还有成本、延迟和失败模式
- [ ] 选型跑完，golden set 也就有了
- [ ] 知道换模型时哪些东西必须重新验证

## 坑

**从「哪个最强」开始想。** 这个问题没有答案，也不是你要回答的问题。你要回答的是「哪个刚好够用且最便宜」。

**用编的样本做评测。** 编的样本会系统性地避开真实数据里的脏活，评测结果虚高，上线就打脸。

**只比准确率。** 成本、延迟、失败模式任何一项都可能是决定性的。

**选完就不管了。** 模型在变、价格在降、你的流量分布也在变。选型结论有保质期，golden set 就是用来定期复检的。

**为用不上的能力付钱。** 最常见也最贵的浪费。判据：换成小一档的模型，你的 eval 掉了多少？没掉多少，那就是在白花钱。

下载下来的那 16GB 权重，是怎么从一堆网页文本变成一个会聊天的东西的。

## 一句话

能力在预训练里长出来，行为在后训练里定型——这两件事花的算力差三个数量级，也决定了后面所有「该微调还是该 RAG」的判断。

## 原理

### 四步走完，一个模型就有了

![[模型的一生.excalidraw.md|637]]

**第一步：预训练。** 拿几十 TB 的文本——网页、书、代码、论文——让模型做一件事：预测下一个 token。就这一个目标，没有别的。给个可核对的量级：Llama 3（Meta，2024 年 4 月）用了约 15T tokens，8B 那版烧掉约 130 万 H100·小时。

这一步的产出叫 **base model**（基座模型）。它见多识广，但只会「接着往下写」。你问它「北京在哪」，它可能回你「北京在哪？上海在哪？广州在哪？」——因为在它见过的文本里，这种句子后面经常跟着更多同类问句。它不是不知道答案，是没人教过它「被问到就该回答」。

**第二步：中期训练。** 这个阶段近两年才被单独拎出来说。做的事包括把上下文窗口成数量级地拉长（2026 年前沿模型多数标称 100 万 token 以上，个别标到 1000 万）、调高代码和数学数据的比例、补特定语言的语料。它仍然是预训练那套目标，只是换了数据配方。产出还是 base model。

**第三步：SFT（监督微调）。** 拿几万到几十万条「指令 → 期望回答」的样本，继续训。样本长这样：

```
指令：用一句话解释什么是 KV cache
回答：把已经算过的 key 和 value 存下来，避免每生成一个 token 就重算整段历史。
```

训完之后模型学会的不是新知识，是**新的行为模式**：被问就答，答完就停。这一步通常只要几百到几千 GPU·小时。

**第四步：偏好对齐。** 给模型看成对的答案——「这个比那个好」——让它往人类偏好的方向靠。经典做法是 RLHF（先训一个奖励模型，再用 PPO 优化），现在更常见的是 DPO 这类直接优化偏好的方法，省掉了单独的奖励模型。产出是**更合人意、更不容易闯祸**的模型，也就是你在 API 后面用到的那个。

然后打包发布：权重、分词器、许可证、model card。

### 那个必须记住的分工

**能力主要在第一步长出来，行为主要在第三、四步定型。**

这句话不是文绉绉的总结，它每天都在替人省钱。两个最常见的误判都是它的直接推论：

> [!warning] 用微调去灌事实
> 「我们的产品文档模型不知道，微调一下吧」——大概率白花钱。事实性知识是在 15T tokens 里长出来的，你那几千条样本改不动它，而且很容易把原有能力搞坏。这种情况该上 RAG，见 [[01-Chunking 四种策略]]。

> [!warning] 用 RAG 去教行为
> 「模型输出格式老是不对，多塞几个例子进上下文吧」——例子塞多了会占掉预算，而且不稳定。**格式、语气、工作流程这类行为**恰恰是 SFT 擅长的。这个取舍展开见 [[01-四条路线选型：prompt、RAG、LoRA、蒸馏]]。

一个记忆锚点：预训练是**百万** GPU·小时，微调是**几百**。差三个数量级的两件事，指望后者干前者的活，不太现实。

### Base 和 Instruct 的区别

HuggingFace 上同一个模型常有两个版本：

- `Meta-Llama-3-8B` —— base，只做完第一、二步
- `Meta-Llama-3-8B-Instruct` —— 做完全部四步

日常用一定挑 Instruct。base 版只在你要自己做 SFT 时才用——因为你想在干净的地基上盖自己的房子，而不是在别人已经装修过的房子里重新砸墙。

> [!info] 为什么 base 模型「不会说话」却仍然很值钱
> 你付钱买的是那 130 万卡时。SFT 那一步在整个成本里几乎不占位置，任何人拿几张卡就能做。所以开源社区的玩法是：等大厂放出 base 模型，然后各自做后训练。真正的护城河在第一步，而那一步几乎没有小团队能重来一遍。

### 那些没写在流程图里的事

**数据配比比模型结构重要得多。** 各家的架构差别小到认不出来（见 [[00-一个模型到底是什么]] 里那份 config），拉开差距的是喂了什么、按什么比例喂、怎么去重和过滤。这部分恰恰是各家最不愿意公开的，model card 里通常只有一句「高质量混合语料」。

**「开源模型」多数只开源权重。** 拿得到权重，拿不到训练数据、数据配方和训练代码。所以严格说是 open-weight 而不是 open-source，遇到许可证问题会有实际影响，见 [[04-模型权重来源]]。

**后训练是持续的。** 同一个模型名字下会不断出小版本，改的基本都是第三、四步。所以「我们用的是 GPT-4」这句话在两个月后可能指的已经是另一个东西了，业务上要有 eval 兜底，见 [[02-回归测试与 CI 门禁]]。

## 动手做

- [ ] 同一个 prompt 分别问 `Llama-3-8B` 和 `Llama-3-8B-Instruct`，把两边的输出贴在一起——直观感受「会续写」和「会回答」的差别
- [ ] 找三个模型的 model card，把训练数据那一段抄下来对比，看各家愿意说到什么程度
- [ ] 拿 20 条自己业务里的问题，测模型知不知道你们的产品事实。答不上来的记下来，这批就是该走 RAG 而不是微调的证据
- [ ] 找一个模型的 base 版和 instruct 版，比较两者 `tokenizer_config.json` 里的 `chat_template`——base 版通常压根没有

## 算学会了

- [ ] 有人说「模型不知道我们的产品，微调一下」，你能当场说清这该走 RAG 还是该走微调，并给出理由
- [ ] 知道 base 和 instruct 分别在什么时候用
- [ ] 能说出预训练和微调的算力差了几个数量级
- [ ] 明白「开源模型」通常只开权重，以及这在合规上意味着什么

## 坑

**以为微调能灌知识。** 这是最贵的那个误判——花几周做数据、跑训练，最后发现事实还是记不住，原有能力反而退了。判据很简单：你想让模型**知道**新东西就用 RAG，想让它**改变做事方式**才用微调。

**拿 base 模型直接上线。** 它不会遵守指令，也没有 chat_template，输出会很奇怪。看到模型「答非所问、自问自答」，先确认拿的是不是 instruct 版。

**以为模型名字不变就是同一个东西。** 闭源 API 背后的模型在持续做后训练。没有回归 eval 的话，某天开始变差你根本不知道是什么时候开始的。

**把 model card 上的分数当承诺。** 那是厂商自己跑的，设置、shot 数、有没有开思维链都可能和你的用法不同。怎么读这些数字见 [[03-评测基准都在测什么]]。

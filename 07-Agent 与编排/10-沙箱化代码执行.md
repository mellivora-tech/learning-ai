给 agent 一个「执行代码」的工具，它的能力上限一下子打开了——同时它的破坏力上限也打开了。

## 一句话

代码执行是最强的通用工具，也是**唯一一个必须假设「它一定会被用来做坏事」**的工具；所以沙箱不是可选项。

## 原理

### 为什么值得给

一个代码执行工具能顶掉几十个专用工具：算数、转格式、查数据、画图、处理文件。而且它天然可组合——模型可以把几步串起来，不用你预先设计好每种组合。

对数据分析、报表、文件处理这类任务，它的效果远超一堆窄工具。

### 威胁模型

假设**模型一定会被注入**，见 [[01-间接提示注入与 20 条攻击载荷]]。那么代码执行意味着攻击者可以：

| 想干什么 | 沙箱要挡住 |
| --- | --- |
| 读本机敏感文件 | 文件系统隔离 |
| 访问内网服务 | 网络隔离 |
| 把数据发出去 | 出网限制 |
| 挖矿、跑死循环 | CPU / 内存 / 时间限制 |
| 逃逸到宿主机 | 内核级隔离 |
| 攻击别的租户 | 每次执行独立环境 |

**注意最后一行**：沙箱不能跨请求复用，否则前一个租户留下的东西下一个能看到，见 [[06-多租户隔离]]。

### 隔离强度分档

| 方案 | 强度 | 开销 |
| --- | --- | --- |
| 进程级（限权限、chroot） | **弱**——不该用于不可信代码 | 最低 |
| 容器 | 中——共享内核，有逃逸历史 | 低 |
| **gVisor 这类用户态内核** | 较强 | 中 |
| **microVM（Firecracker 这类）** | **强**——独立内核 | 中 |
| 独立虚拟机 | 最强 | 高 |

**处理不可信代码的底线是容器加额外加固，推荐 microVM 或用户态内核。** 纯进程级隔离不够——语言层面的沙箱（比如「受限的 Python 解释器」）历史上被绕过太多次了。

### 几条必须配的限制

**网络默认全禁。** 需要访问外部的话走白名单，且**禁止访问内网网段**——SSRF 是这里最现实的风险。

**文件系统只读 + 一个可写的临时目录**，执行完销毁。

**资源上限**：CPU 时间、内存、磁盘、进程数都要限，防 fork 炸弹和无限循环。

**执行超时**，且超时后强制销毁整个环境。

**输出限长**——代码可以打印几百 MB 把上下文撑爆，见 [[02-Context engineering：上下文即预算]]。

### 数据怎么进出

沙箱里的代码通常要处理数据。两个方向都要管：

**进去**：只挂载这次任务需要的数据，按当前用户的权限过滤，见 [[04-权限过滤时机]]。**别把整个数据目录挂进去。**

**出来**：结果要有大小上限和格式校验。代码可以返回一个巨大的字符串，或者返回一段试图注入的文本——**沙箱的输出也是不可信内容**。

### 冷启动是主要工程成本

每次执行开一个新环境，冷启动就是延迟的主要来源。常见做法：

- **预热池**——提前起一批空闲环境，用完销毁再补
- **快照恢复**——从预装好依赖的快照启动
- **按语言分池**——Python 和 Node 各一个池

代价是空闲成本。要在延迟和成本之间取点，见 [[03-冷启动]]。

### 别忘了它仍然要受预算约束

代码执行工具很容易被反复调用——模型写错了就改改再跑一次。所以：

- 单工具调用次数上限，见 [[01-五类硬预算]]
- 每次执行的资源上限
- 累计执行时间上限

**没有这些的话，一个陷入循环的 agent 能把执行集群跑满。**

### 审计要跟上

代码执行的每一次都要留痕：执行了什么代码、访问了什么、产出了什么、谁触发的。这既是排查需要，也是合规需要，见 [[02-审计日志]]。

**代码本身要存下来**——出问题时你需要知道当时到底跑了什么。

## 动手做

- [ ] 选一个隔离方案，明确它防不防得住内核级逃逸
- [ ] 默认禁网，验证代码访问不了内网服务
- [ ] 设资源上限，用 fork 炸弹和无限循环各测一次
- [ ] 验证每次执行是独立环境，前一次的残留下一次看不到
- [ ] 测输出限长：让代码打印 100MB，确认不会撑爆上下文
- [ ] 把一条注入载荷放进代码的输出里，看会不会被当指令执行
- [ ] 测冷启动延迟，评估要不要上预热池

## 算学会了

- [ ] 把代码执行当成「一定会被用来做坏事」的工具来设计
- [ ] 知道进程级隔离不够，用容器加固或 microVM
- [ ] 网络默认全禁，尤其禁内网
- [ ] 每次执行独立环境，不跨请求复用
- [ ] 沙箱的输出也当不可信内容处理

## 坑

**用语言层面的「受限解释器」。** 历史上被绕过太多次，不能用于不可信代码。

**允许访问内网。** SSRF 是最现实的风险，能打到你所有内部服务。

**沙箱跨请求复用。** 前一个租户的残留下一个能看到。

**不限输出长度。** 代码打印几百 MB 直接把上下文撑爆。

**忘了沙箱输出也是不可信的。** 它可以返回注入载荷。
